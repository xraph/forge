Forge deployment automation
Run forge deploy start for the authenticated local workbench. It embeds its UI and shares Engine behavior with the CLI. Files are the default; --store sqlite --store-ref .forge/deploy.db or --store postgres --store-ref env:FORGE_DEPLOY_STATE_DSN selects SQL authority. A database outage fails without file fallback.
Use forge deploy schema for the typed deploy v2 schema and forge deploy inspect --output json for source-qualified discovery.
  forge deploy doctor --env dev --output json
  forge deploy plan --env dev --services api,worker --output json
The plan response contains data.hash, data.selector and data.store. data.file is empty for SQL authority unless --out writes a review copy. Apply the exact saved hash from either authority.
  forge deploy apply --plan <data.hash> --approve-plan <data.hash> --non-interactive --output json
  forge deploy status --env dev --output json
  forge deploy logs api --env dev --tail 200
  forge deploy destroy --env dev --yes
Destroy retains persistent data unless --delete-data is explicit. Service selection never schedules deletion. Invalid or stale plans fail before mutation. Unsupported provider operations exit 4. Readiness-disabled or unprobed resources are accepted, not healthy. Compose and Kubernetes have implemented lifecycle adapters. Kubernetes uses an explicit context/namespace, server-side dry-run, immutable images, migration Jobs and observed rollouts. Local image loading requires a named kind cluster; other clusters require registry delivery. Private registries need separate push and cluster pull access. Destroy retains PVCs and shared namespaces. Managed adapters must report their actual qualification level. The static documentation mock performs rehearsals only.

For registry delivery, approve publication separately before handing images to a managed platform:
  forge deploy publish --plan <data.hash> --approve-plan <data.hash> --non-interactive --output json
The publication response gives data.images keyed by service, with repository and immutable digest. It does not create a release or change workloads. Save these refs in build.images with source: existing and delivery: registry, then create and approve a new plan.

Render and DigitalOcean are schema-validated export adapters, not live apply adapters. Use forge deploy export --plan <hash> --output-dir <directory> and read HANDOFF.md. Provider Git builds track a branch; use immutable registry images for fixed revisions. DigitalOcean managed_databases maps resource names to existing production database clusters.
Kubernetes release.mode: gitops exports Kustomize plus gitops-handoff.json and GITOPS.md. Use existing immutable images, external resources and existing Secrets. Direct apply exits 4, controller sync/prune is not managed by Forge, and migrations/one-off jobs require direct deployment.

Runtime inspection is explicit: forge deploy inspect --exec --app api --timeout 2m --output json. It executes trusted app initialization and extension registration with FORGE_INTROSPECT=1, before framework Start. The response's data.runtime uses forge.infra/v1; reports are limited to 1 MiB and 4096 requirements. Runtime requirements never become automatic resource edits. The browser, plan and apply never execute runtime discovery. Custom entry points must honor the reporting mode.
Project deploy/descriptors/*.yaml overrides module-root forge-deploy.yaml, which overrides the embedded catalog. A descriptor requires schema: 1, one YAML document and known resource kinds.
A kind: gateway app must implement FARP and expose exactly one HTTP port. Discovery-enabled callers receive an enabled FARP overlay and FARP_GATEWAY_URL. target.gateway selects among several gateways; excluded gateways need external_services URLs. Logical FORGE_SERVICE_ID differs from per-replica identity. Kubernetes uses pod UID for FORGE_INSTANCE_ID; Compose retains distinct container hostnames.
VM, Fly and Railway export portable Compose graphs requiring immutable existing/CI registry images. Read HANDOFF.md. VM export does not create a machine or execute SSH. Fly/Railway export is not a native platform app spec and needs manual translation.
Hosted export maps one main service per workload, ctrlplane-compatible ServiceSpec/ConfigFile and separate SecretBinding. target.secret_keys maps external resource secret names to existing vault keys. No laptop credential values or account IDs are exported. The hosted authority authorizes keys, sets tenant/instance identity and materializes each binding at EnvKey. Only explicit external connection URLs are accepted. Private pulls, arbitrary mounts, migrations, discovery and native routing remain unqualified. All portable/hosted lifecycle commands exit 4.
