# Forge Framework - Core Package

## Purpose

Forge is an enterprise-grade web framework for Go that provides a complete foundation for building scalable, maintainable, and observable backend applications. It combines clean architecture principles, dependency injection, powerful routing, and a rich extension ecosystem into a unified framework designed for production environments.

## Key Components

- **App**: Central application instance with lifecycle management and graceful shutdown
- **Dependency Injection**: Type-safe container with service resolution and lifecycle management
- **Router**: High-performance HTTP router with OpenAPI/AsyncAPI generation
- **Configuration**: Multi-format config management with auto-discovery and environment overrides
- **Observability**: Built-in metrics, structured logging, and distributed tracing
- **Health Checks**: Automatic health monitoring and status aggregation
- **Extensions**: Modular extension system for adding capabilities (Database, Cache, Events, etc.)
- **Middleware**: Comprehensive middleware stack (CORS, logging, rate limiting, recovery)

## Architecture

Forge follows a layered architecture:
```
Application Layer (App)
├── HTTP Server & Router
├── Middleware Chain
├── Controllers & Handlers
└── Business Logic

Infrastructure Layer
├── Dependency Injection Container
├── Configuration Manager
├── Logger, Metrics, Tracing
├── Health Check Manager
└── Lifecycle Manager

Extension Layer
└── Pluggable extensions (DB, Cache, Events, Storage, etc.)
```

## Usage Examples

### Basic Usage

```go
package main

import "github.com/xraph/forge"

func main() {
    // Create app with default configuration
    app := forge.NewApp(forge.AppConfig{
        Name:        "my-service",
        Version:     "1.0.0",
        Environment: "production",
        HTTPAddress: ":8080",
    })

    // Register routes
    router := app.Router()
    router.GET("/", func(ctx forge.Context) error {
        return ctx.JSON(200, forge.Map{
            "message": "Hello from Forge!",
        })
    })

    // Run the application (blocks until SIGINT/SIGTERM)
    app.Run()
}
```

### Advanced Usage with Extensions

```go
package main

import (
    "github.com/xraph/forge"
    "github.com/xraph/forge/extensions/database"
    "github.com/xraph/forge/extensions/cache"
)

func main() {
    app := forge.NewApp(forge.AppConfig{
        Name:    "advanced-service",
        Version: "2.0.0",
        Extensions: []forge.Extension{
            database.NewExtension(database.Config{
                Databases: []database.DatabaseConfig{
                    {
                        Name: "primary",
                        Type: database.TypePostgres,
                        DSN:  "postgres://localhost/mydb",
                    },
                },
            }),
            cache.NewExtension(cache.Config{
                Driver: "redis",
                URL:    "redis://localhost:6379",
            }),
        },
    })

    // Register services with DI
    forge.RegisterSingleton(app.Container(), "userService", func(c forge.Container) (*UserService, error) {
        db, err := database.GetSQL(c)
        if err != nil {
            return nil, err
        }
        cache := forge.Must[cache.Cache](c, "cache")
        return NewUserService(db, cache), nil
    })

    // Register routes
    router := app.Router()
    router.GET("/users/:id", getUserHandler)
    router.POST("/users", createUserHandler)

    app.Run()
}
```

### Integration with Dependency Injection

```go
// Define a service
type UserService struct {
    db     *sql.DB
    logger forge.Logger
}

// Register in container
forge.RegisterSingleton(app.Container(), "userService", func(c forge.Container) (*UserService, error) {
    db := forge.Must[*sql.DB](c, "database")
    logger := forge.Must[forge.Logger](c, "logger")
    return &UserService{db: db, logger: logger}, nil
})

// Use in handlers
func getUserHandler(ctx forge.Context) error {
    svc := forge.Must[*UserService](ctx.Container(), "userService")
    user, err := svc.GetUser(ctx.Param("id"))
    if err != nil {
        return err
    }
    return ctx.JSON(200, user)
}
```

### Profiling

Push to Pyroscope is on when a server address is set, and off otherwise.
Precedence is `WithAppProfilingConfig`, then the `profiling:` block of the
config file, then `PYROSCOPE_SERVER_ADDRESS`, `PYROSCOPE_APPLICATION_NAME`,
`PYROSCOPE_BASIC_AUTH_USER`, `PYROSCOPE_BASIC_AUTH_PASSWORD` and
`PYROSCOPE_TENANT_ID`. `tags` and `profile_types` have no env var and take
the first non-empty source whole: set in code, they replace the file's.
`application_name` defaults to the app name, so Pyroscope's `service_name`
matches the traces' `service.name`. `,`, `{`, `}` and `=` in a tag value
(forge's `service_version` and `environment` included) become `_` with a
warning, because they break the upload's `name=app{k=v,...}` query.
`PYROSCOPE_SERVER_ADDRESS` alone turns push on, so an app that calls
`pyroscope.Start` itself should drop that call, or two sessions fight over the
CPU profiler. Pull (Alloy scraping pprof) only reads `span_labels`; set
`runtime.SetMutexProfileFraction` and `runtime.SetBlockProfileRate` yourself
for mutex and block profiles.

```yaml
profiling:
  server_address: http://pyroscope:4040
  tags: { region: eu-west-1 }
  profile_types: [cpu, inuse_space, mutex_duration]  # five defaults when empty
  span_labels: true   # defaults to push; needs tracing on
```

`app.Start` starts the profiler before the before-start hooks, and a failed
Start stops it again. `app.Stop` stops it last, after the tracing flush. The
final upload is capped at 5 seconds both times, and a failed Start's attempt
ignores a cancelled context. An unreachable Pyroscope never fails Start; SDK
errors log "profiling: pyroscope client error" at warn, at most once a minute. With push holding
the CPU profiler, `/_/debug/pprof/profile` answers "cpu profiling already in
use", and Start logs a warning when pprof is on. Span labels (`span_id`,
`span_name`, `pyroscope.profile.id`) are in `internal/telemetry/llm.txt`; the
resolver and profiler are in `internal/profiling/llm.txt`.

### Tracing

`forge.New` builds an OpenTelemetry tracer provider and installs a server
span middleware as the outermost global middleware. Every request gets a span
named `METHOD /route/pattern`, an incoming `traceparent` is honoured, and the
response carries a `traceparent` header. Spans are exported over OTLP/HTTP
only when an endpoint is set. Precedence is `WithAppTracingConfig`, then the
`tracing:` block of the config file, then `OTEL_*` env
(`OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_SDK_DISABLED`, ...). `Stop` flushes
queued spans last, after the container stops.

```yaml
tracing:
  enabled: true            # false turns tracing off entirely
  endpoint: http://collector:4318/v1/traces
  sample_ratio: 0.1
  exclude_paths: ["/_/"]
  response_header: traceparent   # "" sends no header
```

### Metrics push

Set an OTLP endpoint and your app also pushes its metrics over OTLP/HTTP
to `<endpoint>/v1/metrics`, every 60 seconds by default, from `Start` until
`Stop`. The same `OTEL_EXPORTER_OTLP_ENDPOINT` you set for traces turns it on, so no new
setting is needed. Precedence is `WithAppMetricsExportConfig(MetricsExportConfig{...})`,
then the `metrics_export:` key of the config file, then `OTEL_*` env
(`OTEL_EXPORTER_OTLP_METRICS_ENDPOINT`, `OTEL_METRIC_EXPORT_INTERVAL`, ...).
`OTEL_METRICS_EXPORTER=none` (any list without `otlp`) or `metrics_export.enabled: false`
turns it off.
If your backend also scrapes `/_/metrics`, it counts everything twice.

```yaml
metrics_export:
  enabled: true
  endpoint: http://collector:4318/v1/metrics
  interval: 30s
  temporality: delta       # cumulative (default) or delta
  headers: { X-Api-Key: k }
```

`forge.New` resolves the settings, logs any warnings and checks the endpoint,
but sends nothing. `Start` begins pushing once the metrics collector runs and
logs `telemetry: pushing metrics over OTLP` with the endpoint, interval and
temporality (never the headers). `Stop` pushes once more after the extensions
stop and before the container and the collector stop, then flushes spans. An
app you build and never start never pushes, and if `Start` returns an error
the push is stopped again before it returns. A bad endpoint is logged once at
`New` and the app boots without pushing. The pusher can start again after a
`Stop`, but the app itself can't be started twice yet: a second `Start`
returns "app already started".

## Common Patterns

### Service Registration
```go
// Singleton - created once, shared across requests
forge.RegisterSingleton(container, "db", dbFactory)

// Transient - new instance per request
forge.RegisterTransient(container, "request", requestFactory)
```

### Error Handling
```go
// Return structured errors
return forge.NewHTTPError(404, "user not found")

// Use error helpers
if forge.IsServiceNotFound(err) {
    return ctx.JSON(503, forge.Map{"error": "service unavailable"})
}
```

### Graceful Shutdown
```go
// Automatically handled by app.Run()
// Manual control:
ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
defer cancel()

if err := app.Stop(ctx); err != nil {
    log.Fatal(err)
}
```

### Middleware Usage
```go
router := app.Router()
router.Use(forge.CORS())
router.Use(forge.Logger())
router.Use(forge.Recovery())
router.Use(forge.RequestID())
```
