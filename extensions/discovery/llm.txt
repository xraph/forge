# Forge Discovery Extension

## Purpose

Service registration and discovery for Forge apps. On start the app registers itself in a
registry (memory, Consul, etcd, mDNS/DNS-SD, or an HTTP seed list), a loop keeps its health
status current, and it deregisters on shutdown. A `*discovery.Service` in the container finds
other services by name or tag with round-robin or random picks. Optional FARP endpoints tell an
API gateway about your routes and OpenAPI or AsyncAPI schemas (github.com/xraph/farp).

Module: github.com/xraph/forge/extensions/discovery (package `discovery`). Backends live in
`discovery/backends` (NewMemoryBackend, NewConsulBackend, NewEtcdBackend, NewKubernetesBackend,
NewMDNSBackend, NewHTTPBackend).

## What the container holds

`*discovery.Service`, also under the names `discovery` (ServiceKey) and `discovery.Service`
(ServiceKeyLegacy).

```go
svc, err := forge.Inject[*discovery.Service](app.Container())
all, err := svc.Discover(ctx, "payments")
v2, err := svc.DiscoverWithTags(ctx, "payments", []string{"v2"})
healthy, err := svc.DiscoverHealthy(ctx, "payments")
inst, err := svc.SelectInstance(ctx, "payments", discovery.LoadBalanceRandom)
url, err := svc.GetServiceURL(ctx, "payments", "http", discovery.LoadBalanceRoundRobin)
err = svc.Watch(ctx, "payments", func(instances []*discovery.ServiceInstance) {})
names, err := svc.ListServices(ctx)
```

Also Register, Deregister, Backend(), Health.

## Key types

- `Backend` (= backends.Backend): Name, Initialize, Register, Deregister, Discover,
  DiscoverWithTags, Watch, ListServices, Health, Close.
- `ServiceInstance` (= backends.ServiceInstance): ID, Name, Version, Address, Port, Tags,
  Metadata, Status, LastHeartbeat; helpers URL(scheme), HasTag, HasAllTags, IsHealthy,
  GetMetadata(key) (string, bool).
- `LoadBalanceStrategy`: LoadBalanceRoundRobin, LoadBalanceRandom work.
  LoadBalanceLeastConnections and LoadBalanceWeightedRoundRobin fall back to round-robin.
- Config structs: Config, ServiceConfig, HealthCheckConfig, WatchConfig, FARPConfig,
  FARPSchemaConfig, FARPLocationConfig, FARPEndpointsConfig, plus aliases ConsulConfig,
  EtcdConfig, KubernetesConfig, EurekaConfig, MDNSConfig, HTTPConfig.
- `NewSchemaPublisher(config FARPConfig, app forge.App) *SchemaPublisher`.

## Backends

| backend | registers this app | notes |
| --- | --- | --- |
| memory (default) | yes, in process | one process only |
| consul | yes | 30s TTL check kept passing by the health loop; deregistered after 1m critical |
| etcd | yes | keys under etcd.key_prefix (/services) |
| kubernetes | no | Discover returns one instance per matching Kubernetes Service |
| mdns | yes | service type defaults to `_<name>._tcp` |
| http | no | polls each seed's `/_farp/discovery` |
| eureka | n/a | startup fails: "eureka backend not yet implemented" |

## Identity and address

- Name: FORGE_SERVICE_ID, service.name, app name. Version: service.version, app version.
- Port: service.port, then the port in the app's HTTPAddress.
- Address: service.address, FORGE_ADVERTISE_ADDR, POD_IP, host in HTTPAddress, hostname,
  localhost. A wildcard (0.0.0.0, ::) is never advertised.
- Instance ID: FORGE_INSTANCE_ID, `<name>-<hostname>` when FORGE_SERVICE_ID is set, service.id,
  else generated as `<name>-<unix nanoseconds>`.

## FARP

With farp.enabled the extension adds GET /_farp/manifest, /_farp/health, /_farp/schemas/:type
and /_farp/discovery. The manifest is built in a PhaseAfterStart hook so it sees every route;
until then the first three answer 503. With gateway_url set, it posts to
`<gateway_url>/_farp/v1/register` once the server is listening (retrying with backoff) and calls
`/_farp/v1/deregister/<name>` on shutdown. Internal paths (/_/*, /_farp/*) are excluded from
schemas unless WithFARPExcludeInternalPaths(false). Path rules: first match wins. With no
farp.schemas and auto_register on, it publishes whichever of OpenAPI and AsyncAPI the app has.

## Config

Key `extensions.discovery`, falling back to `discovery`. Options apply on top of the file.

| yaml key | default |
| --- | --- |
| enabled | true (must be a boolean) |
| backend | "memory" |
| service.name, id, version, address, port, tags, metadata | empty |
| service.enable_auto_deregister | true (when FARP is off) |
| health_check.enabled, interval, timeout | true, 10s, 5s |
| watch.enabled, watch.services | false, [] |
| consul.address, token, datacenter, namespace, tls_enabled, tls_ca_file, tls_cert, tls_key | 127.0.0.1:8500 |
| etcd.endpoints, username, password, dial_timeout, key_prefix | 127.0.0.1:2379, 5s, /services |
| kubernetes.namespace, in_cluster, kubeconfig_path, service_type, label_selector | default, true, ClusterIP |
| mdns.domain, service_type, service_types, watch_interval, interface, ipv6, browse_timeout, ttl | local., 3s, 120 |
| http.seeds, poll_interval, timeout | [], 10s, 5s |
| farp.enabled, auto_register, gateway_url | false, true, "" |
| farp.schemas, endpoints, capabilities, path_rules | |
| farp.exclude_internal_paths, collapse_service_tags | true, false |

## Gotchas

- Always set a stable instance ID (WithServiceID, service.id or FORGE_INSTANCE_ID). Without one,
  the health loop re-registers a freshly generated ID every interval, so the registry fills with
  duplicates and shutdown deregisters an ID that was never registered.

## Not implemented yet

- eureka backend.
- etcd `tls_*` keys aren't applied.
- Read but ignored: health_check.http, health_check.tcp, health_check.grpc,
  health_check.deregister_critical_service_after (the loop always uses the app's health checks;
  Consul's deregistration delay is fixed at 1m), watch.tags, farp.strategy.
