# Forge WebRTC Extension

## Purpose

WebRTC call rooms and server-side peer connections for Forge apps, built on Pion WebRTC v4
(github.com/pion/webrtc/v4) and the Forge streaming extension. You get call rooms with mesh and
SFU topologies, SDP offer and answer handling, ICE candidates, data channels and STUN/TURN
configuration.

Early software: the built-in signaling endpoint, SFU media forwarding, recording, screen share
and quality monitoring are unfinished. See "Not implemented yet".

Module: github.com/xraph/forge/extensions/webrtc (package `webrtc`). Its go.mod replaces the
root, streaming and auth modules with local paths.

## Constructor and options

```go
func New(streamingExt *streaming.Extension, config Config, opts ...ConfigOption) (*Extension, error)
func DefaultConfig() Config

type ConfigOption func(*Config)
WithTopology(topology Topology)          // TopologyMesh (default), TopologySFU; TopologyMCU is rejected
WithSFU(config SFUConfig)                // sets SFU topology and its settings
WithSTUNServers(servers ...string)       // replaces the list
WithTURNServer(turn TURNConfig)          // appends; TURNConfig{URLs []string; Username, Credential string; TLS fields}
WithAudioCodecs(codecs ...string)        // stored, not applied
WithVideoCodecs(codecs ...string)        // stored, not applied
WithRecording(path string)               // stored, not applied
WithQualityMonitoring(config QualityConfig) // stored, not applied
```

`New` validates: at least one STUN or TURN server (ErrNoICEServers), SFU topology needs an
SFUConfig, MaxVideoBitrate >= MinVideoBitrate. DefaultConfig has two Google STUN servers
(stun.l.google.com:19302, stun1.l.google.com:19302), mesh topology.

Config is code only: the extension doesn't read `extensions.webrtc`. It declares a dependency on
`streaming`, so register both extensions in the same app. Nothing is put in the DI container;
keep the `*Extension` you got from New.

## Usage

```go
stream := streaming.NewExtension(streaming.WithLocalBackend())
rtc, err := webrtc.New(stream, webrtc.DefaultConfig())
app := forge.NewApp(forge.AppConfig{Name: "calls", Extensions: []forge.Extension{stream, rtc}})

_ = forge.OnStarted(app, "create-call", func(ctx context.Context, _ forge.App) error {
    _, err := rtc.CreateCallRoom(ctx, "standup", streaming.RoomOptions{ID: "standup", Name: "Standup"})
    return err
})

// in an HTTP handler: answer a browser offer
peer, err := rtc.JoinCall(ctx, roomID, userID, &webrtc.JoinOptions{})
err = peer.SetRemoteDescription(ctx, &offer)
answer, err := peer.CreateAnswer(ctx)   // waits up to 5s for ICE gathering, so candidates are inline
```

## Extension methods

CreateCallRoom(ctx, roomID string, opts streaming.RoomOptions) (CallRoom, error),
GetCallRoom(roomID) (CallRoom, error), GetCallRooms() []CallRoom, DeleteCallRoom(ctx, roomID)
(closes every peer), JoinCall(ctx, roomID, userID string, opts *JoinOptions) (PeerConnection, error),
LeaveCall(ctx, roomID, userID), GetConfig() Config, GetSignalingManager(), GetSFURouter(),
GetQualityMonitor(), GetRecorder(), RegisterRoutes(router forge.Router) error.
`(*Config).GetICEServers() []ICEServer` returns STUN and TURN servers for clients.

Each user can join a room once; a second JoinCall for the same user fails until LeaveCall.
JoinCall and LeaveCall on the extension update `webrtc.calls.*` and `webrtc.peers.active`.

## Key types (interfaces.go)

- PeerConnection: ID, UserID, State, CreateOffer, CreateAnswer, SetLocalDescription,
  SetRemoteDescription, AddICECandidate, AddTrack, RemoveTrack, GetTracks, GetStats, Close,
  OnICECandidate, OnTrack, OnConnectionStateChange, OnDataChannel.
- CallRoom: ID, Name, JoinCall, Leave, GetPeer, GetPeers, GetParticipants, MuteUser, UnmuteUser,
  EnableVideo, DisableVideo, StartScreenShare, StopScreenShare, GetQuality, Close.
- JoinOptions{AudioEnabled, VideoEnabled bool; DisplayName string; Metadata map[string]any}: audio/video add a local
  track to the server's peer.
- Also MediaTrack, DataChannel, SignalingManager, SFURouter, Recorder, QualityMonitor,
  SessionDescription{Type, SDP}, ICECandidate, ICEServer, ConnectionState, Participant, PeerStats.
- Constructors: NewPeerConnection, NewDataChannel, NewLocalTrack, NewSignalingManager,
  NewSFURouter, NewMeshCallRoom, NewMeshCallRoomFromOptions, NewSFUCallRoomFromOptions,
  NewRecorder (DefaultRecorderConfig), NewQualityMonitor (DefaultQualityConfig).
- Errors: ErrNoICEServers, ErrPeerNotFound, ErrPeerAlreadyExists, ErrRoomNotFound,
  ErrAlreadyInRoom, ErrSFUNotEnabled, ErrNotImplemented and more; error types SignalingError,
  ConnectionError, MediaError.

## Gotchas

- SessionDescription and ICECandidate have no JSON tags: they marshal as `Type`, `SDP`. Decoding
  is case-insensitive, so binding a browser's `{type, sdp}` works, but shape responses to the
  browser yourself with lowercase keys.
- No trickle ICE endpoint: have the browser finish gathering before sending its offer.

## Not implemented yet

- RegisterRoutes mounts a WebSocket at `/webrtc/signal/{roomID}` whose read loop drops every
  message. The handler also asserts `ctx.Get("user_id").(string)` without a check, so it panics
  unless global or group middleware has set `user_id`. Do your own signaling.
- SFU: rooms and the router exist but RTP isn't forwarded between participants.
- StartScreenShare, StopScreenShare and GetQuality return ErrNotImplemented. The extension never
  builds a recorder or quality monitor, so GetRecorder and GetQualityMonitor return nil.
- Stored but unread: MediaConfig (codecs, bitrates, resolution), SignalingEnabled,
  SignalingTimeout, RequireAuth, AllowGuests, RecordingEnabled, RecordingPath, MetricsEnabled.
  Pion negotiates codecs with its defaults.
- examples/basic relies on RegisterRoutes and recording.

## Testing

`-short` skips the integration tests; nothing in CI runs them.
