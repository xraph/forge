# Forge Streaming Extension

## Purpose

Real-time messaging for Forge apps: ready-made WebSocket and Server-Sent Events endpoints and a
`Manager` for rooms, pub/sub channels, presence, typing indicators, message history and replay
after a reconnect. Runs on one node with the local backend, or across nodes with Redis. Inbound
messages go through a size cap, per-user rate limiting and room authorization, and the server
stamps the sender's identity.

Module: github.com/xraph/forge/extensions/streaming (package `streaming`). Most types are aliases
over `streaming/internal` (exports.go).

Subpackages: `backends` (CreateStores factory; `backends/local`, `backends/redis`),
`coordinator` (cross-node relay: NewRedisCoordinator is wired; NewNATSCoordinator exists but the
extension never uses it), `lb` (load balancer strategies), `auth`, `filters`, `ratelimit`,
`trackers`, `validation`, `contract` (dashboard contract pages).

## Extension methods

```go
func (e *Extension) Manager() Manager
func (e *Extension) RegisterRoutes(router forge.Router, wsPath, ssePath string) error
func (e *Extension) RegisterHook(hook StreamingHook)
func (e *Extension) UnregisterHook(name string)
func (e *Extension) RegisterCodec(codec Codec)
func (e *Extension) Hooks() *HookRegistry
func (e *Extension) Codecs() *CodecRegistry
func (e *Extension) AsyncAPISpec() *forge.AsyncAPISpec
func (e *Extension) RegisterContractContributor(disp *dispatcher.Dispatcher, reg contract.Registry, wreg contract.WardenRegistry) error
// (dashboard contract; dispatcher and contract are packages under forge/extensions/dashboard/contract)
```

RegisterRoutes mounts GET wsPath (WebSocket), GET ssePath (SSE), and POST ssePath+"/subscribe"
and ssePath+"/unsubscribe". The logger, hook registry and manager are created in Register, so
call RegisterRoutes, RegisterHook and RegisterCodec from a start hook (`forge.OnStarted`),
otherwise you get a nil pointer panic.

## What the container holds

`Manager` under the alias `streaming` (ManagerKey). Helpers: `GetManager(c)`, `MustGetManager(c)`,
`GetManagerFromApp(app)`, `MustGetManagerFromApp(app)`.

## Usage

```go
stream := streaming.NewExtension(streaming.WithLocalBackend())
app := forge.NewApp(forge.AppConfig{Name: "live", Extensions: []forge.Extension{stream}})

_ = forge.OnStarted(app, "streaming-routes", func(_ context.Context, a forge.App) error {
    return stream.RegisterRoutes(a.Router(), "/ws", "/events")
})

// from a handler
_ = stream.Manager().Broadcast(ctx, streaming.NewEventMessage("announcement", "deploy finished"))

// rooms must exist before anyone joins
_ = stream.Manager().CreateRoom(ctx, streaming.NewLocalRoom(streaming.RoomOptions{ID: "lobby", Name: "Lobby", Owner: "system"}))
```

## Key types

- `Manager` (internal.Manager): Register/Unregister/GetConnection/GetUserConnections, rooms
  (CreateRoom, GetRoom, DeleteRoom, JoinRoom, LeaveRoom, ListRooms, SearchRooms, ArchiveRoom,
  ...), channels (CreateChannel, Subscribe, Unsubscribe, ...), `ProcessInbound(ctx, msg, sender)`,
  Broadcast, BroadcastToRoom, BroadcastToChannel, SendToUser, SendToConnection, presence
  (SetPresence, GetPresence, GetOnlineUsers), typing (StartTyping, StopTyping, GetTypingUsers),
  history (GetHistory(ctx, roomID, HistoryQuery), ...), moderation (MuteUser, BanUser, ...),
  GetStats, ResumeSession, Replay, Start, Drain, Stop, Health.
- `Connection` = internal.EnhancedConnection. Wrap a core connection with
  `NewConnection(conn forge.Connection, opts ...ConnOption) Connection`; options
  WithSendQueueCapacity, WithSendQueueTimeouts, WithConnectionMetrics, WithConnectionLogger.
- `Message`: JSON frame with type, event, room_id, channel_id, user_id, id, timestamp, data,
  sequence. `NewEventMessage(event string, data any) *Message`.
- `RoomOptions{ID, Name, Owner, Private, MaxMembers, Description, Metadata}`, `NewLocalRoom(opts)`.
- Hooks: a `StreamingHook` (Name) plus any of ConnectionHook (OnConnect, OnDisconnect),
  MessageHook (OnMessageReceived, OnMessageDelivered), RawMessageHook (OnRawMessage), RoomHook
  (OnRoomJoin, OnRoomLeave, OnRoomCreate, OnRoomDelete), PresenceHook (OnPresenceChange),
  ErrorHook (OnError).
- `Codec` interface: ContentType, Encode, Decode. JSON is the default; binary and text are built
  in. Clients pick one with `?content_type=` or an `X-Content-Type` header.
- Errors: many sentinels in exports.go (ErrRoomNotFound, ErrRoomAccessDenied, ErrSendDenied,
  ErrUserMuted, ErrUserBanned, ErrRateLimitExceeded, ErrMessageTooLarge, ...).

## Wire protocol

Client frames: `{"type":"join","room_id":"lobby"}`, `{"type":"message","room_id":"lobby","data":...}`,
`{"type":"typing","room_id":"lobby","data":true}`, `{"type":"presence","data":"away"}`,
`{"type":"leave","room_id":"lobby"}`. Server-set fields (user_id, id, timestamp) overwrite what
the client sends. Rejections come back as `type: "error"` with a stable `code` (rate_limited,
message_too_large, send_denied, room_access_denied, muted, banned, feature_disabled, ...).

SSE query params: `rooms`, `channels`, `session_id`, `last_event_id` (or the Last-Event-ID
header). The stream starts with a `connected` event; it sends `resync_required` when it can't
replay from the cursor. EventSource clients change subscriptions with POST .../subscribe and
.../unsubscribe and `{"conn_id": "...", "rooms": [...], "channels": [...]}`.

## Config

Key `extensions.streaming`, falling back to `streaming`. File overrides defaults, options override
the file. YAML keys: backend, backend_urls, backend_username, backend_password, enable_rooms,
enable_channels, enable_presence, enable_typing_indicators, enable_message_history,
enable_distributed, max_connections_per_user (5), max_rooms_per_user (50),
max_channels_per_user (100), max_message_size (65536), max_messages_per_second (100),
max_anonymous_connections (1000), max_total_connections (0 = unbounded), ping_interval (30s),
pong_timeout (10s), write_timeout (10s), read_buffer_size, write_buffer_size (4096),
message_retention (720h), message_cleanup, max_messages_per_room (100000), presence_timeout (5m),
presence_cleanup, typing_timeout (3s), typing_cleanup, max_typing_users_per_room, node_id,
heartbeat_interval, node_timeout, enable_load_balancer, load_balancer_strategy,
health_check_interval, health_check_timeout, sticky_session_ttl, consistent_hash_replicas,
enable_session_resumption, session_resumption_ttl, drain_timeout (15s), tls_enabled,
tls_cert_file, tls_key_file, tls_ca_file.

Validation: backend must be local, redis, nats or empty; distributed needs redis or nats; redis
and nats need backend_urls; ping_interval and pong_timeout at least 1s; TLS needs cert and key.

Load balancer strategies: consistent_hash, sticky, least_connections. The default,
round_robin, currently behaves as least connections. Session resumption state is kept in memory on the node.

## Gotchas

- Identity: the built-in handlers read `user_id` from the Forge context. Set it with middleware
  (`ctx.Set("user_id", id)`) on a group you pass to RegisterRoutes, or globally. Since
  forge commit bce0387d the router hands values that middleware stores with ctx.Set to
  WebSocket and SSE handlers. Without it, connections are anonymous: they receive broadcasts,
  but JoinRoom refuses them and the SSE subscribe endpoints answer 404. Or register your own
  `router.WebSocket` handler: wrap with NewConnection, SetUserID, `Manager().Register`, and pass
  every inbound message through `Manager().ProcessInbound`.
- Redis backend: the first backend URL is handed to go-redis as `Addr`, so it must be `host:port`.
  `redis://host:port` fails every call with "too many colons in address". One Redis server only
  (no Cluster or Sentinel). With TLS on, cert and key are required and the CA file is ignored.
- With the Redis backend, rooms, history, presence and typing live in Redis and broadcasts are
  relayed over Redis Pub/Sub. Connections, rate limits, connection limits and resumable sessions
  stay per node. If the coordinator's Redis client can't be created the node logs "distributed
  messaging disabled" and runs without cross-node relay.
- WithLoadBalancer keeps a node registry and health checker but nothing uses it to route
  clients; put your own load balancer in front. DISTRIBUTED_DEPLOYMENT_GUIDE.md has the details.
- Metrics go to Forge metrics under `streaming.` (connections.active, messages.broadcast,
  messages.rate_limited, sendqueue.dropped, sessions.resumed, replay.messages, ...).

## Not implemented yet

- NATS backend: `backends.CreateStores` returns `backends.ErrBackendNotImplemented` for "nats"
  (it aliases the backend-not-connected error), so `WithNATSBackend` makes registration fail
  with "failed to create stores".
- examples/chat: its create-room endpoint doesn't create a room, and it installs no middleware
  that sets `user_id`, so its connections are anonymous.
