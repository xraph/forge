# Forge MQTT Extension

## Purpose

Connects a Forge app to an MQTT broker (Mosquitto, EMQX, HiveMQ, ...) when the app starts and
gives you one shared client for publish and subscribe: QoS 0/1/2, retained messages, `+` and `#`
wildcards, a last will, TLS, and username/password auth. Built on the Eclipse Paho Go client
(github.com/eclipse/paho.mqtt.golang), MQTT 3.1 and 3.1.1 only. The raw Paho client is reachable
with GetClient().

Module: github.com/xraph/forge/extensions/mqtt (package `mqtt`). Import Paho as `paho` (or any
name) to write handlers.

## What the container holds

`*mqtt.MQTTService` by type and under the alias `mqtt` (ServiceKey), and the `mqtt.MQTT`
interface backed by the same instance.

```go
m, err := forge.Inject[mqtt.MQTT](app.Container())
```

The extension's Start connects and waits up to connect_timeout; if the broker doesn't accept,
the app doesn't start. Stop disconnects with a 250ms quiesce.

## Key types

```go
type MQTT interface {
    Connect(ctx context.Context) error
    Disconnect(ctx context.Context) error
    IsConnected() bool
    Reconnect() error
    Publish(topic string, qos byte, retained bool, payload any) error       // waits for Paho
    PublishAsync(topic string, qos byte, retained bool, payload any) error  // failures only logged
    Subscribe(topic string, qos byte, handler MessageHandler) error
    SubscribeMultiple(filters map[string]byte, handler MessageHandler) error
    Unsubscribe(topics ...string) error
    AddRoute(topic string, handler MessageHandler)                          // no SUBSCRIBE packet
    SetDefaultHandler(handler MessageHandler)
    SetOnConnectHandler(handler ConnectHandler)
    SetConnectionLostHandler(handler ConnectionLostHandler)
    SetReconnectingHandler(handler ReconnectingHandler)
    GetClient() paho.Client
    GetStats() ClientStats
    GetSubscriptions() []SubscriptionInfo
    Ping(ctx context.Context) error
}

type MessageHandler = paho.MessageHandler            // func(paho.Client, paho.Message)
type ConnectHandler = paho.OnConnectHandler
type ConnectionLostHandler = paho.ConnectionLostHandler
type ReconnectingHandler = paho.ReconnectHandler
type SubscriptionInfo struct { Topic string; QoS byte; Handler string }
type ClientStats struct {
    Connected bool; ConnectTime, LastMessageTime time.Time
    MessagesReceived, MessagesSent int64; Subscriptions int; Reconnects int64
}
```

Payloads: `[]byte` and string go out as-is; anything else is JSON-encoded. Publish and
PublishAsync fail fast when not connected.

Sentinel errors: ErrNotConnected, ErrAlreadyConnected, ErrConnectionFailed, ErrPublishFailed,
ErrSubscribeFailed, ErrUnsubscribeFailed, ErrInvalidQoS, ErrInvalidTopic, ErrTimeout.

## Usage

```go
err := m.Subscribe("devices/+/state", 1, func(_ paho.Client, msg paho.Message) {
    log.Printf("%s: %s", msg.Topic(), msg.Payload())
})
err = m.Publish("devices/42/state", 1, true, map[string]any{"online": true})
```

Subscribe from an after-start hook, once the client is connected.

## Config

Key `extensions.mqtt`, falling back to `mqtt`. File overrides defaults, options override the file.

| yaml key | default |
| --- | --- |
| broker | tcp://localhost:1883 |
| client_id | forge-mqtt-client |
| username, password | "" |
| clean_session | true |
| connect_timeout | 30s |
| keep_alive, ping_timeout | 60s, 10s |
| auto_reconnect, max_reconnect_delay | true, 10m |
| resume_subs | true |
| write_timeout | 30s |
| default_qos | 1 (validated 0..2, not applied) |
| message_channel_depth | 100 |
| order_matters | true (handlers get messages one at a time, in order) |
| message_store, store_directory | memory, "" (file store needs a directory) |
| will_enabled, will_topic, will_payload, will_qos, will_retained | off |
| enable_tls, tls_cert_file, tls_key_file, tls_ca_file, tls_skip_verify | off |
| enable_metrics, enable_logging | true |

Metrics: counters `mqtt.messages.published` and `mqtt.messages.received` (label `topic`),
`mqtt.connections` (`status=connected|disconnected`), `mqtt.reconnects`.

## Gotchas

- With clean_session true (default) the broker drops subscriptions when the connection drops and
  the extension doesn't resubscribe after an automatic reconnect. Use WithCleanSession(false)
  with a stable, unique client ID if you need to keep receiving.
- Two clients with the same ID keep disconnecting each other (`mqtt connection lost` loops).
- With order_matters, a slow handler holds up the next message; hand work off to a worker.
- With TLS and verification on, validation needs both a client cert and key, so TLS with only a
  CA file doesn't pass validation today.

## Not implemented yet

- SetOnConnectHandler, SetConnectionLostHandler, SetReconnectingHandler only log a warning: the
  client is already connected by the time you can call them.
- default_qos and max_reconnect_attempts are not read.
- enable_tracing and WithTracing are deprecated and do nothing. paho v1.5.1 speaks MQTT 3.1.1, which
  has no user properties, so a message can't carry a traceparent the way queue, events, conduit and
  kafka messages do. The field stays so existing config loads. Real support waits on an MQTT v5 client.
- MQTT 5.
