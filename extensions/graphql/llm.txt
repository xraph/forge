# Forge GraphQL Extension

## Purpose

Runs a gqlgen (github.com/99designs/gqlgen) server inside a Forge app and mounts it on the Forge
router, with a GraphQL Playground, a complexity limit, automatic persisted queries, multipart
file uploads, Apollo Federation v2's `_service` query, Forge metrics and slow query logging.
Also ships a standalone `dataloader` package.

The server only runs the schema compiled into this module (`schema/schema.graphql`: Query.hello,
Query.version, Mutation.echo). You can't supply your own schema or resolvers through the
extension yet. See "Not implemented yet".

Module: github.com/xraph/forge/extensions/graphql (package `graphql`). Its go.mod has no
`replace` for the Forge root, so it builds against the published Forge version in its require
line, even inside this repo.

## Constructors and options

```go

WithEndpoint(endpoint string)
WithPlayground(enable bool)
WithMaxComplexity(maxComplexity int)          // 0 turns the limit off
WithQueryCache(enable bool, ttl time.Duration)
WithMetrics(enable bool)

WithMaxDepth(maxDepth int)                    // validated only
WithTimeout(timeout time.Duration)            // validated only

WithCORS(origins ...string)                   // not read

WithRequireConfig(require bool)

```

Lower level: `NewGraphQLService(config Config, container forge.Container, logger forge.Logger, metrics forge.Metrics) (*GraphQLService, error)`,
`NewGraphQLServer(config Config, logger forge.Logger, metrics forge.Metrics, container forge.Container) (GraphQL, error)`,
`NewResolver(container, logger, metrics, config) *Resolver`.

## What the container holds

`*graphql.GraphQLService` by type and under the alias `graphql` (ServiceKey), and the
`graphql.GraphQL` interface backed by the same instance. When the extension starts it registers
GET and POST routes at `endpoint` and, if enabled, the playground at `playground_endpoint`.

## Key types

```go
type GraphQL interface {
    RegisterType(name string, obj any) error                                  // logs only
    RegisterQuery(name string, resolver FieldResolverFunc) error              // logs only
    RegisterMutation(name string, resolver FieldResolverFunc) error           // logs only
    RegisterSubscription(name string, resolver SubscriptionResolverFunc) error // logs only
    GenerateSchema() (string, error)

    ExecuteQuery(ctx context.Context, query string, variables map[string]any) (*Response, error) // error response
    HTTPHandler() http.Handler
    PlaygroundHandler() http.Handler
    Use(middleware Middleware)                                                // no-op
    EnableIntrospection(enable bool)
    Ping(ctx context.Context) error

```

Also FieldResolverFunc, SubscriptionResolverFunc, Middleware, ExecutorFunc, Request, Response,
Error, Location, GraphQLSchema, TypeDefinition, FieldDefinition, ArgumentDefinition,
GraphQLDirective, DataLoader, FieldResolver, FederationConfig / DefaultFederationConfig().
Sentinel errors: ErrNotInitialized, ErrInvalidQuery, ErrInvalidSchema, ErrTypeNotFound,
ErrResolverNotFound, ErrExecutionFailed, ErrComplexityExceeded, ErrDepthExceeded, ErrTimeout,
ErrInvalidConfig.

## dataloader package

```go
func DefaultLoaderConfig() LoaderConfig                 // Wait 10ms, MaxBatch 100
func NewLoader(config LoaderConfig, batchFunc BatchFunc) *Loader
type BatchFunc func(ctx context.Context, keys []any) ([]any, []error)
(*Loader).Load(ctx, key any) (any, error)
(*Loader).LoadMany(ctx, keys []any) ([]any, error)
(*Loader).Prime(key, value any); Clear(key any); ClearAll()
```

The batch function must return values and errors lined up one-to-one with keys. LoadMany calls
Load one key after another, so it waits a full window per key and doesn't batch; call Load from
concurrent resolvers instead. MaxBatch is not enforced.

`directives.Auth` implements an `@auth(requires:)` directive over `ctx.Value("user")` and
`ctx.Value("roles")`, but the server doesn't wire it in and no field uses it.

## Config

Key `extensions.graphql`, falling back to `graphql`. Options override the file.

| yaml key | default | effect |
| --- | --- | --- |
| endpoint | /graphql | GraphQL route |
| playground_endpoint | /playground | playground route |
| enable_playground | true | serves the playground |
| max_complexity | 1000 | gqlgen fixed complexity limit |
| enable_query_cache | true | automatic persisted queries |
| max_cache_size | 1000 | APQ LRU entries |
| max_upload_size | 10485760 | multipart upload cap |
| enable_metrics | true | graphql_operation_duration_seconds, graphql_operation_total |
| enable_logging | true | operation and error logs |
| log_slow_queries, slow_query_threshold | true, 1s | warn on slow ops (needs metrics or logging on) |

Validated but otherwise unused: max_depth (15, must be >= 1), query_timeout (30s, must be
positive), dataloader_batch_size (100, must be >= 1). Unused: enable_introspection,
enable_dataloader, dataloader_wait, query_cache_ttl, enable_cors, allowed_origins,
enable_tracing, auto_generate_schema, schema_file.

Transports registered: WebSocket, GET, POST, OPTIONS, multipart. The schema has no
subscriptions, so the WebSocket transport has nothing to stream.

## Not implemented yet

- Your own schema and resolvers. For now, run gqlgen in your module and mount its
  `handler.Server` on a Forge route yourself, the way extension.go does.
- Turning introspection off: gqlgen's default server always allows it.
- Federation entity resolvers (the built-in schema has no entities).

## Regenerating

After editing schema/schema.graphql: `go run github.com/99designs/gqlgen generate` from this
directory.
