# Forge gRPC Extension

## Purpose

Runs a grpc-go server (google.golang.org/grpc) next to the app's HTTP server and ties it to the
Forge lifecycle. It gives you the gRPC health checking protocol with per-service checkers, server
reflection, TLS and mutual TLS, keepalive and message size limits, logging, OpenTelemetry server
spans, the rpc.server.call.duration metric, client dial options that trace outbound calls, and
graceful shutdown.

Register your services with WithService or WithServiceRegistrar when you create the extension.
The server can't take a service once it's serving. See "Registering services".

Module: github.com/xraph/forge/extensions/grpc (package `grpc`; import it as `grpcext` so it
doesn't clash with google.golang.org/grpc).

## What the container holds

- `*GRPCService`, also under the name `grpc` (`ServiceKey`). Implements Name/Start/Stop/Health and
  forwards the GRPC methods; `Server() GRPC` returns the underlying server.
- `GRPC`, the interface, backed by the same `*GRPCService` singleton.

Resolve with `forge.Inject[grpcext.GRPC](app.Container())` or
`forge.Inject[*grpcext.GRPCService](app.Container())`. Resolving builds the service but doesn't
start the server: under the extension, GRPCService.Start is a no-op. The extension's Register adds
a PhaseAfterStart hook named "grpc-serve" with Priority math.MinInt, which starts the server
after every other hook, so the server listens when app.Start returns. A listen or TLS error
fails app.Start from that hook.

## Key types

```go
type GRPC interface {
    RegisterService(desc *grpc.ServiceDesc, impl any) error
    Start(ctx context.Context, addr string) error
    Stop(ctx context.Context) error
    GracefulStop(ctx context.Context) error
    AddUnaryInterceptor(interceptor grpc.UnaryServerInterceptor)
    AddStreamInterceptor(interceptor grpc.StreamServerInterceptor)
    RegisterHealthChecker(service string, checker HealthChecker)
    GetServer() *grpc.Server   // nil until Start; never register generated services on it
    IsRunning() bool
    GetStats() ServerStats
    GetServices() []ServiceInfo
    Ping(ctx context.Context) error
}

type HealthChecker interface { Check(ctx context.Context) error }

type ServiceInfo struct { Name string; Methods []MethodInfo; Description string }
type MethodInfo struct { Name string; IsClientStream, IsServerStream bool; InputType, OutputType string }
type ServerStats struct {
    StartTime, TotalConnections, ActiveStreams, RPCsStarted, RPCsSucceeded, RPCsFailed int64
}
```

Sentinel errors (errors.go): ErrNotStarted, ErrAlreadyStarted, ErrServiceNotFound,
ErrInvalidConfig, ErrStartFailed, ErrStopFailed, ErrHealthCheckFailed, ErrRegisterAfterStart,
ErrInvalidService.

## Usage

Add a health checker with the server's setup:

```go
app := forge.NewApp(forge.AppConfig{
    Name: "billing",
    Extensions: []forge.Extension{
        grpcext.NewExtension(
            grpcext.WithAddress(":50051"),
            grpcext.WithServiceRegistrar(func(app forge.App, s grpcext.GRPC) error {
                s.RegisterHealthChecker("billing.db", dbCheck{})
                return nil
            }),
        ),
    },
})
```

Checkers are looked up on every call, so you can also add them later, from anywhere that
resolves grpcext.GRPC.

## Config

Key `extensions.grpc`, falling back to `grpc`. Non-zero programmatic options win over the file.

| yaml key | default |
| --- | --- |
| address | ":50051" |
| max_recv_msg_size, max_send_msg_size | 4194304 (4MB) |
| max_concurrent_streams | 0 (no limit) |
| connection_timeout | 120s |
| keepalive.time / keepalive.timeout | 2h / 20s |
| keepalive.enforcement_policy / min_time / permit_without_stream | true / 5m / false |
| enable_tls, tls_cert_file, tls_key_file, tls_ca_file | false, "" |
| client_auth | false |
| enable_health_check | true |
| enable_reflection | true |
| enable_metrics, enable_tracing, enable_logging | true |

`Config.Validate()` runs in Register: TLS on without cert and key, or client_auth without a CA
file, fails registration. `keepalive.time` is also the max idle time, and twice it is the max
connection age.

## Health service

With enable_health_check on, `grpc.health.v1.Health` is registered. Check returns SERVING for an
empty service name, for a service with no checker, and when the checker returns nil; NOT_SERVING
when the checker errors. The extension's own `Health(ctx)` only reports whether it has started.

## Registering services

Pass services to the extension. It applies them inside the *GRPCService constructor, before the
server can start:

```go
grpcext.NewExtension(
    grpcext.WithService(&pb.Greeter_ServiceDesc, &greeter{}),
    grpcext.WithServiceRegistrar(func(app forge.App, s grpcext.GRPC) error {
        db, err := forge.Inject[*sql.DB](app.Container())
        if err != nil {
            return err
        }
        s.AddUnaryInterceptor(auth)
        return s.RegisterService(&pb.Billing_ServiceDesc, &billing{db: db})
    }),
)
```

- Each registrar runs once, in order, the first time anything resolves the service (no later than
  the extension's Start). An error fails app.Start, wrapped.
- A registrar can resolve what was provided before app.Start and what earlier extensions
  registered. Resolving GRPC or *GRPCService inside it is a circular dependency.
- Config.Services holds the registrars (json/yaml/mapstructure "-"). WithConfig replaces it, so
  put WithService and WithServiceRegistrar after WithConfig. NewGRPCService and NewGRPCServer
  ignore the field.

From another extension or a hook, resolve GRPC and call RegisterService. Anything before the
"grpc-serve" hook works: another extension's Register or Start (list "grpc" in its
dependencies), a PhaseAfterRegister hook, a PhaseAfterStart hook at any priority above
math.MinInt. Tested under both the default and the central-migrations lifecycle. Once app.Start
returns, RegisterService returns ErrRegisterAfterStart. Nothing can dial the server from inside
app.Start, since the port isn't open until that last hook.

On the server itself:

- `RegisterService(&pb.X_ServiceDesc, impl)` before Start is buffered and served. After Start it
  returns ErrRegisterAfterStart. A nil descriptor, an impl that doesn't satisfy desc.HandlerType,
  or a name already taken (pending, or health/reflection when on) returns ErrInvalidService,
  where grpc-go would log.Fatalf at Start.
- `AddUnaryInterceptor` and `AddStreamInterceptor` before Start are chained onto the server. After
  Start they are stored and never called.
- `RegisterHealthChecker` works at any time.
- `GetServer()` is nil until Start. Don't call a generated `pb.RegisterXServer` on it: on a serving
  server grpc-go aborts the process with `grpc: Server.RegisterService after Server.Serve`.
- NewGRPCServer gives you a server outside the extension that you Start and GracefulStop
  yourself. Create it after forge.NewApp, which installs the OpenTelemetry globals it reads.

`examples/grpc-advanced` registers a greeter, an auth interceptor and a health checker through
WithServiceRegistrar.

## Tracing

With enable_tracing (default), every served call gets an otelgrpc server span named
`pkg.Service/Method` with semconv v1.43 attributes: rpc.system.name=grpc, rpc.method (full
`pkg.Service/Method`, no leading slash), rpc.response.status_code (canonical, such as OK or
NOT_FOUND). An incoming traceparent in the metadata joins the caller's trace. Health and reflection
calls get no span. Server-side codes such as INTERNAL mark the span as an error; client-error codes
such as NOT_FOUND don't. The call's context carries trace_id and span_id for a request-scoped
logger, and the server's own logging lines carry them. The server reads the OpenTelemetry globals
that forge.New installs, when it starts.

If you already run your own otelgrpc server handler, remove it, or you get two spans per call.

Leave OTEL_SEMCONV_STABILITY_OPT_IN unset. If it holds rpc/old or rpc/dup, otelgrpc puts the older
attributes on spans (rpc.service, a short rpc.method, a numeric status code) while
rpc_server_call_duration_seconds keeps the v1.43 labels, so spans and metrics stop lining up.

## Metrics

With enable_metrics (default), every served call is recorded in one histogram through forge's
registry: `rpc_server_call_duration_seconds` (OTel name rpc.server.call.duration), labels
rpc_system_name, rpc_method, rpc_response_status_code, buckets 5ms to 10s. Health and reflection
are excluded. A stream records the whole call. A handler that returns a bare context.Canceled or
DeadlineExceeded is recorded as CANCELLED or DEADLINE_EXCEEDED. enable_metrics=false records
nothing. `GetStats()` is unchanged.

Two cases differ from the span. A call to an unknown service or method gets a span (UNIMPLEMENTED)
but no observation, because grpc-go rejects it before interceptors run. A unary call whose handler
succeeds but whose response fails to send is recorded as OK, while the wire and the span say
otherwise.

```promql
sum by (rpc_method) (rate(rpc_server_call_duration_seconds_count[5m]))
sum by (rpc_method) (rate(rpc_server_call_duration_seconds_count{rpc_response_status_code!="OK"}[5m]))
```

Every old forge_grpc_* series is gone (forge_grpc_unary_started/succeeded/failed_total,
forge_grpc_unary_duration_seconds, forge_grpc_stream_succeeded/failed_total,
forge_grpc_stream_duration_seconds, forge_grpc_stream_active). Started, succeeded and failed counts
now come from the histogram's _count split by rpc_response_status_code. forge_grpc_stream_active has
no replacement; GetStats().ActiveStreams still reports it. The status label is the canonical name
(NOT_FOUND), not the Go spelling (NotFound), and rpc_method has no leading slash.

## Client dial options

```go
import forgegrpc "github.com/xraph/forge/extensions/grpc"

conn, err := grpc.NewClient(target,
    append(forgegrpc.ClientDialOptions(), grpc.WithTransportCredentials(creds))...)
```

`ClientDialOptions()` adds an otelgrpc client handler: a client span per outbound call and the
trace context on the wire. Conduit's `Services.GRPC` adds the same handler for you, so don't pass
ClientDialOptions() into it: gRPC appends stats handlers, and a second one gives every call a second
client span. Both read the OpenTelemetry globals when called, so call them after forge.New.

## Gotchas

- GracefulStop(ctx) waits for calls in flight; when ctx ends first it calls Stop and returns
  ctx's error. Stop during a GracefulStop cuts the drain short. Neither holds the server lock
  while grpc-go drains, so calls finishing during shutdown don't deadlock it.
- If TLS is on and the cert, key or CA file fails to load (bad path, bad PEM), Start returns
  `failed to load TLS credentials: ...` and the server doesn't listen. No plaintext fallback.
- `Watch` sends the status, polls the checker every 5s and sends on change. On stop it sends
  NOT_SERVING and ends the stream. `List` returns "" plus every service with a checker.
- `TotalConnections` in `GetStats()` is never updated.
