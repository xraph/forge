# Forge gRPC Extension

## Purpose

Runs a grpc-go server (google.golang.org/grpc) next to the app's HTTP server and ties it to the
Forge lifecycle. It gives you the gRPC health checking protocol with per-service checkers, server
reflection, TLS and mutual TLS, keepalive and message size limits, logging and metrics
interceptors, and graceful shutdown.

Registering your own generated services on the managed server does not work reliably yet. Read
"Not implemented yet" before you plan around it.

Module: github.com/xraph/forge/extensions/grpc (package `grpc`; import it as `grpcext` so it
doesn't clash with google.golang.org/grpc).


Lower level, if you want the server without the extension:

```go
func NewGRPCServer(config Config, logger forge.Logger, metrics forge.Metrics) GRPC
func NewGRPCService(config Config, logger forge.Logger, metrics forge.Metrics) (*GRPCService, error)
```

## What the container holds

- `*GRPCService`, also under the name `grpc` (`ServiceKey`). Implements Name/Start/Stop/Health and
  forwards the GRPC methods; `Server() GRPC` returns the underlying server.
- `GRPC`, the interface, backed by the same `*GRPCService` singleton.

Resolve with `forge.Inject[grpcext.GRPC](app.Container())` or
`forge.Inject[*grpcext.GRPCService](app.Container())`. The extension's `Start` resolves
`*GRPCService` and starts it, so the server listens once the app starts.

## Key types

```go
type GRPC interface {
    RegisterService(desc *grpc.ServiceDesc, impl any) error
    Start(ctx context.Context, addr string) error
    Stop(ctx context.Context) error
    GracefulStop(ctx context.Context) error
    AddUnaryInterceptor(interceptor grpc.UnaryServerInterceptor)
    AddStreamInterceptor(interceptor grpc.StreamServerInterceptor)
    RegisterHealthChecker(service string, checker HealthChecker)
    GetServer() *grpc.Server
    IsRunning() bool
    GetStats() ServerStats
    GetServices() []ServiceInfo
    Ping(ctx context.Context) error
}

type HealthChecker interface { Check(ctx context.Context) error }

type ServiceInfo struct { Name string; Methods []MethodInfo; Description string }
type MethodInfo struct { Name string; IsClientStream, IsServerStream bool; InputType, OutputType string }
type ServerStats struct {
    StartTime, TotalConnections, ActiveStreams, RPCsStarted, RPCsSucceeded, RPCsFailed int64
}
```

Sentinel errors (errors.go): ErrNotStarted, ErrAlreadyStarted, ErrServiceNotFound,
ErrInvalidConfig, ErrStartFailed, ErrStopFailed, ErrHealthCheckFailed.

## Usage

Add a health checker once the app has started:

```go
app := forge.NewApp(forge.AppConfig{
    Name: "billing",
    Extensions: []forge.Extension{
        grpcext.NewExtension(grpcext.WithAddress(":50051")),
    },
})

_ = app.RegisterHookFn(forge.PhaseAfterStart, "grpc-health", func(ctx context.Context, a forge.App) error {
    srv, err := forge.Inject[grpcext.GRPC](a.Container())
    if err != nil {
        return err
    }
    srv.RegisterHealthChecker("billing.db", dbCheck{})
    return nil
})
```

Checkers are looked up on every call, so you can add them at any time.

## Config

Key `extensions.grpc`, falling back to `grpc`. Non-zero programmatic options win over the file.

| yaml key | default |
| --- | --- |
| address | ":50051" |
| max_recv_msg_size, max_send_msg_size | 4194304 (4MB) |
| max_concurrent_streams | 0 (no limit) |
| connection_timeout | 120s |
| keepalive.time / keepalive.timeout | 2h / 20s |
| keepalive.enforcement_policy / min_time / permit_without_stream | true / 5m / false |
| enable_tls, tls_cert_file, tls_key_file, tls_ca_file | false, "" |
| client_auth | false |
| enable_health_check | true |
| enable_reflection | true |
| enable_metrics, enable_tracing, enable_logging | true |

`Config.Validate()` runs in Register: TLS on without cert and key, or client_auth without a CA
file, fails registration. `keepalive.time` is also the max idle time, and twice it is the max
connection age.

## Health service

With enable_health_check on, `grpc.health.v1.Health` is registered. Check returns SERVING for an
empty service name, for a service with no checker, and when the checker returns nil; NOT_SERVING
when the checker errors. The extension's own `Health(ctx)` only reports whether it has started.

## Metrics

From the metrics interceptors, all labelled by `method`: grpc_unary_started_total,
grpc_unary_succeeded_total, grpc_unary_failed_total (plus `code`),
grpc_unary_duration_seconds, grpc_stream_active, grpc_stream_succeeded_total,
grpc_stream_failed_total, grpc_stream_duration_seconds.

## Gotchas

- If TLS files are configured but fail to load (bad path, bad PEM), the server logs
  `failed to load TLS credentials` and starts in plaintext. Check your logs.
- The tracing interceptor only writes a debug log line. It creates no spans.
- `Watch` sends one SERVING message and returns; `List` returns an empty list.

## Not implemented yet

- No dependable point to register your own services. Before Start, `Start` builds a fresh
  `grpc.Server` and drops what you registered; after Start, grpc-go aborts the process with
  `grpc: Server.RegisterService after Server.Serve`. Run your application services on a
  `grpc.Server` you create and start yourself for now. `examples/grpc-advanced` hits this.
- `AddUnaryInterceptor` and `AddStreamInterceptor` have the same timing problem: interceptors are
  chained when the server is built, so ones added later are stored and never called.

## Dependencies

- google.golang.org/grpc (health, reflection, credentials)
- github.com/xraph/forge, github.com/xraph/vessel
