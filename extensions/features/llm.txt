# Forge Features Extension

## Purpose

Feature flags for Forge apps. Boolean, string, number and JSON flags defined in Go, targeting by
user ID, email, name, IP, country, group or custom attribute, and percentage rollouts with stable
hashing. Flags are evaluated in process by the local provider. LaunchDarkly, Unleash, Flagsmith
and PostHog settings exist but those providers are not wired up (see "Not implemented yet").

Module: github.com/xraph/forge/extensions/features (package `features`). The `providers`
subpackage holds the local provider and client code for the remote services.

## Constructors and options

```go
func NewExtension(opts ...ConfigOption) forge.Extension
func NewExtensionWithConfig(config Config) forge.Extension
func DefaultConfig() Config    // Enabled true, Provider "local", RefreshInterval 30s, empty maps
func NewService(config Config, provider Provider, logger forge.Logger) *Service
func NewLocalProvider(config LocalProviderConfig, defaults map[string]any) Provider

type ConfigOption func(*Config)
WithEnabled(enabled bool)                         // false skips registration; Get then errors
WithProvider(provider string)
WithRefreshInterval(interval time.Duration)       // 0 turns the refresh loop off
WithCache(enabled bool, ttl time.Duration)        // stored, nothing reads it
WithLocalFlags(flags map[string]FlagConfig)       // also selects "local"
WithDefaultFlags(flags map[string]any)            // fallbacks for undefined keys
WithLaunchDarkly(sdkKey string)
WithUnleash(url, apiToken, appName string)
WithFlagsmith(apiURL, environmentKey string)
WithPostHog(apiKey, host string)
WithRequireConfig(require bool)                   // Register fails without a config section
WithConfig(config Config)
```

## What the container holds

`*features.Service`, also under `features` (ServiceKey) and `features.Service` (ServiceKeyLegacy).
Helpers: `Get(container)`, `MustGet(container)`, `GetFromApp(app)`, `MustGetFromApp(app)`.

## Usage

```go
features.NewExtension(features.WithLocalFlags(map[string]features.FlagConfig{
    "new-checkout": {
        Key: "new-checkout", Type: "boolean", Enabled: true,
        Rollout: &features.RolloutConfig{Percentage: 25},
    },
}))

flags, err := features.GetFromApp(app)
user := features.NewUserContext("user-42").WithEmail("ada@example.com").WithGroups([]string{"beta"})
on := flags.IsEnabled(ctx, "new-checkout", user)
limit := flags.GetInt(ctx, "upload-limit-mb", user, 10)
```

## Service methods

| Method | Returns |
| --- | --- |
| IsEnabled(ctx, key, user *UserContext) | bool, false when unknown |
| IsEnabledWithDefault(ctx, key, user, def bool) | bool |
| GetString(ctx, key, user, def string) | string |
| GetInt(ctx, key, user, def int) | int |
| GetFloat(ctx, key, user, def float64) | float64 |
| GetJSON(ctx, key, user, def any) | any |
| GetAllFlags(ctx, user) | (map[string]any, error) |
| Refresh(ctx) | error (no-op for local) |

Getters never return an error: an evaluation error logs a warning and returns the default.

## Key types

- `UserContext{UserID, Email, Name string; Groups []string; Attributes map[string]any; IP, Country string}`.
  `NewUserContext(userID string) *UserContext`; chain WithEmail, WithName, WithGroups,
  WithAttribute(key, value), WithIP, WithCountry. Also GetAttribute, GetAttributeString, HasGroup.
  A nil user context skips targeting and rollouts.
- `FlagConfig{Key, Name, Description, Type string; Enabled bool; Value any; Targeting []TargetingRule; Rollout *RolloutConfig}`.
  Type is "boolean", "string", "number" or "json"; GetAllFlags uses it to choose the getter.
- `TargetingRule{Attribute, Operator string; Values []string; Value any}`.
- `RolloutConfig{Percentage int; Attribute string}`.
- `Provider` interface: Name, Initialize, IsEnabled, GetString, GetInt, GetFloat, GetJSON,
  GetAllFlags, Refresh, Close, Health (each getter takes a default and returns (T, error)).
- Also FlagValue, EvaluationResult, FlagEvaluationEvent, LocalProviderConfig, and config
  structs LaunchDarklyConfig, UnleashConfig, FlagsmithConfig, PostHogConfig.

## Evaluation order (local provider)

1. Targeting rules in order. A matching rule whose Value has the requested type wins.
2. Boolean flags with a Rollout: users inside the percentage get `Enabled`, users outside get
   the opposite. (Enabled false + 25% means 25% get false and 75% get true.)
3. The flag's own value (`Enabled` for booleans, `Value` otherwise).
Undefined flags fall back to WithDefaultFlags, then the getter's default.

Rule attributes: user_id, email, name, ip, country match the UserContext fields; `group` matches
Groups and only with `in`; anything else reads Attributes[name] when it's a string.
Operators: equals and in (equals one of Values), not_in, contains (case-sensitive substring).
Rollout hashing: MD5 of the attribute (user_id by default) into 100 buckets; an empty value is
always outside; Percentage <= 0 is nobody, >= 100 is everybody.

## Gotchas

- Types match exactly. GetInt only returns values stored as Go `int`, GetFloat only `float64`.
  A mismatch silently returns your default with no log line.
- Config comes from `extensions.features` (falling back to `features`) as well as options.
  Options win over the file, the file over defaults. WithRequireConfig(true) makes a missing
  section a Register error.
- A flag's `value` (and a targeting rule's `value`) can come from YAML. A bare `50` decodes as Go
  `int` and `50.0` as `float64`, so write the number in the form your getter expects.
- No public way to change local flags at runtime.

## Not implemented yet

- launchdarkly, unleash, flagsmith, posthog: the root `NewXxxProvider` functions return
  "<name> provider not yet available - dependencies not resolved", so selecting one makes
  registration fail. The `providers` package's own clients are never called by the extension.
- EnableCache and CacheTTL are not read.
