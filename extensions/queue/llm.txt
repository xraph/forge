# Forge Queue Extension

## Purpose

One `Queue` interface in front of four message queue backends: in-memory, Redis Streams
(github.com/redis/go-redis/v9), RabbitMQ (github.com/rabbitmq/amqp091-go) and NATS JetStream
(github.com/nats-io/nats.go). You publish background jobs and consume them in workers, with
dead-letter queues, priority and TTL where the backend supports them. Switching backends means
changing `driver`.

Module: github.com/xraph/forge/extensions/queue (package `queue`).

## What the container holds

`*queue.QueueService` by type and under the alias `queue` (ServiceKey), and the `queue.Queue`
interface backed by the same instance.

```go
q, err := queue.GetQueue(app.Container())   // also MustGetQueue, GetQueueFromApp, MustGetQueueFromApp
q, err = forge.Inject[queue.Queue](app.Container())
```

The extension's Start connects to the backend, so an unreachable broker stops the app starting.

## Key types

```go
type Queue interface {
    Connect(ctx context.Context) error
    Disconnect(ctx context.Context) error
    Ping(ctx context.Context) error
    DeclareQueue(ctx context.Context, name string, opts QueueOptions) error
    DeleteQueue(ctx context.Context, name string) error
    ListQueues(ctx context.Context) ([]string, error)
    GetQueueInfo(ctx context.Context, name string) (*QueueInfo, error)
    PurgeQueue(ctx context.Context, name string) error
    Publish(ctx context.Context, queue string, message Message) error
    PublishBatch(ctx context.Context, queue string, messages []Message) error
    PublishDelayed(ctx context.Context, queue string, message Message, delay time.Duration) error
    Consume(ctx context.Context, queue string, handler MessageHandler, opts ConsumeOptions) error
    StopConsuming(ctx context.Context, queue string) error
    Ack(ctx context.Context, messageID string) error
    Nack(ctx context.Context, messageID string, requeue bool) error
    Reject(ctx context.Context, messageID string) error
    GetDeadLetterQueue(ctx context.Context, queue string) ([]Message, error)
    RequeueDeadLetter(ctx context.Context, queue string, messageID string) error
    Stats(ctx context.Context) (*QueueStats, error)
}

type MessageHandler func(ctx context.Context, msg Message) error

type Message struct {
    ID, Queue string; Body []byte; Headers map[string]string
    Priority int /* 0-9 */; Delay, Expiration time.Duration
    Retries, MaxRetries int; PublishedAt time.Time; Metadata map[string]any
}
type QueueOptions struct {
    Durable, AutoDelete, Exclusive bool; MaxLength, MaxLengthBytes int64
    MessageTTL time.Duration; MaxPriority int; DeadLetterQueue string; Arguments map[string]any
}
type ConsumeOptions struct {
    ConsumerTag string; AutoAck, Exclusive bool; PrefetchCount, Priority, Concurrency int
    RetryStrategy RetryStrategy; Timeout time.Duration; Arguments map[string]any
}
func DefaultQueueOptions() QueueOptions      // durable, no limits
func DefaultConsumeOptions() ConsumeOptions  // prefetch 10, concurrency 1, 30s timeout
```

Also QueueInfo, QueueStats, RetryStrategy. Sentinel errors in errors.go (ErrNotConnected,
ErrQueueNotFound, ErrPublishFailed, ErrUnsupportedDriver, ErrMessageTooLarge, ...).

## Usage

```go
_ = q.DeclareQueue(ctx, "emails", queue.DefaultQueueOptions())
_ = q.Consume(ctx, "emails", func(ctx context.Context, msg queue.Message) error {
    return send(ctx, msg.Body)
}, queue.DefaultConsumeOptions())   // returns immediately; workers run in the background
_ = q.Publish(ctx, "emails", queue.Message{Body: payload})
```

## Backend differences

- inmemory: declare before Publish and Consume. Handler error moves the message to the DLQ. On
  nil, removed with AutoAck, otherwise held until `Ack(ctx, msg.ID)`. ConsumeOptions.Concurrency
  sets worker goroutines. PublishDelayed blocks the caller for the delay.
- redis: one stream per queue (`queue:<name>:stream`), consumer group `consumers`. Declare before
  Consume. Handler error pushes to the `queue:<name>:dlq` list and acks. No retry.
- rabbitmq: a queue per name via the default exchange, persistent messages. Declare before
  Publish (the default exchange drops messages for a missing queue). Handler error nacks; the
  broker dead-letters if the queue has DeadLetterQueue. PublishDelayed uses a `<name>.delayed`
  TTL queue. QueueOptions become `x-` arguments; Priority needs MaxPriority on the queue.
- nats: a JetStream stream per queue, file storage, subjects `<name>.*`. Declare before Publish
  and Consume. Handler error terminates, or NakWithDelay while Retries < MaxRetries.
  PublishDelayed waits in a goroutine (lost on exit). Stop with StopConsuming, not ctx.
- Ack, Nack and Reject only do something on inmemory; the other drivers ack based on the
  handler's return value. GetDeadLetterQueue returns nothing on rabbitmq and nats.

## Config

Key `extensions.queue`, falling back to `queue`. File overrides defaults, options override the file.

| yaml key | default | used by |
| --- | --- | --- |
| driver | "inmemory" | all |
| url, hosts | "" | redis, rabbitmq and nats need one |
| username, password | "" | redis, nats, rabbitmq (when built from hosts) |
| vhost | "" | rabbitmq (when built from hosts) |
| max_connections, max_idle_connections | 10, 5 | redis pool; idle must not exceed max |
| connect_timeout, read_timeout, write_timeout | 10s, 30s, 30s | redis |
| max_retries | 3 | redis command retries, nats reconnects |
| default_prefetch | 10 | rabbitmq channel QoS |
| default_concurrency, max_message_size | 1, 1048576 | validated, not applied |
| enable_dead_letter | true | inmemory, redis |

URLs are redacted in logs and connection errors.

## Tracing and metrics

`QueueService` traces every message and times it, through `forge/messaging`. `enable_tracing` and
`enable_metrics` (both default true) gate it. `messaging.system` is the driver, with `inmemory`
reported as `memory`.

- `Publish` and `PublishDelayed` start a producer span `publish <queue>` and write the trace context
  headers (`traceparent`, `tracestate` when set, `baggage` when the context has any) into a copy of `Message.Headers`. The map you pass is never modified,
  so you can reuse one headers map across publishes and goroutines. A nil map stays nil when
  there is no trace context to add.
- `PublishBatch` loops over the service's `Publish`, so each message gets its own span. An empty
  batch goes straight to the backend's `PublishBatch`, so it still answers `ErrNotConnected` when disconnected.
- `Consume` wraps your handler in a consumer span `process <queue>`, a child of the publisher's
  span. Spans you start from the handler's `ctx` nest under it, and `trace_id` and `span_id` are on
  the context for logging. A message with no `traceparent` (an old publisher) gets a root span. A
  handler error marks the span as an error.
- Two histograms: `messaging.client.operation.duration` for publishes and
  `messaging.process.duration` for handlers. The Prometheus names are
  `messaging_client_operation_duration_seconds` and `messaging_process_duration_seconds`.
- With `enable_tracing` off, no spans start but `traceparent` still passes through the headers.
  With `enable_metrics` off, nothing is recorded.
- Only calls through `QueueService` are instrumented. A backend you build with `NewInMemoryQueue`
  and the like, and use directly, gets no spans and no headers.

## Not implemented yet

- No driver reads: enable_tls and tls_cert_file/tls_key_file/tls_ca_file, insecure_skip_verify,
  enable_priority, enable_delayed, enable_persistence, dead_letter_suffix, default_timeout,
  retry_backoff, retry_multiplier, max_retry_backoff, keep_alive.
  For TLS use a `rediss://`, `amqps://` or `tls://` URL.
- PublishDelayed on redis writes to a sorted set no consumer reads, so delayed messages are never
  delivered.
- Nothing increments Message.Retries, so on rabbitmq and nats MaxRetries > 0 means "retry until
  it succeeds". ConsumeOptions.RetryStrategy isn't read by any driver.
