# Forge oRPC Extension

## Purpose

Exposes a Forge app's HTTP routes as JSON-RPC 2.0 methods on one endpoint (`POST /rpc`), with
batch requests, a method list, and a generated OpenRPC 1.3.2 document. Calling a method builds
an HTTP request for the route and runs the real handler through the router.

Despite the name, this is not the TypeScript oRPC wire protocol. It's JSON-RPC 2.0 plus OpenRPC.
SPEC_COMPLIANCE.md lists where it deviates from both specs.

Module: github.com/xraph/forge/extensions/orpc (package `orpc`).

## What the container holds

`*orpc.ORPCService` by type and under the alias `orpc` (ServiceKey). It implements the ORPC
methods and `Server() ORPC`.

```go
type ORPC interface {
    RegisterMethod(method *Method) error
    GetMethod(name string) (*Method, error)
    ListMethods() []Method
    GenerateMethodFromRoute(route forge.RouteInfo) (*Method, error)
    HandleRequest(ctx context.Context, req *Request) *Response
    HandleBatch(ctx context.Context, requests []*Request) []*Response
    OpenRPCDocument() *OpenRPCDocument
    Use(interceptor Interceptor)
    GetStats() ServerStats
    SetRouter(router forge.Router)
}
type Interceptor func(ctx context.Context, req *Request, next MethodHandler) (any, error)
type MethodHandler func(ctx any, params any) (any, error)
type Method struct {
    Name, Description string; Params *ParamsSchema; Result *ResultSchema
    Handler MethodHandler; RouteInfo any; Tags []string; Deprecated bool; Metadata map[string]any
}
```

Add your own methods or interceptors from a `forge.PhaseAfterStart` hook:

```go
svc, err := forge.Inject[*orpc.ORPCService](a.Container())
svc.Use(func(ctx context.Context, req *orpc.Request, next orpc.MethodHandler) (any, error) {
    return next(ctx, req.Params)
})
err = svc.RegisterMethod(&orpc.Method{Name: "system.ping",
    Handler: func(ctx any, params any) (any, error) { return map[string]string{"pong": "ok"}, nil }})
```

## Wire types (types.go)

Request{JSONRPC, Method string; Params json.RawMessage; ID any}, Response{JSONRPC; Result any;
Error *Error; ID any}, Error{Code int; Message string; Data any}. Helpers NewErrorResponse,
NewErrorResponseWithData, NewSuccessResponse, (*Request).IsNotification, GetErrorMessage(code).
Codes: ErrParseError -32700, ErrInvalidRequest -32600, ErrMethodNotFound -32601,
ErrInvalidParams -32602, ErrInternalError -32603, ErrServerError -32000. Go sentinel errors:
ErrMethodExists, ErrMethodNotFoundError, ErrInvalidMethodName, ErrDisabled, ErrBatchDisabled,
ErrBatchTooLarge, ErrRequestTooLarge. OpenRPC types: OpenRPCDocument, OpenRPCInfo,
OpenRPCMethod, OpenRPCParam, OpenRPCResult, OpenRPCError, OpenRPCTag, OpenRPCServer, ...;
schema types ParamsSchema, ResultSchema, PropertySchema.

## Routes and method names

Endpoints: POST /rpc (single or batch), GET /rpc/methods (WithDiscovery), GET /rpc/schema
(WithOpenRPC). Routes are read when the extension starts, so register them before app.Run.

Default naming (`path`): verb word (POST create, GET get, PUT update, PATCH patch, DELETE delete)
plus the path with slashes as dots, parameter markers dropped and hyphens as underscores:
`GET /users/:id` is `get.users.id`. `method` strategy uses the route name (forge.WithName).
MethodPrefix is prepended to every name, including custom ones.

Route options read by the extension: forge.WithORPCMethod(name), forge.WithORPCExclude(),
forge.WithORPCParams(schema), forge.WithORPCResult(schema), forge.WithORPCPrimaryResponse(code),
plus forge.WithSummary (description) and forge.WithTags (tags). forge.WithORPCTags sets
`orpc.tags` metadata that the extension never reads.

Calling: params is an object; path params are top-level keys, the body goes under `body`, query
values under `query`. Status >= 400 from the route becomes -32603 `route returned status <code>`.
A non-JSON response comes back as {"status": ..., "body": ...}. JSON-RPC responses always use
HTTP 200.

## Config

Key `extensions.orpc`, falling back to `orpc`. Options override the file. YAML keys: enabled,
endpoint, openrpc_endpoint, server_name, server_version, auto_expose_routes, method_prefix,
exclude_patterns, include_patterns, naming_strategy, enable_openrpc, enable_discovery,
enable_batch, batch_limit, max_request_size, enable_metrics, plus the unused require_auth,
auth_header, auth_tokens, rate_limit_per_minute, request_timeout, schema_cache.

Metrics: `orpc_requests_total` (labels status, method), gauge `orpc_methods_total`.

## Gotchas

- Headers on the original POST /rpc (Authorization, cookies, tracing) are not copied to the
  request the route sees, so routes that read the caller's identity get nothing over JSON-RPC.
- Notifications (no id) still get a response, and one bad element rejects a whole batch. See
  SPEC_COMPLIANCE.md.
- Pattern matching uses filepath.Match; a trailing `/*` matches anything under the prefix.

## Not implemented yet

- Auth, rate limiting, request timeout and schema cache settings are stored and validated but
  not applied. Put middleware or the auth extension in front of the endpoint.
- `custom` naming strategy (behaves like `path`).
