# Forge Consensus Extension

## Purpose

Raft consensus building blocks in Go: a Raft node with leader election, pre-vote, log
replication and snapshots, plus storage, transports, discovery and state machines to build a
node from. A Forge extension sits on top and runs a node from configuration.

Read "Status" before you use any of it.

Module: github.com/xraph/forge/extensions/consensus (package `consensus`). Most root types and
helpers are aliases over `consensus/internal` (exports.go).

## Status

- `raft`: leader election, log replication and applying entries work over the in-process, TCP and
  HTTP transports (three node tests). Log, term and vote survive restarts. Followers behind the
  leader's snapshot catch up through chunked InstallSnapshot.
- `consensus.NewExtension` builds storage (badger, boltdb, memory), the tcp or http transport
  (TLS/mTLS from security.*), a memory state machine and the Raft node from config.
- Not implemented: gRPC transport, membership changes, leadership transfer, linearizable reads,
  non-static discovery in the extension.

## Packages and constructors

Each constructor takes a config struct and a `forge.Logger`.

- raft: `NewNode(config raft.Config, logger, stateMachine internal.StateMachine, transport internal.Transport, storage internal.Storage) (*Node, error)`.
  Node methods: Start, Stop, IsLeader, GetLeader, Propose(ctx, command []byte), GetCommitIndex, AddPeer(peerID).
- storage: `NewMemoryStorage(MemoryStorageConfig, logger) *MemoryStorage`,
  `NewBadgerStorage(BadgerStorageConfig, logger) (*BadgerStorage, error)`,
  `NewBoltDBStorage(BoltDBStorageConfig, logger) (*BoltDBStorage, error)`,
  `NewWAL(nodeID string, WALConfig, logger) (*WAL, error)`.
- transport: `NewLocalTransport(LocalTransportConfig, logger) *LocalTransport` (in process; link
  with `Connect(other)`), `NewGRPCTransport`, `NewTCPTransport`, `NewHTTPTransport`,
  `NewTLSManager`, serializers (Gob, JSON, Protobuf, compressed).
- statemachine: `NewMemoryStateMachine(MemoryStateMachineConfig, logger) *MemoryStateMachine`
  (key-value map; commands `set`, `delete`, `increment`; Query `{"type":"get","key":...}`),
  `NewPersistentStateMachine(PersistentStateMachineConfig, logger) (*PersistentStateMachine, error)`.
- discovery: NewStaticDiscovery, NewDNSDiscovery, NewConsulDiscovery, NewEtcdDiscovery,
  NewKubernetesDiscovery, NewRegistry.
- cluster: `NewManager(ManagerConfig, logger)`, plus membership, quorum, topology and rebalance managers.
- middleware: NewLeadershipMiddleware, NewQuorumMiddleware, NewMetricsMiddleware,
  NewReadOnlyMiddleware, NewRedirectMiddleware, NewConsistencyMiddleware.
- testing: in-process cluster harness.

## Usage (in-process cluster)

```go
tr := transport.NewLocalTransport(transport.LocalTransportConfig{NodeID: id}, logger)
st := storage.NewMemoryStorage(storage.MemoryStorageConfig{}, logger)
sm := statemachine.NewMemoryStateMachine(statemachine.MemoryStateMachineConfig{}, logger)
node, err := raft.NewNode(raft.Config{
    NodeID: id, HeartbeatInterval: 100 * time.Millisecond,
    ElectionTimeoutMin: 300 * time.Millisecond, ElectionTimeoutMax: 600 * time.Millisecond,
}, logger, sm, tr, st)
_ = st.Start(ctx)
// for every other peer: tr.Connect(peerTransport); node.AddPeer(peerID)
_ = tr.Start(ctx); _ = node.Start(ctx)

cmd, _ := json.Marshal(consensus.Command{Type: "set", Payload: map[string]any{"key": "k", "value": "v"}})
err = leaderNode.Propose(ctx, cmd)   // a follower returns a not-leader error naming the leader
```

The README quick start is the full, compiling version of this.

Container entries: `*consensus.Service` (aliases `consensus`, `consensus:service`),
`ClusterManager` (`consensus:cluster`, nil: membership is the static peer list), `RaftNode`
(`consensus:raft`), `StateMachine` (`consensus:statemachine`), `*LeadershipChecker`
(`consensus:leadership`). RaftNode and StateMachine are created by Start, so resolve them after
the app has started.

Service: `Apply` commits through the leader (ErrNotLeader elsewhere); `Read` queries the local
state machine; `Snapshot` compacts; `StepDown` works; AddNode/RemoveNode return
ErrMembershipChangeUnsupported; TransferLeadership is not implemented. NewConsensusService fails
for grpc transport, pebble/postgres storage and non-static discovery.
admin_api.enabled (default false) registers the admin routes on the app router.

## Config

Key `extensions.consensus`, falling back to `consensus`. Options override the file. Validation
at registration: node_id set (no default); cluster_id set ("default"); bind_port 1..65535
(7000); raft.heartbeat_interval < election_timeout_min < election_timeout_max (1s, 5s, 10s);
bind_addr ("127.0.0.1"); transport.type tcp or http ("tcp", grpc rejected as not implemented); transport.max_message_size positive (4MB); discovery.type
static/dns/consul/etcd/kubernetes ("static"); storage.type badger/boltdb/pebble/postgres
("badger") with storage.path ("./data/consensus"); TLS needs cert_file and key_file, mTLS needs
ca_file; enable_encryption needs one key source (see Encryption at rest); admin_api.enable_auth needs api_key.
enable_tls serves and dials over TLS; enable_mtls also requires client certificates and checks
each message's sender against its certificate (node ID as a DNS SAN in each node certificate).

Other sections: election, health, observability, resilience, admin_api, events, advanced. Full
keys and defaults in internal/config.go. The extension acts on: health.enabled and
health.check_interval, observability.metrics.enabled and collection_interval,
advanced.enable_auto_snapshot with raft.snapshot_interval, and events.enabled (adds an `events`
dependency and publishes start and stop events when an event bus is present).

## Encryption at rest

security.enable_encryption wraps the storage backend in storage.EncryptedStorage (any backend).
Every value (log entries, currentTerm, votedFor, snapshot_<index>, snapshot_meta) is sealed with
AES-256-GCM: version(1) | key ID(4, big endian) | random 96-bit nonce(12) | ciphertext | tag(16),
33 bytes of overhead. GCM additional data = version + key ID + storage key, so moved, edited or
re-labelled values fail with storage.ErrDecrypt. Storage keys stay plaintext (they only carry
indexes; range scans keep working). Not covered: storage.NewWAL files (unused by the service),
data in transit (use TLS/mTLS), key names chosen by your own state machine.
Keys: 32 bytes. encryption_key_file (raw 32 bytes, 64 hex chars or base64) or
encryption_key_env (hex or base64) is key ID 1; encryption_keys: [{id, file|env|value}] for
rotation, active = encryption_active_key_id or the highest ID. Inline keys (encryption_key,
value) need allow_inline_encryption_key. Keys load in Start; bad size or source fails with
storage.ErrInvalidEncryptionKey; key material is never logged or put in errors.
Start checks a per-key-ID encrypted check value under reserved keys (prefix 0x00): a wrong key
fails with ErrWrongKey; encryption over a plaintext store fails with ErrPlaintextStore (set
encryption_migrate_plaintext once to encrypt in place); plaintext over an encrypted store fails
with ErrEncryptedStore (decrypt offline with storage.MigrateToPlaintext); an interrupted
migration fails with ErrMigrationIncomplete until rerun. Service.ReencryptStorage() rewrites
values under the active key while the node runs; after that old keys can be removed.

## Gotchas

- bind_addr defaults to 127.0.0.1. Set it explicitly for a cluster spanning hosts.
- Migrating to or from encryption rewrites values in place; BoltDB free pages and Badger value
  logs can keep old plaintext until compaction. Rebuild from an empty path if that matters.

## Not implemented yet

- gRPC transport, cluster membership changes, leadership transfer, linearizable reads,
  and discovery other than the static peer list in the extension.
