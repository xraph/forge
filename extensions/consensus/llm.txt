# Forge Consensus Extension

## Purpose

Raft consensus building blocks in Go: a Raft node with leader election, pre-vote, log
replication and snapshots, plus storage, transports, discovery and state machines to build a
node from. A Forge extension sits on top, but it does not wire those pieces together yet.

Read "Status" before you use any of it. Today the useful path is assembling `raft.Node`
yourself on the in-process transport.

Module: github.com/xraph/forge/extensions/consensus (package `consensus`). Most root types and
helpers are aliases over `consensus/internal` (exports.go).

## Status

- `raft`: leader election and log replication work on the in-process transport. Three nodes
  elect a leader and a proposed entry commits on a majority.
- Followers advance their commit index but don't apply committed entries to their state
  machine. Read from the leader.
- `consensus.NewExtension`: validates config and registers services, but its storage,
  transport, discovery, state machine and Raft node are never created (the init steps only log).
- gRPC/TCP/HTTP transports, BadgerDB/BoltDB storage and the discovery backends compile, but
  nothing in this repo runs a networked cluster on them.
- `testing/` runs in-process clusters; `TestLogReplication` is skipped under `-short`, which is
  how CI runs it.

## Packages and constructors

Each constructor takes a config struct and a `forge.Logger`.

- raft: `NewNode(config raft.Config, logger, stateMachine internal.StateMachine, transport internal.Transport, storage internal.Storage) (*Node, error)`.
  Node methods: Start, Stop, IsLeader, GetLeader, Propose(ctx, command []byte), GetCommitIndex, AddPeer(peerID).
- storage: `NewMemoryStorage(MemoryStorageConfig, logger) *MemoryStorage`,
  `NewBadgerStorage(BadgerStorageConfig, logger) (*BadgerStorage, error)`,
  `NewBoltDBStorage(BoltDBStorageConfig, logger) (*BoltDBStorage, error)`,
  `NewWAL(nodeID string, WALConfig, logger) (*WAL, error)`.
- transport: `NewLocalTransport(LocalTransportConfig, logger) *LocalTransport` (in process; link
  with `Connect(other)`), `NewGRPCTransport`, `NewTCPTransport`, `NewHTTPTransport`,
  `NewTLSManager`, serializers (Gob, JSON, Protobuf, compressed).
- statemachine: `NewMemoryStateMachine(MemoryStateMachineConfig, logger) *MemoryStateMachine`
  (key-value map; commands `set`, `delete`, `increment`; Query `{"type":"get","key":...}`),
  `NewPersistentStateMachine(PersistentStateMachineConfig, logger) (*PersistentStateMachine, error)`.
- discovery: NewStaticDiscovery, NewDNSDiscovery, NewConsulDiscovery, NewEtcdDiscovery,
  NewKubernetesDiscovery, NewRegistry.
- cluster: `NewManager(ManagerConfig, logger)`, plus membership, quorum, topology and rebalance managers.
- middleware: NewLeadershipMiddleware, NewQuorumMiddleware, NewMetricsMiddleware,
  NewReadOnlyMiddleware, NewRedirectMiddleware, NewConsistencyMiddleware.
- testing: in-process cluster harness.

## Usage (in-process cluster)

```go
tr := transport.NewLocalTransport(transport.LocalTransportConfig{NodeID: id}, logger)
st := storage.NewMemoryStorage(storage.MemoryStorageConfig{}, logger)
sm := statemachine.NewMemoryStateMachine(statemachine.MemoryStateMachineConfig{}, logger)
node, err := raft.NewNode(raft.Config{
    NodeID: id, HeartbeatInterval: 100 * time.Millisecond,
    ElectionTimeoutMin: 300 * time.Millisecond, ElectionTimeoutMax: 600 * time.Millisecond,
}, logger, sm, tr, st)
_ = st.Start(ctx)
// for every other peer: tr.Connect(peerTransport); node.AddPeer(peerID)
_ = tr.Start(ctx); _ = node.Start(ctx)

cmd, _ := json.Marshal(consensus.Command{Type: "set", Payload: map[string]any{"key": "k", "value": "v"}})
err = leaderNode.Propose(ctx, cmd)   // a follower returns a not-leader error naming the leader
```

The README quick start is the full, compiling version of this.

## The extension

```go
func NewExtension(opts ...ConfigOption) forge.Extension
func NewExtensionWithConfig(config Config) forge.Extension
func DefaultConfig() Config

WithNodeID(id string)
WithClusterID(id string)
WithBindAddress(addr string, port int)
WithPeers(peers []PeerConfig)              // PeerConfig{ID, Address string; Port int}
WithTransportType(transportType string)    // grpc, tcp
WithDiscoveryType(discoveryType string)    // static, dns, consul, etcd, kubernetes
WithStorageType(storageType string)        // badger, boltdb, pebble, postgres
WithStoragePath(path string)
WithTLS(certFile, keyFile string)
WithMTLS(caFile string)
WithConfig(cfg Config)
WithRequireConfig(require bool)
```

Container entries: `*consensus.Service` (aliases `consensus`, `consensus:service`),
`ClusterManager` (`consensus:cluster`), `RaftNode` (`consensus:raft`), `StateMachine`
(`consensus:statemachine`), `*LeadershipChecker` (`consensus:leadership`). Because the
components are never built, the RaftNode and StateMachine entries are nil.

What you get from the service today: `Apply` always returns ErrNotLeader; `Read` panics on the
nil state machine; `HealthCheck` returns "storage not initialized" (and the health loop logs it every
health.check_interval); GetRaftNode/GetStateMachine/GetStorage/GetTransport return nil;
TransferLeadership and StepDown return "not yet implemented".

## Config

Key `extensions.consensus`, falling back to `consensus`. Options override the file. Validation
at registration: node_id set (no default); cluster_id set ("default"); bind_port 1..65535
(7000); raft.heartbeat_interval < election_timeout_min < election_timeout_max (1s, 5s, 10s);
transport.type grpc or tcp ("grpc"); transport.max_message_size positive (4MB); discovery.type
static/dns/consul/etcd/kubernetes ("static"); storage.type badger/boltdb/pebble/postgres
("badger") with storage.path ("./data/consensus"); TLS needs cert_file and key_file, mTLS needs
ca_file.

Other sections: election, health, observability, resilience, admin_api, events, advanced. Full
keys and defaults in internal/config.go. The extension acts on: health.enabled and
health.check_interval, observability.metrics.enabled and collection_interval,
advanced.enable_auto_snapshot with raft.snapshot_interval, and events.enabled (adds an `events`
dependency and publishes start and stop events when an event bus is present).

## Gotchas

- advanced.enable_auto_snapshot is on by default; every raft.snapshot_interval (30m) the snapshot
  call panics on the nil state machine and takes the process down. Set it to false if you add
  the extension.

## Not implemented yet

- The extension's component wiring (storage, transport, discovery, state machine, Raft node).
- The admin API under `admin_api`: turning it on only writes a log line.
- Applying committed entries on followers.
