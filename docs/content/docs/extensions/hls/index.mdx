## Overview

`github.com/xraph/forge/extensions/hls` adds an HTTP Live Streaming API to your Forge app. You create a stream with one variant per transcode profile, push MPEG-TS segments you've already encoded, and players read master and media M3U8 playlists with a sliding DVR window. Segments and playlists live in a [Trove](https://github.com/xraph/trove) object store, so they can sit on local disk, S3, GCS or Azure.

<Callout type="warn">
Parts of this extension aren't finished. Segment URLs return 404 today, VOD doesn't produce output, and stream records live only in memory. Read [Status](#status) before you put a player in front of it.
</Callout>

## What it registers

| Service | How you resolve it | Type |
|---|---|---|
| HLS manager | `forge.Inject[hls.HLS](container)`, alias `hls` (`hls.ServiceKey`) | `hls.HLS`, backed by `*hls.Manager` |

It also mounts the [HTTP endpoints](#http-endpoints) below under `BasePath` (`/hls` by default) while it registers.

## Dependencies

HLS needs a `*trove.Trove` in the container and resolves it while it registers: the unnamed one by default, or a named one when you set `WithStorageBackend("name")`. You can provide it yourself with `forge.ProvideValue`, as the quick start does, or let Trove's own Forge extension provide it. If you use the extension, list it before HLS in `Extensions`, because HLS doesn't declare the dependency. The bucket (`hls` by default) is created when the extension starts.

The `consensus` extension is optional. You need it only when you turn on `WithDistributed(true)`, and registration fails without it then.

## Quick start

```bash
go get github.com/xraph/forge@latest
go get github.com/xraph/forge/extensions/hls@latest
go get github.com/xraph/trove@latest
```

```go title="main.go"
package main

import (
	"context"
	"log"

	"github.com/xraph/forge"
	"github.com/xraph/forge/extensions/hls"
	"github.com/xraph/trove"
	"github.com/xraph/trove/drivers/localdriver"
)

func main() {
	app := forge.NewApp(forge.AppConfig{
		Name:        "video",
		HTTPAddress: ":8080",
		Extensions: []forge.Extension{
			hls.NewExtension(hls.WithBaseURL("http://localhost:8080/hls")),
		},
	})

	// HLS keeps playlists and segments in a Trove object store, resolved
	// from the container. Here that's a directory on local disk.
	drv := localdriver.New()
	if err := drv.Open(context.Background(), "local://./hls-data"); err != nil {
		log.Fatal(err)
	}

	store, err := trove.Open(drv)
	if err != nil {
		log.Fatal(err)
	}
	defer store.Close(context.Background())

	if err := forge.ProvideValue(app.Container(), store); err != nil {
		log.Fatal(err)
	}

	if err := app.Run(); err != nil {
		log.Fatal(err)
	}
}
```

Run it with `go mod tidy && go run .`, then drive it with curl (and `jq` to pick out the IDs):

```bash
# Create a live stream with one 720p variant.
STREAM=$(curl -s -X POST localhost:8080/hls/streams -H 'Content-Type: application/json' -d '{
  "Title": "Launch", "Type": "live", "TargetDuration": 6, "DVRWindowSize": 5,
  "TranscodeProfiles": [{"Name": "720p", "Width": 1280, "Height": 720, "Bitrate": 2800000,
    "FrameRate": 30, "VideoCodec": "h264", "AudioCodec": "aac"}]}')
ID=$(echo "$STREAM" | jq -r .ID)
VARIANT=$(echo "$STREAM" | jq -r '.Variants[0].ID')

# Go live, then push a segment. Data is the .ts file, base64 encoded.
curl -X POST localhost:8080/hls/streams/$ID/start
curl -X POST localhost:8080/hls/streams/$ID/ingest -H 'Content-Type: application/json' \
  -d "{\"VariantID\":\"$VARIANT\",\"SequenceNum\":0,\"Duration\":6.0,\"Data\":\"$(base64 < segment0.ts)\"}"

# Playlists.
curl localhost:8080/hls/$ID/master.m3u8
curl localhost:8080/hls/$ID/variants/$VARIANT/playlist.m3u8
```

The master playlist lists the variant with `BANDWIDTH=2800000,RESOLUTION=1280x720,CODECS="avc1.4d401f,mp4a.40.2"`, and the media playlist lists `segment_0.ts` with `#EXTINF:6.000`. Playlist and segment URLs are built from `BaseURL`, so set it to the address your players use. The files land under `./hls-data`.

Forge reads `config.yaml` only when `EnableConfigAutoDiscovery` is on. `forge.DefaultAppConfig()` turns it on; an `AppConfig` literal like the one above leaves it off.

## HTTP endpoints

Routes are mounted under `BasePath` (default `/hls`):

| Method | Path | Purpose |
|---|---|---|
| POST | `/streams` | Create a stream from `StreamOptions` JSON. Returns the `Stream` with its ID and variant IDs (201) |
| GET | `/streams` | `{"streams": [...], "count": n}` |
| GET | `/streams/:streamID` | One stream |
| DELETE | `/streams/:streamID` | Delete a stream and its stored files (204) |
| POST | `/streams/:streamID/start` | Mark a live or event stream active |
| POST | `/streams/:streamID/stop` | Mark it stopped |
| POST | `/streams/:streamID/ingest` | Store one `Segment`: `VariantID`, `SequenceNum`, `Duration` and base64 `Data` |
| GET | `/streams/:streamID/stats` | `StreamStats` |
| GET | `/:streamID/master.m3u8` | Master playlist |
| GET | `/:streamID/variants/:variantID/playlist.m3u8` | Media playlist |
| GET | `/:streamID/variants/:variantID/segment_:segmentNum.ts` | Meant to serve a segment, but returns 404 today. See [Status](#status) |

The request and response types have no JSON tags, so the keys are the Go field names (`Title`, `VariantID`, `SequenceNum`). Go's decoder ignores case on the way in, so `title` works, but responses use the capitalised names. A segment is accepted only while the stream is active.

None of these routes check authentication. Put the management routes behind your own middleware or gateway before you expose the app.

## Using it from Go

```go
svc, err := forge.Inject[hls.HLS](app.Container())

stream, err := svc.CreateStream(ctx, hls.StreamOptions{
	Title:             "Launch",
	Type:              hls.StreamTypeLive,
	TargetDuration:    6,
	DVRWindowSize:     5,
	TranscodeProfiles: []hls.TranscodeProfile{hls.Profile360p, hls.Profile720p},
})

err = svc.StartLiveStream(ctx, stream.ID)

err = svc.IngestSegment(ctx, stream.ID, &hls.Segment{
	VariantID:   stream.Variants[0].ID,
	SequenceNum: 0,
	Duration:    6.0,
	Data:        tsBytes,
})

master, err := svc.GetMasterPlaylist(ctx, stream.ID)
fmt.Println(master.Content)
```

Resolve the service once the extensions have registered, for example in a `forge.OnStarted` hook. Variant IDs are UUIDs generated when the stream is created, not profile names, so take them from `stream.Variants`.

A service of your own can take `hls.HLS` as a constructor parameter:

```go
type VideoService struct {
	hls hls.HLS
}

func NewVideoService(h hls.HLS) *VideoService {
	return &VideoService{hls: h}
}

func (vs *VideoService) StartLiveEvent(ctx context.Context, title string) (*hls.Stream, error) {
	stream, err := vs.hls.CreateStream(ctx, hls.StreamOptions{
		Title:             title,
		Type:              hls.StreamTypeLive,
		TargetDuration:    6,
		DVRWindowSize:     10,
		TranscodeProfiles: hls.DefaultProfiles(),
	})
	if err != nil {
		return nil, err
	}

	return stream, vs.hls.StartLiveStream(ctx, stream.ID)
}
```

`StreamOptions` doesn't fall back to the extension config. Set `TargetDuration`, `DVRWindowSize` and `TranscodeProfiles` on every stream: with a zero `DVRWindowSize` the live playlist lists no segments, and with no profiles the stream has no variants.

## Status

Segment delivery is broken. The router registers `segment_:segmentNum.ts` as a literal path, so a real segment URL such as `.../segment_0.ts` gets a 404 and players can't fetch segments. Until that's fixed, serve segments from your own handler that calls `GetSegment` (there's one in [Features](/docs/extensions/hls/features#serving-segments-yourself)), or let your CDN read them straight from the Trove bucket.

VOD doesn't produce output. `CreateVOD` only creates the stream record, `CreateVODFromFile` starts FFmpeg jobs but never segments or stores the results, and `TranscodeVideo` reads from a placeholder path.

Stream records live in memory. Metadata is written to storage, but nothing reads it back, so streams are gone after a restart even though their files remain.

Several config fields are stored and never read. The [configuration page](/docs/extensions/hls/configuration#fields-that-do-nothing-yet) lists them. With `WithDistributed(true)` the extension starts a coordinator on the consensus extension, but the routes don't redirect to a leader or stream owner.
