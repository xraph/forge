## Overview

`github.com/xraph/forge/extensions/orpc` exposes every HTTP route you register as a JSON-RPC 2.0 method on one endpoint. A call runs your real handler through the router. You also get batch requests, a method list and a generated OpenRPC 1.3.2 document. The extension registers an `*orpc.ORPCService` in the container and adds its routes in `Start()`.

This is JSON-RPC with OpenRPC. It doesn't implement the wire protocol of the TypeScript `orpc` library.

## Quick Start

```go
package main

import (
	"log"
	"net/http"

	"github.com/xraph/forge"
	"github.com/xraph/forge/extensions/orpc"
)

func main() {
	app := forge.NewApp(forge.AppConfig{
		Name:        "users",
		HTTPAddress: ":8080",
		Extensions: []forge.Extension{
			orpc.NewExtension(orpc.WithServerInfo("users", "1.0.0")),
		},
	})

	err := app.Router().GET("/users/:id", func(ctx forge.Context) error {
		return ctx.JSON(http.StatusOK, map[string]string{
			"id":   ctx.Param("id"),
			"name": "Ada",
		})
	},
		forge.WithSummary("Get a user by ID"),
		forge.WithORPCMethod("users.get"),
	)
	if err != nil {
		log.Fatal(err)
	}

	if err := app.Run(); err != nil {
		log.Fatal(err)
	}
}
```

Call the route as a method:

```bash
curl -X POST http://localhost:8080/rpc \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","method":"users.get","params":{"id":"42"},"id":1}'
# {"jsonrpc":"2.0","result":{"id":"42","name":"Ada"},"id":1}

curl http://localhost:8080/rpc/methods
curl http://localhost:8080/rpc/schema
```

The extension reads the router's routes when it starts, so register your routes before `app.Run()`. A route added after that doesn't become a method.

<Callout type="warn">
The request the extension sends through your router is a new one. None of the headers or cookies from the original `POST /rpc` are copied onto it, so a route that reads `Authorization` or a session cookie sees nothing, and route middleware that requires them rejects the call. You get `-32603` with `route returned status <code>`, for example 401. `WithAuth`, `WithRateLimit`, `WithRequestTimeout` and `WithSchemaCache` set config fields that nothing reads, so they don't protect or limit the endpoint either.
</Callout>

## What It Registers

| Service | DI key | Type |
|---|---|---|
| oRPC service | `orpc` | `*orpc.ORPCService` (it also implements `orpc.ORPC`) |

Routes, with the default config:

| Route | What it does |
|---|---|
| `POST /rpc` | Runs a single JSON-RPC request or a batch (a JSON array) |
| `GET /rpc/methods` | Lists method names, descriptions, tags and deprecation flags (`enable_discovery`) |
| `GET /rpc/schema` | Returns the OpenRPC document (`enable_openrpc`) |

`WithEndpoint` moves the first one, and the methods list always sits at `<endpoint>/methods`. `WithOpenRPCEndpoint` moves the schema.

## Calling Methods

`params` is a JSON object. Path parameters are top-level keys, the request body goes under `body`, and query values go under `query`:

```json
{
  "jsonrpc": "2.0",
  "method": "update.users.id",
  "params": {"id": "42", "body": {"name": "Ada Lovelace"}, "query": {"notify": true}},
  "id": 7
}
```

That becomes `PUT /users/42?notify=true` with a JSON body. The decoded JSON response goes in `result`. A handler that answers with a status of 400 or more comes back as error `-32603` with the message `route returned status <code>`, and a non-JSON response comes back as `{"status": ..., "body": ...}`. JSON-RPC errors are always sent with HTTP 200.

## Register Methods and Interceptors Yourself

You can add a method that isn't backed by a route, or wrap every call in an interceptor. A `forge.PhaseAfterStart` hook is a good place, since the extension has started by then:

```go
err := app.RegisterHookFn(forge.PhaseAfterStart, "rpc-extras", func(ctx context.Context, a forge.App) error {
	svc, err := forge.Inject[*orpc.ORPCService](a.Container())
	if err != nil {
		return err
	}

	svc.Use(func(ctx context.Context, req *orpc.Request, next orpc.MethodHandler) (any, error) {
		log.Printf("rpc %s", req.Method)

		return next(ctx, req.Params)
	})

	return svc.RegisterMethod(&orpc.Method{
		Name:        "system.ping",
		Description: "Liveness check",
		Handler: func(ctx any, params any) (any, error) {
			return map[string]string{"pong": "ok"}, nil
		},
	})
})
```

## Key Concepts

- Method names come from the verb and path by default: `GET /users/:id` is `get.users.id` and `POST /api/v1/posts` is `create.api.v1.posts`. `forge.WithORPCMethod` overrides that, and `WithMethodPrefix` prefixes every generated name.
- `exclude_patterns` defaults to `["/_/*"]`, so Forge's health, info and metrics routes stay out. `forge.WithORPCExclude()` keeps a single route out.
- The OpenRPC document reuses the request and response schemas you already give Forge for OpenAPI.
- Methods are sorted by name in the list and in the document, so you can diff the schema between builds.
