## Programmatic Configuration

Pass options to `NewExtension`:

```go
ext := mqtt.NewExtension(
	mqtt.WithBroker("tcp://broker.example.com:1883"),
	mqtt.WithClientID("my-iot-service"),
	mqtt.WithCredentials("user", os.Getenv("MQTT_PASSWORD")),
	mqtt.WithWill("devices/my-device/status", "offline", 1, true),
)
```

For fields without an option, start from `mqtt.DefaultConfig()`, change what you need and hand the struct to `WithConfig` (or `NewExtensionWithConfig`):

```go
cfg := mqtt.DefaultConfig()
cfg.Broker = "tcp://mosquitto:1883"
cfg.ClientID = "sensors-api-1"
cfg.CleanSession = false
cfg.MessageStore = "file"
cfg.StoreDirectory = "/var/lib/sensors/mqtt"

ext := mqtt.NewExtension(mqtt.WithConfig(cfg))
```

## YAML Configuration

The extension reads `extensions.mqtt` from your config file, falling back to a top-level `mqtt` key. Keys are the snake_case names from the struct's `yaml` tags. Durations take Go duration strings such as `"30s"` or `"10m"`.

```yaml title="config.yaml"
extensions:
  mqtt:
    broker: "tcp://localhost:1883"     # tcp, ssl, tls, ws or wss
    client_id: "forge-mqtt-client"
    username: ""
    password: ""
    clean_session: true
    connect_timeout: "30s"
    keep_alive: "60s"
    ping_timeout: "10s"
    max_reconnect_delay: "10m"

    # TLS
    enable_tls: false
    tls_cert_file: ""
    tls_key_file: ""
    tls_ca_file: ""
    tls_skip_verify: false

    # Reliability
    auto_reconnect: true
    resume_subs: true
    write_timeout: "30s"

    # Message handling
    message_channel_depth: 100
    order_matters: true
    message_store: "memory"            # memory or file
    store_directory: ""                # required for file

    # Last Will and Testament
    will_enabled: false
    will_topic: ""
    will_payload: ""
    will_qos: 0
    will_retained: false

    # Observability
    enable_metrics: true
    enable_logging: true
```

Defaults sit at the bottom, the file goes on top of them, and options you set in code go on top of the file. So a `broker`, `client_id` or `clean_session: false` in YAML takes effect with a plain `mqtt.NewExtension()`. A field you set in code counts when it differs from `DefaultConfig()`, so `WithCleanSession(false)` beats a file that says `clean_session: true`. Setting a field in code back to its default leaves the file's value in place.

`WithRequireConfig(true)` turns a missing `extensions.mqtt` (and `mqtt`) section into a startup error.

Validation runs when the extension registers. It needs a broker and a client ID, QoS values of 0 to 2, a `will_topic` when the will is on, `memory` or `file` for the message store, a `store_directory` for a file store, and, with TLS verification on, both `tls_cert_file` and `tls_key_file`.

## Config Reference

### `Config`

Source: `config.go`

| Field | YAML key | Type | Default | Description |
|---|---|---|---|---|
| `Broker` | `broker` | `string` | `"tcp://localhost:1883"` | Broker URL |
| `ClientID` | `client_id` | `string` | `"forge-mqtt-client"` | Client ID, unique per connection |
| `Username` | `username` | `string` | `""` | Broker username |
| `Password` | `password` | `string` | `""` | Broker password |
| `CleanSession` | `clean_session` | `bool` | `true` | Start a fresh session on every connect |
| `ConnectTimeout` | `connect_timeout` | `time.Duration` | `30s` | How long a connect waits |
| `KeepAlive` | `keep_alive` | `time.Duration` | `60s` | Keepalive interval |
| `PingTimeout` | `ping_timeout` | `time.Duration` | `10s` | Ping response timeout |
| `MaxReconnectDelay` | `max_reconnect_delay` | `time.Duration` | `10m` | Cap on the reconnect backoff |
| `EnableTLS` | `enable_tls` | `bool` | `false` | Connect over TLS |
| `TLSCertFile` | `tls_cert_file` | `string` | `""` | Client certificate |
| `TLSKeyFile` | `tls_key_file` | `string` | `""` | Client key |
| `TLSCAFile` | `tls_ca_file` | `string` | `""` | CA bundle for the broker |
| `TLSSkipVerify` | `tls_skip_verify` | `bool` | `false` | Skip broker certificate checks |
| `DefaultQoS` | `default_qos` | `byte` | `1` | Validated but not applied (see below) |
| `AutoReconnect` | `auto_reconnect` | `bool` | `true` | Reconnect after a drop |
| `ResumeSubs` | `resume_subs` | `bool` | `true` | Resend stored, unacknowledged subscribe requests on a persistent session |
| `MaxReconnectAttempts` | `max_reconnect_attempts` | `int` | `0` | Not read (see below) |
| `WriteTimeout` | `write_timeout` | `time.Duration` | `30s` | Timeout for a blocked write |
| `MessageChannelDepth` | `message_channel_depth` | `uint` | `100` | Paho's internal message buffer |
| `OrderMatters` | `order_matters` | `bool` | `true` | Deliver messages to handlers one at a time, in order |
| `MessageStore` | `message_store` | `string` | `"memory"` | `memory` or `file` |
| `StoreDirectory` | `store_directory` | `string` | `""` | Directory for the file store |
| `WillEnabled` | `will_enabled` | `bool` | `false` | Send a last will on connect |
| `WillTopic` | `will_topic` | `string` | `""` | Will topic |
| `WillPayload` | `will_payload` | `string` | `""` | Will message |
| `WillQoS` | `will_qos` | `byte` | `0` | Will QoS |
| `WillRetained` | `will_retained` | `bool` | `false` | Retain the will message |
| `EnableMetrics` | `enable_metrics` | `bool` | `true` | Record the `mqtt.*` metrics |
| `EnableTracing` | `enable_tracing` | `bool` | `true` | Deprecated, does nothing (see below) |
| `EnableLogging` | `enable_logging` | `bool` | `true` | Log connects, drops, reconnects and publishes |
| `RequireConfig` | none | `bool` | `false` | Fail when the config section is missing |

### Fields that don't do anything yet

- `default_qos` / `WithQoS`: validated (0 to 2) and stored, but nothing reads it. Pass the QoS you want on each `Publish` and `Subscribe`.
- `max_reconnect_attempts`: nothing reads it, so Paho keeps reconnecting with no limit while `auto_reconnect` is on.
- `enable_tracing` / `WithTracing`: deprecated, and the extension doesn't trace. Unlike queue, events, conduit and kafka, mqtt can't carry trace context. Paho v1.5.1 speaks MQTT 3.1.1, which has no user properties, so a message has nowhere to hold a `traceparent`. Your existing config keeps loading. Real support has to wait for an MQTT v5 client.

## Option Helpers

| Function | What it sets |
|---|---|
| `WithBroker(broker string)` | `Broker` |
| `WithClientID(clientID string)` | `ClientID` |
| `WithCredentials(username, password string)` | `Username`, `Password` |
| `WithTLS(certFile, keyFile, caFile string, skipVerify bool)` | `EnableTLS` plus the four TLS fields |
| `WithQoS(qos byte)` | `DefaultQoS` (unused) |
| `WithCleanSession(clean bool)` | `CleanSession` |
| `WithKeepAlive(duration time.Duration)` | `KeepAlive` |
| `WithAutoReconnect(enable bool)` | `AutoReconnect` |
| `WithWill(topic, payload string, qos byte, retained bool)` | `WillEnabled` plus the four will fields |
| `WithMetrics(enable bool)` | `EnableMetrics` |
| `WithTracing(enable bool)` | `EnableTracing` (deprecated, unused) |
| `WithRequireConfig(require bool)` | `RequireConfig` |
| `WithConfig(config Config)` | Replaces the whole config |
