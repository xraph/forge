## Overview

`github.com/xraph/forge/extensions/mqtt` connects your app to an MQTT broker such as Mosquitto, EMQX or HiveMQ when the app starts, and gives you one shared client for publishing and subscribing. You get QoS 0, 1 and 2, retained messages, topic wildcards, a last will message, TLS, and username and password auth. Under the hood it's the [Eclipse Paho Go client](https://github.com/eclipse/paho.mqtt.golang), which speaks MQTT 3.1 and 3.1.1, and you can reach the Paho client directly when you need to.

```bash
go get github.com/xraph/forge/extensions/mqtt@latest
go get github.com/eclipse/paho.mqtt.golang
```

## Quick Start

This app subscribes to `sensors/+/temperature`, logs every reading, and publishes the body of `POST /readings` to `sensors/demo/temperature`:

```go
package main

import (
	"context"
	"io"
	"log"
	"net/http"

	paho "github.com/eclipse/paho.mqtt.golang"
	"github.com/xraph/forge"
	"github.com/xraph/forge/extensions/mqtt"
)

func main() {
	app := forge.NewApp(forge.AppConfig{
		Name:        "sensors",
		HTTPAddress: ":8080",
		Extensions: []forge.Extension{
			mqtt.NewExtension(
				mqtt.WithBroker("tcp://localhost:1883"),
				mqtt.WithClientID("sensors-api"),
			),
		},
	})

	// The extension connects during startup, so subscribe once it's up.
	err := app.RegisterHookFn(forge.PhaseAfterStart, "subscribe-readings",
		func(ctx context.Context, a forge.App) error {
			m, err := forge.Inject[mqtt.MQTT](a.Container())
			if err != nil {
				return err
			}

			return m.Subscribe("sensors/+/temperature", 1, func(_ paho.Client, msg paho.Message) {
				log.Printf("%s: %s", msg.Topic(), msg.Payload())
			})
		})
	if err != nil {
		log.Fatal(err)
	}

	// POST a reading and it's published to sensors/demo/temperature.
	err = app.Router().POST("/readings", func(ctx forge.Context) error {
		m, err := forge.Inject[mqtt.MQTT](app.Container())
		if err != nil {
			return err
		}

		body, err := io.ReadAll(ctx.Request().Body)
		if err != nil {
			return err
		}

		if err := m.Publish("sensors/demo/temperature", 1, false, body); err != nil {
			return err
		}

		return ctx.JSON(http.StatusAccepted, map[string]string{"status": "published"})
	})
	if err != nil {
		log.Fatal(err)
	}

	if err := app.Run(); err != nil {
		log.Fatal(err)
	}
}
```

No broker yet? Mosquitto runs in Docker with one command:

```bash
docker run -d --name mosquitto -p 1883:1883 eclipse-mosquitto:2 mosquitto -c /mosquitto-no-auth.conf
```

Then `go run .` and `curl -X POST localhost:8080/readings -d '21.5'`. You'll see `sensors/demo/temperature: 21.5` in the log.

## What It Registers

| Service | How you resolve it | Type |
|---|---|---|
| MQTT service | `forge.Inject[*mqtt.MQTTService](c)`, or `forge.Resolve[*mqtt.MQTTService](c, "mqtt")` | `*mqtt.MQTTService` (has every `mqtt.MQTT` method except `GetSubscriptions`) |
| MQTT client interface | `forge.Inject[mqtt.MQTT](c)` | `mqtt.MQTT`, the client inside that same service |

The extension's `Start` resolves the service and connects, waiting up to `connect_timeout` for the broker. If the broker doesn't accept in time, the app doesn't start and `app.Run()` returns the connection error. On shutdown the client disconnects with a 250 ms quiesce period.

## Using MQTT in Your Services

Take `mqtt.MQTT` in a constructor and the container hands you the shared client:

```go
type SensorCollector struct {
	mqtt   mqtt.MQTT
	logger forge.Logger
}

func NewSensorCollector(m mqtt.MQTT, logger forge.Logger) *SensorCollector {
	return &SensorCollector{mqtt: m, logger: logger}
}

func (sc *SensorCollector) Listen() error {
	return sc.mqtt.Subscribe("sensors/#", 1, func(_ paho.Client, msg paho.Message) {
		sc.logger.Info("sensor reading",
			forge.F("topic", msg.Topic()),
			forge.F("payload", string(msg.Payload())),
		)
	})
}

func (sc *SensorCollector) SendCommand(deviceID string, cmd []byte) error {
	return sc.mqtt.Publish("commands/"+deviceID, 1, false, cmd)
}
```

Register it with the container, and call `Listen` from an after-start hook, since `Subscribe` fails until the client is connected:

```go
err := forge.ProvideConstructor(app.Container(), NewSensorCollector)
```

## Connection Callbacks

`SetOnConnectHandler`, `SetConnectionLostHandler` and `SetReconnectingHandler` are on the interface, but they don't register anything. Paho only takes these callbacks before it connects, and the extension has connected by the time you can call them, so each one just logs a warning. The extension's own callbacks keep `GetStats()` and the metrics up to date, and you can read those instead.

## Key Concepts

- QoS levels: you pass QoS 0, 1 or 2 on every `Publish` and `Subscribe`. `default_qos` is validated but nothing applies it.
- Reconnects: Paho reconnects after a drop, backing off up to `max_reconnect_delay`. There is no attempt limit; `max_reconnect_attempts` isn't read.
- Subscriptions: `+` matches one topic level and `#` everything below a level. `GetSubscriptions` lists what this client subscribed to.
- Last will: a message the broker publishes when your client disappears without a clean disconnect.
- Retained messages: the broker keeps the last retained message on a topic and hands it to every new subscriber.
- Sessions: with `clean_session` on (the default), the broker forgets your subscriptions when the connection drops, and the extension doesn't subscribe again.

## Important Runtime Notes

- The client is created by `NewMQTTService` and connects in the extension's `Start`. `Publish`, `Subscribe` and `Unsubscribe` return `not connected` until then, and during a reconnect.
- `resume_subs` is Paho's option for resending subscribe requests that were stored but not yet acknowledged. It doesn't restore your subscriptions after a clean-session reconnect. For that, turn `clean_session` off and keep the client ID stable.
- Give every instance of your service its own client ID. Two clients with the same ID keep kicking each other off the broker.
