## Pluggable Provider Model

Every authentication method is an `AuthProvider`:

```go
type AuthProvider interface {
    Name() string
    Type() SecuritySchemeType
    Authenticate(ctx context.Context, r *http.Request) (*AuthContext, error)
    OpenAPIScheme() SecurityScheme
    Middleware() forge.Middleware
}
```

A provider reads the credential from the request, hands it to a validator you write, and returns an
`*AuthContext` or an error. If you forget the validator, the provider returns
`ErrInvalidConfiguration` on every request. The six built-in providers live in `auth/providers`:

- `BearerTokenProvider` reads `Authorization: Bearer <token>` and passes the token to a
  `BearerTokenValidator`. `WithBearerFormat` sets the format shown in OpenAPI (`JWT` by default).
- `APIKeyProvider` reads the key from a header (`X-API-Key` by default), then a query parameter,
  then a cookie, and passes it to an `APIKeyValidator`.
- `BasicAuthProvider` reads `Authorization: Basic <base64>` and passes username and password to a
  `BasicAuthValidator`. Its own `Middleware` sets `WWW-Authenticate` on failure. The registry
  middleware doesn't.
- `OAuth2Provider` reads a Bearer token and passes it to an `OAuth2TokenValidator`. The flows you
  give it only feed the OpenAPI scheme.
- `OIDCProvider` reads a Bearer token and passes it to an `OIDCTokenValidator`. The discovery URL
  only feeds the OpenAPI scheme (`openIdConnectUrl`).
- `LDAPProvider` reads HTTP Basic credentials and checks them against your directory. It's
  registered under the fixed name `ldap`.

None of the token providers verify signatures, expiry or audience. That's your validator's job, with
the JWT library you trust.

```go
jwt := providers.NewBearerTokenProvider("jwt",
	providers.WithBearerFormat("JWT"),
	providers.WithBearerValidator(verifyJWT),
)
basic := providers.NewBasicAuthProvider("basic",
	providers.WithBasicAuthValidator(checkPassword),
)
oauth := providers.NewOAuth2Provider("oauth2", &auth.OAuthFlows{
	AuthorizationCode: &auth.OAuthFlow{
		AuthorizationURL: "https://id.example.com/authorize",
		TokenURL:         "https://id.example.com/token",
		Scopes:           map[string]string{"read": "Read access"},
	},
}, providers.WithOAuth2Validator(verifyJWT))

for _, p := range []auth.AuthProvider{jwt, basic, oauth} {
	if err := registry.Register(p); err != nil {
		return err
	}
}
```

If your scheme isn't covered, implement `AuthProvider` yourself. The registry only calls `Name` and
`Authenticate` on the request path, and `OpenAPIScheme` from `OpenAPISchemes()`. You only need a
real `Middleware` if you use the provider on its own, outside the registry.

## Provider Registry

Create the registry with `auth.NewRegistry` and keep a reference to it:

```go
registry := auth.NewRegistry(app.Container(), app.Logger())

// Register a provider. Duplicate names return ErrProviderExists.
err := registry.Register(providers.NewBearerTokenProvider("jwt",
	providers.WithBearerValidator(verifyJWT),
))

// Check whether a provider exists
if registry.Has("jwt") {
	// ...
}

// Get a provider by name
provider, err := registry.Get("jwt")

// List registered provider names
names := registry.List()

// Remove a provider
err = registry.Unregister("jwt")
```

Don't resolve the registry from the container. The extension registers a constructor under
`auth:registry` and `auth.Registry`, but that constructor needs a `forge.Container` from the
container, nothing provides one, and `auth.GetRegistry` returns an error.

## Rich AuthContext

On success a provider returns an `AuthContext`:

```go
type AuthContext struct {
    Subject      string         // user or service identifier
    Claims       map[string]any // provider-specific claims
    Scopes       []string
    Roles        []string
    Permissions  []string
    Metadata     map[string]any // extra data, such as the LDAP DN and groups
    Data         any            // whatever your application wants to carry
    ProviderName string         // set by the registry to the provider's registered name
}
```

Read it in a handler with `auth.GetAuthContext`:

```go
err := router.GET("/me", func(ctx forge.Context) error {
	authCtx, ok := auth.GetAuthContext(ctx)
	if !ok {
		return forge.Unauthorized("not signed in")
	}

	email, _ := authCtx.GetClaimString("email")

	return ctx.JSON(http.StatusOK, map[string]any{
		"subject": authCtx.Subject,
		"email":   email,
		"scopes":  authCtx.Scopes,
	})
}, forge.WithMiddleware(registry.Middleware("jwt")), forge.WithAuth("jwt"))
```

## Scopes, Roles and Permissions

`AuthContext` has checks for each list. All of them are safe on a nil `*AuthContext` and return
`false`, except that an empty argument list returns `true`.

| Method | True when |
|---|---|
| `HasScope(scope)` | The scope is present |
| `HasScopes(scopes...)` | Every scope is present |
| `HasRole(role)` | The role is present |
| `HasAnyRole(roles...)` | At least one role is present |
| `HasPermission(permission)` | The permission is present |
| `HasAllPermissions(permissions...)` | Every permission is present |

You rarely need them in handlers, because the registry can check for you. `MiddlewareWithScopes`
authenticates with one provider and requires scopes:

```go
// Require JWT authentication with the "admin" and "write" scopes
mw := registry.MiddlewareWithScopes("jwt", "admin", "write")
```

`MiddlewareWithRequirement` covers all three lists:

```go
deleteUser := registry.MiddlewareWithRequirement(auth.Requirement{
	Providers:   []string{"jwt"},
	Permissions: []string{"users:write", "users:delete"},
})

err := api.DELETE("/users/:id", handler,
	forge.WithMiddleware(deleteUser),
	forge.WithAllPermissions("users:write", "users:delete"),
)
```

`Requirement.Mode: "and"` makes every provider in `Providers` authenticate, as `MiddlewareAnd` does.
`MiddlewareWithRequirement` also stores the subject's roles and scopes under `auth.subject.roles`
and `auth.subject.scopes` with `ctx.Set`.

## Claim Access

- `GetClaim(key string) (any, bool)` returns the raw claim and whether it exists.
- `GetClaimString(key string) (string, bool)` returns the claim when it is a string.

```go
authCtx := auth.MustGetAuthContext(ctx)

if email, ok := authCtx.GetClaimString("email"); ok {
	fmt.Println("User email:", email)
}

if tenant, ok := authCtx.GetClaim("tenant"); ok {
	fmt.Println("Tenant:", tenant)
}
```

## Middleware Generation

The registry turns provider names into `forge.Middleware`. Attach it with `forge.WithMiddleware` on a
route, `forge.WithGroupMiddleware` on a group, or `router.Use` for everything registered on that
router.

| Method | Behaviour |
|---|---|
| `Middleware(names...)` | Tries each provider in order and uses the first that succeeds. 401 when all fail. No names means no check at all |
| `MiddlewareAnd(names...)` | Every provider must succeed. The first one's subject is kept, and later claims and scopes are merged in |
| `MiddlewareWithScopes(name, scopes...)` | One provider plus required scopes |
| `MiddlewareWithRequirement(req)` | Authenticates with `req.Providers`, then calls the authorizer |

A failed sign-in gets a plain-text `401 Unauthorized`. A failed check gets `403` with the authorizer's
error text.

```go
// Accept a JWT or an API key on every route in the group
api := router.Group("/api",
	forge.WithGroupMiddleware(registry.Middleware("jwt", "api-key")),
	forge.WithGroupAuth("jwt", "api-key"),
)

// Require both a JWT and an API key on the admin group
admin := router.Group("/admin",
	forge.WithGroupMiddleware(registry.MiddlewareAnd("jwt", "api-key")),
	forge.WithGroupAuthAnd("jwt", "api-key"),
)
```

### Route metadata doesn't enforce

`forge.WithAuth`, `forge.WithRequiredAuth`, `forge.WithAuthAnd`, `forge.WithAnyRole`,
`forge.WithAllPermissions` and the `WithGroup...` versions only record route metadata. The OpenAPI
generator turns it into `security` requirements and an `x-forge-authz` extension, and the client
generators read it too. Nothing is checked until the registry middleware is on the route, which is
why the examples on these pages set both.

## Authorization

The default authorizer does plain set membership. The subject must hold all `Scopes`, any one of the
`Roles` and all `Permissions`. A requirement with none of the three passes. There's no role
hierarchy and no wildcard matching. For real policy, swap the authorizer:

```go
type tenantAuthorizer struct{}

func (tenantAuthorizer) Name() string { return "tenant" }

func (tenantAuthorizer) Authorize(ctx context.Context, a *auth.AuthContext, req auth.Requirement) error {
	if tenant, _ := a.GetClaimString("tenant"); tenant == "" {
		return fmt.Errorf("%w: no tenant claim", auth.ErrAuthorizationFailed)
	}

	return auth.NewDefaultAuthorizer().Authorize(ctx, a, req)
}

registry.SetAuthorizer(tenantAuthorizer{})
```

Return `nil` to allow. Any error becomes a 403 with the error's text. Wrap `auth.ErrAuthorizationFailed`
or `auth.ErrInsufficientScopes` so callers can tell the cases apart with `errors.Is`.
`SetAuthorizer(nil)` is ignored, so the registry always has one.

## Context Propagation

The registry middleware stores the auth context in `forge.Context` under `"auth_context"`. What
middleware stores with `ctx.Set` reaches the handler, so `auth.GetAuthContext` works in later
middleware and in the handler alike.

```go
// In a handler or later middleware
authCtx, ok := auth.GetAuthContext(forgeCtx)

// Panics when missing. Use it only behind the registry middleware.
authCtx = auth.MustGetAuthContext(forgeCtx)
```

The registry doesn't touch the request's `context.Context`. If code downstream takes a plain
`context.Context`, copy the auth context in yourself:

```go
stdCtx := auth.WithContext(forgeCtx.Context(), authCtx)

// Later, in code that only has stdCtx
authCtx, ok := auth.FromContext(stdCtx)
```

### Credentials from protocol frames

For transports that receive a token after the HTTP handshake (a WebSocket or SSE control frame, for
example), `auth.ParseExplicitFrameCredential` parses a bare token, `Bearer <token>` or
`DPoP <token>`. Trusted transport code can mark it with `auth.WithExplicitFrameCredential`, and a
provider can check the mark with `auth.MatchesExplicitFrameCredential`. The mark stores only a
SHA-256 digest and grants no identity: your provider still validates the token.

## OpenAPI Security Schemes

Each provider describes itself with `OpenAPIScheme()`, and the registry collects them:

```go
schemes := registry.OpenAPISchemes()
// map[string]auth.SecurityScheme{
//   "jwt":     {Type: "http", Scheme: "bearer", BearerFormat: "JWT"},
//   "api-key": {Type: "apiKey", Name: "X-API-Key", In: "header"},
// }
```

The OpenAPI generator tries to read these from the container under `auth:registry`. That lookup
fails today (see [Provider Registry](#provider-registry)), so the schemes don't reach
`components.securitySchemes` on their own, even though each operation still gets its `security`
requirement from `forge.WithAuth`. Until that changes, pass them in the OpenAPI config yourself.
The providers don't need the registry to describe themselves, so you can build them before the app:

```go
apiKey := providers.NewAPIKeyProvider("api-key",
	providers.WithAPIKeyValidator(validateKey),
)

app := forge.NewApp(forge.AppConfig{
	Name: "auth-demo",
	RouterOptions: []forge.RouterOption{
		forge.WithOpenAPI(forge.OpenAPIConfig{
			Title:       "Auth demo",
			Version:     "1.0.0",
			SpecEnabled: true,
			Security: map[string]forge.SecurityScheme{
				"api-key": apiKey.OpenAPIScheme(),
			},
		}),
	},
})

registry := auth.NewRegistry(app.Container(), app.Logger())
if err := registry.Register(apiKey); err != nil {
	log.Fatal(err)
}
```

The key in `Security` has to match the provider name you use in `forge.WithAuth`.

`SecuritySchemeType` constants:

| Constant | OpenAPI type |
|---|---|
| `SecurityTypeAPIKey` | `apiKey` |
| `SecurityTypeHTTP` | `http` (bearer, basic) |
| `SecurityTypeOAuth2` | `oauth2` |
| `SecurityTypeOpenIDConnect` | `openIdConnect` |
| `SecurityTypeMutualTLS` | `mutualTLS` |

## LDAP / Active Directory Integration

The provider binds with your service account, searches with `SearchFilter` (`(uid=%s)` by default,
`(sAMAccountName=%s)` for Active Directory), then binds as the user to check the password.

- Groups: when `GroupBaseDN` is set, it searches there with `GroupFilter` (`(member=%s)` by
  default). Without `GroupBaseDN`, no groups are fetched.
- Role mapping: with an empty `RoleMapping`, every group DN is passed through. With a mapping,
  only the mapped names are kept. Either way they land in `Scopes`, not `Roles`, so check them with
  `Requirement.Scopes`. The user's DN and raw groups go in `Metadata`, and the attributes in
  `Attributes` become claims.
- Connection pool: `PoolSize` connections (10 by default) are dialled when the provider is
  created. Each one is checked with a service-account bind before reuse and replaced if that fails.
- Retries: dialling retries up to `MaxRetries` times, doubling `RetryDelay` each time.
- Result cache: successful sign-ins are cached for `CacheTTL` (5 minutes by default), keyed on
  username and password.
- TLS: on by default. The connection starts plain on `Port` (389) and upgrades with StartTLS,
  verifying the certificate and hostname with TLS 1.2 or newer. Install your directory's
  certificate authority in the host trust store. Setting `InsecureSkipVerify` to `true` makes
  `NewLDAPProvider` return an error.

`PageSize`, `EnableReferrals` and `IdleTimeout` are in `LDAPConfig` but nothing reads them yet, so
there's no paging, no referral handling and no idle eviction.

## Sentinel Errors

| Error | Meaning |
|---|---|
| `ErrProviderNotFound` | `Get` or `Unregister` with an unknown name |
| `ErrProviderExists` | `Register` with a name that's taken |
| `ErrInvalidConfiguration` | A provider without a validator, or a provider with an empty name |
| `ErrMissingCredentials` | The request had no credential the provider recognised |
| `ErrInvalidCredentials` | The credential was malformed or your validator rejected it |
| `ErrInsufficientScopes` | Returned by the default authorizer for missing scopes |
| `ErrAuthorizationFailed` | Returned by the default authorizer for missing roles or permissions |
| `ErrAuthenticationFailed` | For your validators to return |
| `ErrTokenExpired` | For your validators to return |
| `ErrTokenInvalid` | For your validators to return |
