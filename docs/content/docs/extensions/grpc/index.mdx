## Overview

`github.com/xraph/forge/extensions/grpc` runs a [grpc-go](https://github.com/grpc/grpc-go) server next to your HTTP server and ties it to the app's lifecycle. It gives you the standard gRPC health checking protocol, server reflection for tools like grpcurl, TLS and mutual TLS, keepalive and message size limits, request logging, OpenTelemetry spans and metrics, and graceful shutdown.

The server listens on its own port (`:50051` by default), separate from the Forge HTTP router.

<Callout>
Register your generated services with `WithService` or `WithServiceRegistrar`, or from another extension or a hook before `app.Start` returns. The server starts listening at the end of `app.Start` and can't take a service after that. See [registering your own services](#registering-your-own-services).
</Callout>

## What it registers

| Service | DI key | Type |
|---|---|---|
| gRPC service | `grpc` | `*grpcext.GRPCService` |
| gRPC server | by type | `grpcext.GRPC`, backed by the same server |

The server listens on the configured address once every extension and hook has had its turn, at the very end of `app.Start`. The extension's `Stop` drains it with `GracefulStop`, and stops it hard if the app's shutdown timeout runs out first.

## Quick start

```bash
go get github.com/xraph/forge@latest
go get github.com/xraph/forge/extensions/grpc@latest
```

This starts a gRPC server on port 50051 with health checks and reflection, and adds a health checker for one dependency:

```go
package main

import (
	"context"
	"log"

	"github.com/xraph/forge"
	grpcext "github.com/xraph/forge/extensions/grpc"
)

type dbCheck struct{}

func (dbCheck) Check(ctx context.Context) error {
	return nil // ping your database here
}

func main() {
	app := forge.NewApp(forge.AppConfig{
		Name:        "billing",
		HTTPAddress: ":8080",
		Extensions: []forge.Extension{
			grpcext.NewExtension(
				grpcext.WithAddress(":50051"),
				grpcext.WithReflection(true),
				grpcext.WithHealthCheck(true),
				grpcext.WithServiceRegistrar(func(app forge.App, s grpcext.GRPC) error {
					s.RegisterHealthChecker("billing.db", dbCheck{})

					return nil
				}),
			),
		},
	})

	if err := app.Run(); err != nil {
		log.Fatal(err)
	}
}
```

The package is named `grpc`, so the example imports it as `grpcext` to keep it apart from `google.golang.org/grpc`.

```bash
grpcurl -plaintext localhost:50051 list
# grpc.health.v1.Health
# grpc.reflection.v1.ServerReflection
# grpc.reflection.v1alpha.ServerReflection

grpcurl -plaintext -d '{"service":"billing.db"}' localhost:50051 grpc.health.v1.Health/Check
# { "status": "SERVING" }
```

## Registering your own services

Pass your services to the extension when you create it. `WithService` takes the generated descriptor and your implementation:

```go
grpcext.NewExtension(
	grpcext.WithAddress(":50051"),
	grpcext.WithService(&pb.Greeter_ServiceDesc, &greeter{}),
)
```

If the implementation needs something from the container, or you want an interceptor or a health checker next to it, use `WithServiceRegistrar`. Your function gets the app and the server, and the extension calls it once, while it builds the server inside `app.Start`:

```go
grpcext.WithServiceRegistrar(func(app forge.App, s grpcext.GRPC) error {
	db, err := forge.Inject[*sql.DB](app.Container())
	if err != nil {
		return err
	}

	s.AddUnaryInterceptor(authInterceptor)
	s.RegisterHealthChecker("greeter", greeterCheck{db: db})

	return s.RegisterService(&pb.Greeter_ServiceDesc, &greeter{db: db})
}),
```

A registrar that returns an error fails `app.Start` with that error wrapped. So does a service the server can't take, which comes back as `ErrInvalidService`: an implementation that doesn't satisfy the descriptor's server interface, or a service name that's already registered. The health and reflection services count when they're on. grpc-go would end the process for either one at `Start`, so the extension checks them when you register.

The registrar runs inside the constructor of the gRPC service, so it can resolve anything you provided on the container before `app.Start` and anything an earlier extension registered. Resolving `grpcext.GRPC` or `*grpcext.GRPCService` from inside it is a circular dependency. `WithConfig` replaces the whole config, registrars included, so put `WithService` and `WithServiceRegistrar` after it.

### From another extension or a hook

The server doesn't listen until the very end of `app.Start`. The extension starts it from a `PhaseAfterStart` hook with priority `math.MinInt`, so it runs after every other hook, and until then you can register from anywhere that reaches the container. An extension that lists `grpc` in its dependencies resolves the server in its `Register` or its `Start`:

```go
func (e *Extension) Register(app forge.App) error {
	if err := e.BaseExtension.Register(app); err != nil {
		return err
	}

	srv, err := forge.Inject[grpcext.GRPC](app.Container())
	if err != nil {
		return err
	}

	return srv.RegisterService(&pb.Ledger_ServiceDesc, e.ledger)
}
```

A `PhaseAfterRegister` hook works too, and so does a `PhaseAfterStart` hook at any higher priority. Once `app.Start` returns, the server is serving and `RegisterService` returns `ErrRegisterAfterStart`. The flip side is that nothing can dial the server from inside `app.Start`: an extension's `Start` or an after-start hook runs before the port is open. If the port is taken or the TLS files don't load, `app.Start` fails with the error from that last hook.

grpc-go can't add a service to a server that's already serving, which is why all of this has to happen first. Here's what each call does on either side of the server's start:

| What | Before it serves | Once it serves |
|---|---|---|
| `RegisterService` | Buffered and served | Returns `ErrRegisterAfterStart` |
| `AddUnaryInterceptor`, `AddStreamInterceptor` | Chained onto the server | Stored, never called |
| `RegisterHealthChecker` | Works | Works, checkers are looked up on each call |
| `GetServer` | `nil` | The `grpc.Server` |

Don't call a generated `pb.RegisterXxxServer` on `GetServer()`. It's `nil` until `Start`, and on a serving server grpc-go stops the process with `grpc: Server.RegisterService after Server.Serve`. Use `RegisterService(&pb.Xxx_ServiceDesc, impl)` instead.

If you'd like to own the server's start and stop yourself, `grpcext.NewGRPCServer(cfg, app.Logger(), app.Metrics())` gives you one outside the extension, and you call `Start` and `GracefulStop` on it. Create it after `forge.NewApp`, because it reads the OpenTelemetry globals `NewApp` installs when it starts.

The extension's `examples/grpc-advanced` registers a greeter, an auth interceptor and a health checker through `WithServiceRegistrar`.

## TLS and mTLS

```go
grpcext.NewExtension(
	grpcext.WithTLS("server.crt", "server.key", "ca.crt"),
	grpcext.WithClientAuth(true), // require and verify client certificates
)
```

If the certificate, key or CA file can't be loaded, the server doesn't start and `app.Start` returns `failed to load TLS credentials` with the cause. It never falls back to plaintext.

## Key concepts

- The gRPC server binds its own TCP port, independent of the Forge HTTP router.
- The `grpc.health.v1.Health` service is on by default. Register a checker per service name with `RegisterHealthChecker`.
- Reflection is on by default for `grpcurl`, `grpcui` and similar tools.
- Logging, a server span and the `rpc.server.call.duration` metric cover every call. There's no panic recovery interceptor.
- Keepalive settings also set the maximum idle time and age of a connection.
