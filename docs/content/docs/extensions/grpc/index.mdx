## Overview

`github.com/xraph/forge/extensions/grpc` runs a [grpc-go](https://github.com/grpc/grpc-go) server next to your HTTP server and ties it to the app's lifecycle. It gives you the standard gRPC health checking protocol, server reflection for tools like grpcurl, TLS and mutual TLS, keepalive and message size limits, request logging, OpenTelemetry spans and metrics, and graceful shutdown.

The server listens on its own port (`:50051` by default), separate from the Forge HTTP router.

<Callout type="warn">
The extension's own server starts inside `app.Start`, so your generated services need a server you start yourself. Read [registering your own services](#registering-your-own-services) before you plan around it.
</Callout>

## What it registers

| Service | DI key | Type |
|---|---|---|
| gRPC service | `grpc` | `*grpcext.GRPCService` |
| gRPC server | by type | `grpcext.GRPC`, backed by the same server |

The extension's `Start` starts the server on the configured address. Its `Stop` drains it with `GracefulStop` and falls back to a hard stop if that fails.

## Quick start

```bash
go get github.com/xraph/forge@latest
go get github.com/xraph/forge/extensions/grpc@latest
```

This starts a gRPC server on port 50051 with health checks and reflection, and adds a health checker for one dependency:

```go
package main

import (
	"context"
	"log"

	"github.com/xraph/forge"
	grpcext "github.com/xraph/forge/extensions/grpc"
)

type dbCheck struct{}

func (dbCheck) Check(ctx context.Context) error {
	return nil // ping your database here
}

func main() {
	app := forge.NewApp(forge.AppConfig{
		Name:        "billing",
		HTTPAddress: ":8080",
		Extensions: []forge.Extension{
			grpcext.NewExtension(
				grpcext.WithAddress(":50051"),
				grpcext.WithReflection(true),
				grpcext.WithHealthCheck(true),
			),
		},
	})

	err := app.RegisterHookFn(forge.PhaseAfterStart, "grpc-health", func(ctx context.Context, a forge.App) error {
		srv, err := forge.Inject[grpcext.GRPC](a.Container())
		if err != nil {
			return err
		}

		srv.RegisterHealthChecker("billing.db", dbCheck{})

		return nil
	})
	if err != nil {
		log.Fatal(err)
	}

	if err := app.Run(); err != nil {
		log.Fatal(err)
	}
}
```

The package is named `grpc`, so the example imports it as `grpcext` to keep it apart from `google.golang.org/grpc`.

```bash
grpcurl -plaintext localhost:50051 list
# grpc.health.v1.Health
# grpc.reflection.v1.ServerReflection
# grpc.reflection.v1alpha.ServerReflection

grpcurl -plaintext -d '{"service":"billing.db"}' localhost:50051 grpc.health.v1.Health/Check
# { "status": "SERVING" }
```

## Registering your own services

Register services, interceptors and health checkers before the server starts. grpc-go can't add a service to a server that is already serving, so the extension buffers what you register and applies it when `Start` builds the server.

| What | Before `Start` | After `Start` |
|---|---|---|
| `RegisterService` | Buffered and served | Returns `ErrRegisterAfterStart` |
| `AddUnaryInterceptor`, `AddStreamInterceptor` | Chained onto the server | Stored, never called |
| `RegisterHealthChecker` | Works | Works, checkers are looked up on each call |
| `GetServer` | `nil` | The `grpc.Server` |

Don't call a generated `pb.RegisterXxxServer` on `GetServer()`. It's `nil` until `Start`, and on a serving server grpc-go stops the process with `grpc: Server.RegisterService after Server.Serve`. Use `RegisterService(&pb.Xxx_ServiceDesc, impl)` instead.

The catch is the extension's own server. It starts inside `app.Start`, right after the extension registers, and resolving it from the container starts it too. So by the time you can reach it, it's running. For your own services, build the server, register everything and start it yourself:

```go
cfg := grpcext.DefaultConfig()
cfg.Address = ":50051"

srv := grpcext.NewGRPCServer(cfg, app.Logger(), app.Metrics())
srv.AddUnaryInterceptor(authInterceptor)

if err := srv.RegisterService(&pb.Greeter_ServiceDesc, &greeter{}); err != nil {
	return err
}

if err := srv.Start(ctx, cfg.Address); err != nil {
	return err
}
```

Create it after `forge.NewApp`, because the server reads the OpenTelemetry globals that `NewApp` installs when it starts. The extension's `examples/grpc-advanced` is this pattern end to end.

## TLS and mTLS

```go
grpcext.NewExtension(
	grpcext.WithTLS("server.crt", "server.key", "ca.crt"),
	grpcext.WithClientAuth(true), // require and verify client certificates
)
```

If the certificate or key can't be loaded, the extension logs `failed to load TLS credentials` and starts the server in plaintext. Check your logs after you turn TLS on.

## Key concepts

- The gRPC server binds its own TCP port, independent of the Forge HTTP router.
- The `grpc.health.v1.Health` service is on by default. Register a checker per service name with `RegisterHealthChecker`.
- Reflection is on by default for `grpcurl`, `grpcui` and similar tools.
- Logging, a server span and the `rpc.server.call.duration` metric cover every call. There's no panic recovery interceptor.
- Keepalive settings also set the maximum idle time and age of a connection.
