## Overview

`github.com/xraph/forge/extensions/grpc` runs a [grpc-go](https://github.com/grpc/grpc-go) server next to your HTTP server and ties it to the app's lifecycle. It gives you the standard gRPC health checking protocol, server reflection for tools like grpcurl, TLS and mutual TLS, keepalive and message size limits, request logging and metrics, and graceful shutdown.

The server listens on its own port (`:50051` by default), separate from the Forge HTTP router.

<Callout type="warn">
Registering your own generated services on the server this extension manages doesn't work reliably yet. Read [the known issue](#known-issue-registering-your-own-services) before you plan around it.
</Callout>

## What it registers

| Service | DI key | Type |
|---|---|---|
| gRPC service | `grpc` | `*grpcext.GRPCService` |
| gRPC server | by type | `grpcext.GRPC`, backed by the same server |

The extension's `Start` starts the server on the configured address. Its `Stop` drains it with `GracefulStop` and falls back to a hard stop if that fails.

## Quick start

```bash
go get github.com/xraph/forge@latest
go get github.com/xraph/forge/extensions/grpc@latest
```

This starts a gRPC server on port 50051 with health checks and reflection, and adds a health checker for one dependency:

```go
package main

import (
	"context"
	"log"

	"github.com/xraph/forge"
	grpcext "github.com/xraph/forge/extensions/grpc"
)

type dbCheck struct{}

func (dbCheck) Check(ctx context.Context) error {
	return nil // ping your database here
}

func main() {
	app := forge.NewApp(forge.AppConfig{
		Name:        "billing",
		HTTPAddress: ":8080",
		Extensions: []forge.Extension{
			grpcext.NewExtension(
				grpcext.WithAddress(":50051"),
				grpcext.WithReflection(true),
				grpcext.WithHealthCheck(true),
			),
		},
	})

	err := app.RegisterHookFn(forge.PhaseAfterStart, "grpc-health", func(ctx context.Context, a forge.App) error {
		srv, err := forge.Inject[grpcext.GRPC](a.Container())
		if err != nil {
			return err
		}

		srv.RegisterHealthChecker("billing.db", dbCheck{})

		return nil
	})
	if err != nil {
		log.Fatal(err)
	}

	if err := app.Run(); err != nil {
		log.Fatal(err)
	}
}
```

The package is named `grpc`, so the example imports it as `grpcext` to keep it apart from `google.golang.org/grpc`.

```bash
grpcurl -plaintext localhost:50051 list
# grpc.health.v1.Health
# grpc.reflection.v1.ServerReflection
# grpc.reflection.v1alpha.ServerReflection

grpcurl -plaintext -d '{"service":"billing.db"}' localhost:50051 grpc.health.v1.Health/Check
# { "status": "SERVING" }
```

## Known issue: registering your own services

There's no dependable point at which you can register a generated service (`pb.RegisterUserServiceServer`) on the managed server:

| When you register | What happens |
|---|---|
| Before the extension starts | You can't reach the server yet: it's only in the container once the extension registers, and resolving it starts it. If you call `RegisterService` on a server you built with `grpcext.NewGRPCServer` before `Start`, `Start` builds a new `grpc.Server` and your registration is dropped |
| After the extension starts | The server is already serving, and grpc-go stops the process with `grpc: Server.RegisterService after Server.Serve` |

`AddUnaryInterceptor` and `AddStreamInterceptor` have the same timing problem. Interceptors are chained when the server is built, so one you add once it's running is stored and never called.

Until that's fixed, keep your application services on a `grpc.Server` you create and start yourself (in a Forge `RunnableExtension` or a lifecycle hook), and use this extension for what works today: health checks, reflection, TLS, limits, logging and metrics on its own server.

## TLS and mTLS

```go
grpcext.NewExtension(
	grpcext.WithTLS("server.crt", "server.key", "ca.crt"),
	grpcext.WithClientAuth(true), // require and verify client certificates
)
```

If the certificate or key can't be loaded, the extension logs `failed to load TLS credentials` and starts the server in plaintext. Check your logs after you turn TLS on.

## Key concepts

- The gRPC server binds its own TCP port, independent of the Forge HTTP router.
- The `grpc.health.v1.Health` service is on by default. Register a checker per service name with `RegisterHealthChecker`.
- Reflection is on by default for `grpcurl`, `grpcui` and similar tools.
- Logging, metrics and a placeholder tracing interceptor are chained onto every call. There's no panic recovery interceptor.
- Keepalive settings also set the maximum idle time and age of a connection.
