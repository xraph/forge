## The GRPC interface

Resolve `grpcext.GRPC` from the container (or call `Server()` on `*grpcext.GRPCService`) to reach the server:

```go
type GRPC interface {
	RegisterService(desc *grpc.ServiceDesc, impl any) error
	Start(ctx context.Context, addr string) error
	Stop(ctx context.Context) error
	GracefulStop(ctx context.Context) error
	AddUnaryInterceptor(interceptor grpc.UnaryServerInterceptor)
	AddStreamInterceptor(interceptor grpc.StreamServerInterceptor)
	RegisterHealthChecker(service string, checker HealthChecker)
	GetServer() *grpc.Server
	IsRunning() bool
	GetStats() ServerStats
	GetServices() []ServiceInfo
	Ping(ctx context.Context) error
}
```

## Registering services

grpc-go supports unary, server streaming, client streaming and bidirectional streaming calls. Register your service with `RegisterService(&pb.Xxx_ServiceDesc, impl)` before `Start`: the server buffers it and serves it once it starts. After `Start` the call returns `ErrRegisterAfterStart`. `GetServer()` is `nil` until `Start`, and registering a generated service on a serving server stops the process with `grpc: Server.RegisterService after Server.Serve`.

The extension's own server starts inside `app.Start`, so build a server with `grpcext.NewGRPCServer`, register on it and start it yourself. See [registering your own services](/docs/extensions/grpc#registering-your-own-services).

## TLS and mutual TLS

```go
grpcext.NewExtension(
	grpcext.WithTLS("server.crt", "server.key", ""),
)

// Mutual TLS: require and verify client certificates against ca.crt.
grpcext.NewExtension(
	grpcext.WithTLS("server.crt", "server.key", "ca.crt"),
	grpcext.WithClientAuth(true),
)
```

Startup fails if TLS is on without a certificate and key, or client auth is on without a CA file. The CA file is only read when `client_auth` is on.

If the files are configured but can't be loaded (a wrong path, a bad PEM), the extension logs `failed to load TLS credentials` and starts the server without TLS, in plaintext. Watch for that line after you turn TLS on.

## Health checks

With `enable_health_check` on (the default), the server answers the [gRPC health checking protocol](https://github.com/grpc/grpc/blob/master/doc/health-checking.md). A checker is anything with `Check(ctx context.Context) error`:

```go
type HealthChecker interface {
	Check(ctx context.Context) error
}

srv.RegisterHealthChecker("billing.db", dbChecker{})
```

You can add a checker at any time, since checkers are looked up on each call.

| Request | Answer |
|---|---|
| `service` empty | `SERVING` |
| A service whose checker returns `nil` | `SERVING` |
| A service whose checker returns an error | `NOT_SERVING` |
| A service with no checker registered | `SERVING` |

`Watch` sends one `SERVING` message and returns, and `List` returns an empty list. Neither reflects your checkers yet.

The extension's own `Health` only reports whether it has started. It doesn't call your checkers.

## Server reflection

On by default, for `grpcurl`, `grpcui` and other reflection-aware tools:

```bash
grpcurl -plaintext localhost:50051 list
grpcurl -plaintext localhost:50051 describe grpc.health.v1.Health
```

Turn it off with `WithReflection(false)` or `enable_reflection: false`.

## Interceptors

The server chains these onto every call, in this order, when it's built:

| Interceptor | Turned on by | What it does |
|---|---|---|
| Logging | `enable_logging` | A debug line when a call starts and ends, an error line with method, duration and error when it fails |
| Metrics | `enable_metrics` | The `rpc.server.call.duration` histogram, plus the `GetStats` counters |
| Tracing | `enable_tracing` | Puts `trace_id` and `span_id` on the call's context. The span itself comes from an otelgrpc stats handler, see [Tracing](#tracing) |

There's no panic recovery interceptor, so a panic in a handler is grpc-go's to deal with.

`AddUnaryInterceptor` and `AddStreamInterceptor` append to the chain, but the chain is fixed when `Start` builds the server. Add yours before `Start`. On a server that's already running they're stored and never called.

### Tracing

With `enable_tracing` on, every served call gets an otelgrpc server span named after the method, such as `billing.Invoices/Get`. It carries the semconv v1.43 attributes `rpc.system.name` (`grpc`), `rpc.method` (the full `pkg.Service/Method`) and `rpc.response.status_code` (`OK`, `NOT_FOUND`, and so on). A `traceparent` in the incoming metadata joins the caller's trace. Health and reflection calls get no span.

Server-side error codes such as `INTERNAL` mark the span as an error. Client-error codes such as `NOT_FOUND` don't. The call's context carries `trace_id` and `span_id`, so a request-scoped logger stamps them on its lines.

The server uses the OpenTelemetry globals that `forge.New` installs, and reads them when it starts. If you already run your own otelgrpc server handler, remove it, or you get two spans per call.

### Metrics

With `enable_metrics` on, every served call is recorded in one histogram, `rpc.server.call.duration`, through the app's Forge metrics registry. Prometheus exports it as `rpc_server_call_duration_seconds`.

| Label | Value |
|---|---|
| `rpc_system_name` | `grpc` |
| `rpc_method` | `billing.Invoices/Get` |
| `rpc_response_status_code` | `OK`, `NOT_FOUND`, and so on |

The buckets run from 5ms to 10s. Health and reflection calls aren't recorded, a stream records the whole call, and a handler that returns a bare `context.Canceled` or `context.DeadlineExceeded` is recorded as `CANCELLED` or `DEADLINE_EXCEEDED`. With metrics off nothing is recorded.

```promql
# Calls per second, by method
sum by (rpc_method) (rate(rpc_server_call_duration_seconds_count[5m]))

# Failures per second, by method
sum by (rpc_method) (rate(rpc_server_call_duration_seconds_count{rpc_response_status_code!="OK"}[5m]))
```

Every old `forge_grpc_*` series is gone, and nothing is emitted under the old names:

| Old series | Now |
|---|---|
| `forge_grpc_unary_started_total`, `_succeeded_total`, `_failed_total` | `rpc_server_call_duration_seconds_count`, split by `rpc_response_status_code` |
| `forge_grpc_unary_duration_seconds` | `rpc_server_call_duration_seconds` |
| `forge_grpc_stream_succeeded_total`, `_failed_total` | `rpc_server_call_duration_seconds_count`, split by `rpc_response_status_code` |
| `forge_grpc_stream_duration_seconds` | `rpc_server_call_duration_seconds` |
| `forge_grpc_stream_active` | No replacement. `GetStats().ActiveStreams` still has it |

The status code is the canonical name (`NOT_FOUND`), not the Go spelling (`NotFound`) the old `code` label held, and `rpc_method` has no leading slash where the old `method` label had one.

### Tracing outbound calls

`ClientDialOptions()` returns dial options that put a client span on every outbound call and send the trace context on:

```go
import forgegrpc "github.com/xraph/forge/extensions/grpc"

conn, err := grpc.NewClient("billing:50051",
	append(forgegrpc.ClientDialOptions(), grpc.WithTransportCredentials(creds))...)
```

Conduit's `Services.GRPC` adds the same handler for you. Both read the OpenTelemetry globals when called, so call them after `forge.New`.

## Keepalive and connection limits

- `keepalive.time`: ping interval for idle connections. It also sets the maximum idle time, and twice it is the maximum connection age.
- `keepalive.timeout`: how long to wait for a ping ack, and the grace period after the maximum age.
- `keepalive.enforcement_policy`, `min_time`, `permit_without_stream`: what the server accepts from client pings.
- `connection_timeout`: time allowed for a new connection's handshake.

With the defaults, an idle connection closes after two hours and any connection is recycled after four.

## Message size and stream limits

```go
grpcext.NewExtension(
	grpcext.WithMaxMessageSize(16 * 1024 * 1024), // receive and send, 16 MB
	grpcext.WithMaxConcurrentStreams(100),         // per connection, 0 means no limit
)
```

## Service info and statistics

```go
for _, svc := range srv.GetServices() {
	fmt.Printf("service: %s\n", svc.Name)

	for _, m := range svc.Methods {
		fmt.Printf("  %s (client_stream=%v, server_stream=%v)\n",
			m.Name, m.IsClientStream, m.IsServerStream)
	}
}

stats := srv.GetStats()
fmt.Printf("started at %d, RPCs started: %d, failed: %d, active streams: %d\n",
	stats.StartTime, stats.RPCsStarted, stats.RPCsFailed, stats.ActiveStreams)
```

The RPC and stream counts come from the metrics interceptor, so they stay at zero with `enable_metrics` off. `TotalConnections` is never updated and is always zero.

## Sentinel errors

| Error | Returned by |
|---|---|
| `ErrNotStarted` | `Stop`, `GracefulStop` and `Ping` when the server isn't running |
| `ErrRegisterAfterStart` | `RegisterService` once the server is running |

`ErrAlreadyStarted`, `ErrServiceNotFound`, `ErrInvalidConfig`, `ErrStartFailed`, `ErrStopFailed` and `ErrHealthCheckFailed` are exported, but nothing returns them today.
