The snippets assume `rtc` is the `*webrtc.Extension` from `webrtc.New` and that the app has started. The package name `webrtc` clashes with Pion's, so if you also import `github.com/pion/webrtc/v4`, give one of them an alias.

## Call rooms

A call room pairs a streaming room with a set of server-side peer connections, one per participant. You need an ID in the options. The topology comes from the extension's config, not from the room.

```go
room, err := rtc.CreateCallRoom(ctx, "support-42", streaming.RoomOptions{
	ID:         "support-42",
	Name:       "Support call",
	MaxMembers: 4,
})

peer, err := room.JoinCall(ctx, "agent-7", &webrtc.JoinOptions{
	AudioEnabled: true,
	VideoEnabled: true,
})

err = room.MuteUser(ctx, "agent-7")
err = room.Leave(ctx, "agent-7")
err = rtc.DeleteCallRoom(ctx, "support-42")
```

- `CreateCallRoom` registers the streaming room with the streaming manager and fails if a call room with that ID already exists. `GetCallRoom(id)` returns `ErrRoomNotFound` for an unknown ID, and `GetCallRooms()` lists them all.
- `room.ID()` is prefixed with the topology (`mesh-support-42`). Use the ID you passed to `CreateCallRoom` for the extension's methods.
- `rtc.JoinCall(ctx, roomID, userID, opts)` and `rtc.LeaveCall(ctx, roomID, userID)` do the same as the room methods and also update the `webrtc.calls.*` and `webrtc.peers.active` metrics.
- A user can join a room once. A second `JoinCall` for the same user fails until they leave. `Leave` returns `ErrNotInRoom` for someone who isn't there.
- `MaxMembers` goes to the streaming room. `JoinCall` doesn't check it.
- `DeleteCallRoom` closes every peer in the room. A closed room refuses new joins.

`AudioEnabled` and `VideoEnabled` add an Opus and a VP8 send track from the server to that user's peer. Nothing writes media into those tracks, so they're silent. `MuteUser`, `UnmuteUser`, `DisableVideo` and `EnableVideo` switch those server-side tracks off and on. They don't touch what the client sends.

`GetParticipants()` returns one `Participant` per peer with `UserID` filled in, plus `Quality` in SFU rooms (see below). `JoinedAt` is the time of the call, and `DisplayName`, the audio and video flags and `ScreenSharing` stay empty. `JoinOptions.DisplayName` and `Metadata` are accepted and ignored.

`StartScreenShare`, `StopScreenShare` and `GetQuality` return `ErrNotImplemented`.

## Peer connections

`JoinCall` returns a `webrtc.PeerConnection`, an interface over a Pion `*webrtc.PeerConnection` created with your ICE servers.

```go
if err := peer.SetRemoteDescription(ctx, offer); err != nil {
	return err
}

answer, err := peer.CreateAnswer(ctx) // also sets the local description

stats, err := peer.GetStats(ctx)
log.Printf("peer %s is %s, sent %d bytes", peer.UserID(), peer.State(), stats.BytesSent)
```

`CreateOffer` and `CreateAnswer` set the local description themselves and wait up to five seconds for ICE gathering, so the SDP they return already lists the server's candidates. Don't call `SetLocalDescription` with the result afterwards. If the client trickles candidates, pass each one to `AddICECandidate`.

Set callbacks with `OnTrack`, `OnConnectionStateChange` and `OnDataChannel`. Each setter replaces the previous handler, including the logging handler the call room installs.

```go
peer.OnConnectionStateChange(func(state webrtc.ConnectionState) {
	log.Printf("peer %s is %s", peer.UserID(), state)
})

peer.OnTrack(func(track webrtc.MediaTrack, receiver *webrtc.TrackReceiver) {
	log.Printf("remote %s track %s", track.Kind(), track.ID())
})
```

`OnICECandidate` only sees candidates gathered before you call `CreateOffer` or `CreateAnswer`, because both replace Pion's candidate callback with their own gathering wait. In practice the server doesn't trickle, and the SDP carries its candidates.

The `MediaTrack` you get in `OnTrack` exposes the ID, kind and label. It doesn't give you the RTP packets, so you can't read or forward remote media through this API.

`SessionDescription` and `ICECandidate` have no JSON tags, so they marshal with Go field names (`Type`, `SDP`). Decoding is case-insensitive, which is why the quick start can bind a browser's `{type, sdp}` into a `SessionDescription`. Shape what you send back to a browser yourself, with lowercase keys.

## Data channels

A data channel the client opens arrives through `OnDataChannel`:

```go
peer.OnDataChannel(func(dc webrtc.DataChannel) {
	dc.OnOpen(func() {
		_ = dc.SendText("hello from the server")
	})

	dc.OnMessage(func(msg []byte) {
		log.Printf("%s: %s", dc.Label(), msg)
	})
})
```

`Send` writes binary messages and `SendText` text ones. The `PeerConnection` interface has no way to open a data channel from the server. `NewDataChannel(pc, label, ordered, logger)` does that, but it takes a raw Pion `*webrtc.PeerConnection`, which the interface doesn't expose.

## Signaling helpers

`rtc.GetSignalingManager()` returns a `SignalingManager` that wraps SDP and candidates in streaming messages of type `webrtc.offer`, `webrtc.answer` and `webrtc.ice_candidate` and broadcasts them to a streaming room:

```go
sig := rtc.GetSignalingManager()

err := sig.SendOffer(ctx, "support-42", "agent-7", offer)
err = sig.SendAnswer(ctx, "support-42", "agent-7", answer)
err = sig.SendICECandidate(ctx, "support-42", "agent-7", candidate)
```

The target peer ID only goes into the message metadata. Everyone connected to that streaming room receives the message, so your clients have to filter on it.

It only sends. `OnOffer`, `OnAnswer` and `OnICECandidate` store a handler that nothing ever calls, and `Start` subscribes to nothing. Call rooms do hand their peers' ICE candidates to `SendICECandidate`, but they use the prefixed room ID (`mesh-support-42`), which no streaming client is in.

### The built-in signaling WebSocket

<Callout type="warn">
`RegisterRoutes` doesn't give you working signaling yet. Use your own endpoint, over HTTP as in the quick start or over your own WebSocket handler.
</Callout>

`rtc.RegisterRoutes(router)` mounts `GET /webrtc/signal/{roomID}` as a WebSocket on the router you pass. The handler reads the user with `ctx.Get("user_id").(string)`, so mount it under a group whose middleware sets `user_id`. Values route and group middleware store with `ctx.Set` reach WebSocket handlers, so that works. Without it the type assertion panics and the connection drops.

```go
calls := app.Router().Group("/rtc")
calls.Use(func(next forge.Handler) forge.Handler {
	return func(ctx forge.Context) error {
		ctx.Set("user_id", userFromRequest(ctx)) // your auth
		return next(ctx)
	}
})

err := rtc.RegisterRoutes(calls) // ws://host/rtc/webrtc/signal/{roomID}
```

With a user set, the handler joins them to an existing room with audio and video send tracks and leaves the room when the socket closes. Every message it reads is discarded, so no SDP or candidate is ever exchanged. For a room that doesn't exist it tries to create one without an ID, which fails and closes the connection.

## Topologies

Mesh is the default. Every participant gets a peer connection to the server, and the server logs the tracks it receives without forwarding them, so participants don't hear each other through it.

`WithSFU(webrtc.SFUConfig{...})` switches to SFU rooms:

```go
rtc, err := webrtc.New(stream, webrtc.DefaultConfig(),
	webrtc.WithSFU(webrtc.SFUConfig{
		WorkerCount:      4,
		MaxBandwidthMbps: 100,
		SimulcastEnabled: true,
	}),
)
```

In an SFU room, a user who joins with `AudioEnabled` or `VideoEnabled` becomes a publisher. Anyone else becomes a subscriber and is subscribed to every track already published. Each SFU participant also gets a quality monitor built from `DefaultQualityConfig()` (your `QualityConfig` isn't used), which samples the peer every second until the context you passed to `JoinCall` ends, and fills `Participant.Quality`. Pass a long-lived context if you want it to outlive a request. The router behind them is one `SFURouter` shared by every SFU room (`rtc.GetSFURouter()`, nil in mesh mode) that keeps the publisher, subscriber and track bookkeeping: `AddPublisher`, `AddSubscriber`, `SubscribeToTrack`, `UnsubscribeFromTrack`, `AddReceiver`, `SetQuality`, `GetAvailableTracks` and `GetStats`.

<Callout type="warn">
The SFU doesn't forward RTP yet. Subscriptions are recorded, but no packets go from a publisher to its subscribers. `Leave` also doesn't remove a publisher from the shared router, so the same user ID can't publish again, in that room or any other SFU room, until you call `rtc.GetSFURouter().RemovePublisher`. The `SFUConfig` values are stored and not read.
</Callout>

## Quality monitoring and recording

The extension never creates an extension-wide monitor or recorder, so `rtc.GetQualityMonitor()` and `rtc.GetRecorder()` return nil whatever the config says. Apart from the per-participant monitors in SFU rooms, you build them yourself.

```go
monitor := webrtc.NewQualityMonitor(peer.ID(), peer, webrtc.DefaultQualityConfig(), logger, metrics)
if err := monitor.Monitor(ctx, peer); err != nil {
	return err
}
defer monitor.Stop(peer.ID())

quality, err := monitor.GetQuality(peer.ID())
// quality.Score (0-100), PacketLoss, Jitter, Latency, BitrateKbps
```

The monitor samples `peer.GetStats` every `MonitorInterval` and scores the result against your thresholds. `Monitor` watches the peer you passed to `NewQualityMonitor`, not the one you pass to `Monitor`, and `OnQualityChange` stores a handler that is never called, so poll `GetQuality`.

`NewRecorder(roomID, webrtc.DefaultRecorderConfig(), logger, metrics)` returns a `Recorder` whose `Start` opens an Ogg file for audio and an IVF file for video under `OutputDir`. Nothing in the extension writes media into it.

## Errors

The package exports sentinel errors for `errors.Is`: `ErrInvalidConfig`, `ErrNoICEServers` and `ErrInvalidBitrateRange` from config validation, `ErrRoomNotFound`, `ErrNotInRoom`, `ErrPeerNotFound`, `ErrConnectionClosed` and `ErrNotImplemented` from rooms and the extension, and `ErrInvalidCandidate` from `AddICECandidate`. `SignalingError`, `ConnectionError` and `MediaError` wrap an underlying error with the peer, room or track involved. The other declared errors, such as `ErrRoomFull`, `ErrUnauthorized` and `ErrCodecNotSupported`, aren't returned by anything yet.
