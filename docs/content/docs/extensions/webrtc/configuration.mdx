You configure the extension in code. Start from `webrtc.DefaultConfig()` and pass options to `webrtc.New`:

```go
rtc, err := webrtc.New(stream, webrtc.DefaultConfig(),
	webrtc.WithSTUNServers("stun:stun.example.com:3478"),
	webrtc.WithTURNServer(webrtc.TURNConfig{
		URLs:       []string{"turn:turn.example.com:3478"},
		Username:   "calls",
		Credential: os.Getenv("TURN_PASSWORD"),
	}),
)
```

<Callout type="warn">
The extension doesn't read your config file. It isn't built on `forge.BaseExtension` and never calls `LoadConfig`, so an `extensions.webrtc` section is ignored. If you want the values in YAML, read them yourself and build the `Config` before you call `New`.
</Callout>

Start from `DefaultConfig()` rather than `webrtc.Config{}`. An empty config has no ICE servers, so `New` fails, and an empty `Topology` makes every `CreateCallRoom` fail with "unsupported topology".

## Validation

`New` applies the options, then validates. It returns an error wrapping one of these:

| Error | When |
|---|---|
| `ErrNoICEServers` | No STUN and no TURN servers |
| `ErrInvalidConfig` | `Topology` is `TopologySFU` and `SFUConfig` is nil |
| `ErrInvalidBitrateRange` | `MediaConfig.MaxVideoBitrate` is below `MinVideoBitrate` |

## Options

| Option | Sets |
|---|---|
| `WithTopology(webrtc.Topology)` | `TopologyMesh` (default) or `TopologySFU`. `TopologyMCU` passes validation, and `CreateCallRoom` rejects it |
| `WithSFU(webrtc.SFUConfig)` | `TopologySFU` plus `SFUConfig` |
| `WithSTUNServers(servers ...string)` | Replaces the STUN list |
| `WithTURNServer(webrtc.TURNConfig)` | Adds one TURN server |
| `WithAudioCodecs(codecs ...string)`, `WithVideoCodecs(codecs ...string)` | `MediaConfig.AudioCodecs` and `VideoCodecs` |
| `WithRecording(path string)` | `RecordingEnabled` and `RecordingPath` |
| `WithQualityMonitoring(webrtc.QualityConfig)` | Replaces `QualityConfig` |

## What takes effect

| Field | Default | Used |
|---|---|---|
| `Topology` | `TopologyMesh` | Yes, picks mesh or SFU rooms |
| `STUNServers` | `stun:stun.l.google.com:19302`, `stun:stun1.l.google.com:19302` | Yes, every peer connection gets them, and `GetICEServers()` returns them |
| `TURNServers` | none | `URLs`, `Username` and `Credential` are used like the STUN list. `TLSEnabled`, `TLSCertFile` and `TLSKeyFile` are not read |
| `SFUConfig` | nil | Only checked for nil. `WorkerCount`, `MaxBandwidthMbps`, `AdaptiveBitrate`, `SimulcastEnabled`, `QualityLayers`, `RecordingEnabled` and `RecordingFormat` are not read |
| `MediaConfig` | Opus, VP8 and H264, 128 kbps audio, 150 to 2500 kbps video, 1920x1080 at 30 fps | Only the bitrate check in validation. Pion negotiates codecs with its own defaults |
| `QualityConfig` | monitoring on, 5-second interval, 5% loss, 30 ms jitter, 100 kbps | No. SFU rooms build their monitors from `DefaultQualityConfig()` instead |
| `RecordingEnabled`, `RecordingPath` | off, empty | No |
| `SignalingEnabled`, `SignalingTimeout` | on, 30 seconds | No |
| `RequireAuth`, `AllowGuests` | on, off | No. Nothing checks who joins a call, so put your own auth in front of the routes that call `JoinCall` |
| `MetricsEnabled` | off | No. Metrics go to the app's metrics whenever it has them |

`GetICEServers()` turns the STUN and TURN lists into `[]webrtc.ICEServer` with `URLs`, `Username` and `Credential`, which is what you hand to the browser's `RTCPeerConnection`. The [quick start](/docs/extensions/webrtc#quick-start) serves them from `/ice-servers`.

## TURN

The extension doesn't include a TURN server. It passes the ones you configure to Pion and returns them from `GetICEServers()`. Run your own (coturn, for example) or use a hosted one. Credentials you put in `TURNConfig` go to every client you serve them to, so prefer short-lived credentials if your TURN server supports them.
