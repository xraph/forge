## Overview

`github.com/xraph/forge/extensions/webrtc` builds on [Pion WebRTC v4](https://github.com/pion/webrtc) and the [streaming extension](/docs/extensions/streaming) to give you call rooms, server-side peer connections with SDP offer and answer handling, ICE candidates, data channels, and STUN and TURN configuration.

<Callout type="warn">
This is early software. You can create rooms and negotiate real peer connections with a browser today, but the server doesn't forward media between participants in either topology, the built-in signaling WebSocket drops every message, and screen sharing, call quality and recording aren't wired up. See [what isn't implemented yet](#not-implemented-yet) before you design a product around it.
</Callout>

```bash
go get github.com/xraph/forge/extensions/streaming
go get github.com/xraph/forge/extensions/webrtc
```

## Quick start

This creates a call room at startup and answers a browser's SDP offer over plain HTTP:

```go
package main

import (
	"context"
	"log"
	"net/http"

	"github.com/xraph/forge"
	"github.com/xraph/forge/extensions/streaming"
	"github.com/xraph/forge/extensions/webrtc"
)

func main() {
	stream := streaming.NewExtension(streaming.WithLocalBackend())

	rtc, err := webrtc.New(stream, webrtc.DefaultConfig())
	if err != nil {
		log.Fatal(err)
	}

	app := forge.NewApp(forge.AppConfig{
		Name:        "calls",
		HTTPAddress: ":8080",
		Extensions:  []forge.Extension{stream, rtc},
	})

	err = forge.OnStarted(app, "create-call", func(ctx context.Context, _ forge.App) error {
		_, err := rtc.CreateCallRoom(ctx, "standup", streaming.RoomOptions{
			ID:   "standup",
			Name: "Daily standup",
		})

		return err
	})
	if err != nil {
		log.Fatal(err)
	}

	r := app.Router()

	// STUN and TURN servers, shaped for the browser's RTCPeerConnection.
	err = r.GET("/ice-servers", func(ctx forge.Context) error {
		cfg := rtc.GetConfig()

		servers := []map[string]any{}
		for _, s := range cfg.GetICEServers() {
			servers = append(servers, map[string]any{
				"urls":       s.URLs,
				"username":   s.Username,
				"credential": s.Credential,
			})
		}

		return ctx.JSON(http.StatusOK, servers)
	})
	if err != nil {
		log.Fatal(err)
	}

	// The browser posts its offer, the server joins the call and answers.
	err = r.POST("/calls/:room/join", func(ctx forge.Context) error {
		var offer webrtc.SessionDescription
		if err := ctx.Bind(&offer); err != nil {
			return err
		}

		peer, err := rtc.JoinCall(ctx.Context(), ctx.Param("room"), ctx.Query("user"), &webrtc.JoinOptions{})
		if err != nil {
			return err
		}

		if err := peer.SetRemoteDescription(ctx.Context(), &offer); err != nil {
			return err
		}

		answer, err := peer.CreateAnswer(ctx.Context())
		if err != nil {
			return err
		}

		return ctx.JSON(http.StatusOK, map[string]string{
			"type": string(answer.Type),
			"sdp":  answer.SDP,
		})
	})
	if err != nil {
		log.Fatal(err)
	}

	if err := app.Run(); err != nil {
		log.Fatal(err)
	}
}
```

`curl http://localhost:8080/ice-servers` shows the two Google STUN servers from `DefaultConfig()`. From a page on the same origin, a browser can open a data channel to the server:

```js
const pc = new RTCPeerConnection({ iceServers: await (await fetch("/ice-servers")).json() });
pc.createDataChannel("chat");
await pc.setLocalDescription(await pc.createOffer());

// There is no trickle ICE endpoint, so send the offer once gathering is done.
await new Promise((done) => {
  if (pc.iceGatheringState === "complete") return done();
  pc.onicegatheringstatechange = () => pc.iceGatheringState === "complete" && done();
});

const res = await fetch("/calls/standup/join?user=ada", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(pc.localDescription),
});
await pc.setRemoteDescription(await res.json());
```

The server waits for its own ICE gathering (up to five seconds) before it returns the answer, so the answer already carries its candidates. Each user can join a room once. A second join with the same `user` fails until that user leaves with `rtc.LeaveCall`.

## How it fits together

`webrtc.New(stream, config, opts...)` returns an `*Extension` that you register next to the streaming extension. It lists `streaming` as a dependency, so both have to be in the same app. The extension registers nothing in the DI container. Keep the `*Extension` you created and call it directly.

- A call room (`CreateCallRoom`) registers a streaming room under the ID you give it and keeps one server-side Pion peer connection per participant.
- `JoinCall` creates that peer with your ICE servers. You exchange SDP with the client yourself, through `SetRemoteDescription`, `CreateAnswer` or `CreateOffer`.
- `Stop` closes every room. `Health` reports unhealthy until the extension has started, and whenever the streaming extension is unhealthy.

## Not implemented yet

- Media isn't forwarded. In a mesh room every participant gets a peer connection to the server, and the server only logs the tracks it receives. In an SFU room the router records publishers and tracks, but RTP forwarding is a TODO, so nobody hears anybody.
- `RegisterRoutes(router)` mounts a WebSocket at `/webrtc/signal/{roomID}`, but its read loop discards every message. See [Features](/docs/extensions/webrtc/features#the-built-in-signaling-websocket).
- `StartScreenShare`, `StopScreenShare` and `GetQuality` on a call room return `webrtc.ErrNotImplemented`.
- The extension never constructs a recorder or an extension-wide quality monitor, so `GetRecorder()` and `GetQualityMonitor()` return nil.
- The extension doesn't read your config file, and most of `Config` is stored but never read. See [Configuration](/docs/extensions/webrtc/configuration).
- `TopologyMCU` is declared, and `CreateCallRoom` rejects it.
