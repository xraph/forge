## Publish and subscribe

`bus.Subscribe(eventType, handler)` subscribes a handler on every registered broker. `Publish` saves the event to the store, then sends it to the default broker, or to every broker when `bus.default_broker` is empty:

```go
bus := events.MustGetEventBus(app.Container())

handler := events.NewTypedEventHandler("order-handler", []string{"order.placed"},
	func(ctx context.Context, event *core.Event) error {
		fmt.Printf("received %s for %s\n", event.Type, event.AggregateID)

		return nil
	})

if err := bus.Subscribe("order.placed", handler); err != nil {
	return err
}

// Save, then send to the default broker.
err := bus.Publish(ctx, core.NewEvent("order.placed", "order-123", order))

// Send to one named broker without saving, for example when relaying from an outbox.
err = bus.PublishTo(ctx, "nats", event)
```

If any destination fails, `Publish` returns an error, and a retry can deliver again to brokers that already succeeded. The event type doubles as the topic name on every broker.

Give your handlers stable names. `bus.Unsubscribe(eventType, name)` removes a handler by name, and Redis Streams builds its consumer group from the name, so the name is what lets a restarted service pick up where it stopped.

On the in-memory broker each matching handler runs in its own goroutine with a 30 second timeout. A handler error is logged and counted, and the event isn't redelivered.

## Message brokers

Every broker implements `core.MessageBroker`:

| Type | Implementation | Delivery |
|---|---|---|
| `memory` | `brokers.MemoryBroker` | In-process, lost on restart |
| `nats` | `brokers.NATSBroker` | Core NATS subjects (not JetStream), at most once |
| `redis` | `brokers.RedisBroker` | Redis Pub/Sub at most once, or Redis Streams at least once with `enable_streams: true` |

The extension builds brokers from the `brokers` list in config. To add your own, register it while the bus is stopped:

```go
if err := bus.RegisterBroker("custom", myBroker); err != nil {
	return err
}

if err := bus.SetDefaultBroker("custom"); err != nil {
	return err
}
```

`SetDefaultBroker` works while the bus is running. `RegisterBroker` and `UnregisterBroker` don't.

Before you rely on redelivery, check the broker with `core.RequireDurableBroker`. Memory, NATS and Redis Pub/Sub return `core.ErrDurableDeliveryUnavailable`. Redis Streams implements `core.DurableMessageBroker`. The [Redis delivery modes](./configuration#redis-delivery-modes) section has the details.

## Event store

The store is an append-only log with per-aggregate history and time-range queries:

```go
store := events.MustGetEventStore(app.Container())

err := store.SaveEvent(ctx, event)
err = store.SaveEvents(ctx, []*core.Event{event1, event2})

history, err := store.GetEventsByAggregate(ctx, "order-123", 0) // from version 0
placed, err := store.GetEventsByType(ctx, "order.placed", 100, 0) // limit, offset
recent, err := store.GetEventsSince(ctx, time.Now().Add(-24*time.Hour), 100, 0)
window, err := store.GetEventsInRange(ctx, start, end, 100, 0)

total, err := store.GetEventCount(ctx)
byType, err := store.GetEventCountByType(ctx, "order.placed")
```

`GetEvents(ctx, criteria)` takes a `core.EventCriteria` (types, aggregates, sources, time range, metadata, paging and sort) and returns a `*core.EventCollection`. `DeleteEvent` and `DeleteEventsByAggregate` are soft deletes.

| Backend | Implementation | Status |
|---|---|---|
| Memory | `stores.MemoryEventStore` | Built in, used when `store.type` is `memory` |
| Your own | any `core.EventStore` | Pass it with `WithEventStore` or `WithEventStoreFactory` |
| PostgreSQL | `stores.PostgresEventStore` | Doesn't implement the full `core.EventStore` interface yet, so you can't hand it to the service |
| MongoDB | `stores.MongoEventStore` | Same as PostgreSQL |

## Snapshots

A snapshot saves an aggregate's state at a version, so you replay only the events after it:

```go
snap := events.NewSnapshot("order-123", "order", currentState, 50).
	WithMetadata("reason", "periodic")

if err := store.CreateSnapshot(ctx, snap); err != nil {
	return err
}

latest, err := store.GetSnapshot(ctx, "order-123")
if err != nil {
	return err
}

newer, err := store.GetEventsByAggregate(ctx, "order-123", latest.Version+1)
```

## Interfaces without a built-in implementation

`core` defines `EventStream`, `EventProjection`, `ProjectionManager`, `TransactionalEventStore` and `EventStoreMigrator`. Nothing in the extension implements or calls them today. They're there for a store or a projection layer you write yourself, for example:

```go
type TransactionalEventStore interface {
	EventStore
	BeginTransaction(ctx context.Context) (EventStoreTransaction, error)
	ExecuteInTransaction(ctx context.Context, fn func(tx EventStoreTransaction) error) error
}
```

## Handlers

### Typed event handler

A named handler for one or more event types:

```go
handler := events.NewTypedEventHandler("audit-logger", []string{"user.created", "user.deleted"},
	func(ctx context.Context, event *core.Event) error {
		log.Printf("[AUDIT] %s: %v", event.Type, event.Data)

		return nil
	})
```

Event types match exactly. There's no wildcard such as `user.*`.

### Domain event handler

A typed handler that only accepts events whose `aggregate_type` metadata matches:

```go
handler := events.NewDomainEventHandler("order-handler", "order",
	[]string{"order.placed", "order.shipped", "order.delivered"},
	handleOrderEvent,
)

event := core.NewEvent("order.placed", "order-123", order).WithMetadata("aggregate_type", "order")
```

### Reflection event handler

```go
handler := events.NewReflectionEventHandler("payment-handler", paymentService)
```

It calls `Handle<Type>(ctx, event)` on the target, so it only fits event types that are valid Go identifiers, such as `PaymentCaptured`.

### Bare functions

`core.EventHandlerFunc(fn)` also satisfies `core.EventHandler`, but it subscribes anonymously. You can't unsubscribe it by name, and Redis Streams rejects it.

## Middleware

`WithMiddleware` wraps a typed handler (and so a domain handler) in middleware:

```go
handler.WithMiddleware(
	events.LoggingMiddleware(logger),
	events.MetricsMiddleware(metrics),
	events.ValidationMiddleware(),
)
```

| Middleware | What it does |
|---|---|
| `LoggingMiddleware(logger)` | Logs the event type, ID and aggregate before the handler, and the outcome and duration after |
| `MetricsMiddleware(metrics)` | Records `forge.events.handler_execution_time` and the `handler_success` or `handler_errors` counter |
| `ValidationMiddleware()` | Calls `event.Validate()` and rejects an event with no ID, type, aggregate ID, data or timestamp |

`ValidationMiddleware` checks the event's own fields. It doesn't look at the schema registry.

## Retry policies

```go
policy := events.NewRetryPolicy(3, 100*time.Millisecond).
	WithMaxDelay(5 * time.Second).
	WithBackoffFactor(2.0).
	WithRetryableErrors(ErrTemporary)

handler.WithRetryPolicy(policy)
```

`NewRetryPolicy(maxRetries, initialDelay)` doubles the delay on every attempt, up to five minutes unless you cap it with `WithMaxDelay`. By default it retries any error except context cancellation and deadline errors. `WithRetryableErrors` and `WithShouldRetryFunc` narrow that down. `CalculateDelay(attempt)` and `ShouldRetry(err)` are the two methods the handler calls.

## Tracing and metrics

Tracing is on by default. Every broker a publish reaches gets its own `publish {event type}` producer span, and every handler run happens inside a `process {event type}` consumer span that is a child of the producer's. One trace follows an event from the `Publish` call to each handler, across brokers and across services. A handler error or panic marks the consumer span as failed.

The bus puts the trace context into the event's `Metadata` as plain strings (`traceparent`, `tracestate` when there is one, and `baggage` when the context has any), so they survive the JSON hop through NATS and Redis. Your `*core.Event` and its map are never modified: each broker gets its own copy, which matters on the memory broker where handlers share the map. An event from an older publisher, with no `traceparent` or a malformed one, starts a fresh trace instead of failing. If a test of yours asserts the exact `Metadata` of a published event, allow for the new keys.

`messaging_system` is the broker's name, so two brokers show up as two systems. With `bus.enable_metrics` on, the same spans feed two histograms:

| Series | Measures |
|---|---|
| `messaging_client_operation_duration_seconds` | each publish to a broker |
| `messaging_process_duration_seconds` | each handler run |

Both carry `messaging_destination_name` (the event type), the operation labels and `error_type`. They replace the old `forge.events.*` publish and receive timers and counters, which are gone. The [metrics page](/docs/forge/metrics#removed-in-this-release) lists each removed series with its replacement. The error counters, `publish_failures` and `publish_broker_errors` among them, and the subscription and connection series stay.

Set `bus.enable_tracing: false` to turn the spans off. The trace context still passes through the event, so a service that doesn't trace doesn't break the trace of the services around it. See [Observability](/docs/forge/observability#messaging) for how this looks next to the other extensions.

## Event model

```go
event := core.NewEvent("order.placed", "order-123", orderData).
	WithVersion(2).
	WithSource("order-service").
	WithCorrelationID("req-abc-123").
	WithCausationID("cmd-xyz-789").
	WithMetadata("tenant", "acme-corp")

tenant := event.GetMetadataString("tenant")

clone := event.Clone()
err := event.Validate()
data, err := event.MarshalJSON()
```

`NewEvent` fills in a UUID, a UTC timestamp and version 1.

## Event filters

```go
byType := core.TypeFilter("order.placed", "order.shipped")
byAggregate := core.AggregateFilter("order-123")
bySource := core.SourceFilter("order-service")

combined := core.CombineFilters(byType, bySource) // all must match

collection, err := store.GetEvents(ctx, *core.NewEventCriteria().WithLimit(100))
if err != nil {
	return err
}

filtered := collection.Filter(combined)
filtered.SortByTimestamp(true) // ascending
```

Filters match exact values.

## Schema validation

The `schema` subpackage has a schema registry (`schema.NewSchemaRegistry`) with versioned schemas, a memory store and cache, and an `EventSchemaValidator` that checks event data against registered schemas with `JSONSchemaValidator`, `StructValidator` or `RegexValidator`. The bus doesn't call it for you. Run it in your own handler middleware or before you publish.

## Sentinel errors

The `events` package exports these sentinels, but nothing in the extension returns them today. The bus and the memory store return their own errors, so don't rely on `errors.Is` against these.

| Error | Meaning |
|---|---|
| `ErrEventNotFound` | Event ID doesn't exist in the store |
| `ErrSnapshotNotFound` | Snapshot doesn't exist |
| `ErrInvalidEvent` | Event failed validation |
| `ErrInvalidSnapshot` | Snapshot failed validation |
| `ErrBrokerNotFound` | Named broker isn't registered |
| `ErrBrokerAlreadyRegistered` | Broker name collision |
| `ErrHandlerNotFound` | Handler name isn't in the registry |
| `ErrEventBusNotStarted` | Bus operation before `Start` |
| `ErrEventStoreNotStarted` | Store operation before it's initialized |

`core.ErrDurableDeliveryUnavailable` comes from `core.RequireDurableBroker`.
