## YAML configuration

The extension reads `extensions.events` and nothing else. There's no fallback to a top-level `events` key.

```yaml title="config.yaml"
extensions:
  events:
    bus:
      default_broker: "orders"   # where Publish sends; empty means every broker

    store:
      type: "memory"             # the only built-in store; see "Store ownership" below
      database: ""               # passed to a store factory through StoreConfig
      table: "events"            # passed to a store factory through StoreConfig

    brokers:
      - name: "orders"
        type: "redis"
        enabled: true
        config:
          addresses: ["localhost:6379"]

      - name: "local"
        type: "memory"
        enabled: true

      - name: "nats"
        type: "nats"
        enabled: false
        config:
          url: "nats://localhost:4222"
```

When you replace the broker list, set `bus.default_broker` to one of your names as well. The default is `memory`, and startup fails if the default broker isn't enabled. Startup also needs at least one enabled broker, unique names among the enabled ones, and a type of `memory`, `nats` or `redis`.

### Broker `config` keys

| Type | Keys |
|---|---|
| `memory` | none |
| `nats` | `url` (default `nats://localhost:4222`), `name`, `username`, `password`, `token`, `max_reconnects`, `enable_compression` |
| `redis` | `address` or `addresses` (default `localhost:6379`), `username`, `password`, `database`, `pool_size`, `master_name` (Sentinel) |
| `redis` with `enable_streams: true` | the Redis keys plus `consumer_group`, `consumer_name`, `stream_max_len`, `stream_max_deliveries`, `stream_claim_idle`, `stream_poll_interval`, `stream_lease_duration`, `stream_ordering` |

With more than one Redis address and no `master_name`, the Pub/Sub broker uses a cluster client. Streams mode refuses Redis Cluster.

## Programmatic configuration

```go
cfg := events.DefaultConfig()
cfg.Bus.DefaultBroker = "local"
cfg.Brokers = []events.BrokerConfig{
	{Name: "local", Type: "memory", Enabled: true},
}

ext := events.NewExtensionWithConfig(cfg)
```

Start from `events.DefaultConfig()` so the fields you don't touch keep their defaults. `NewExtensionWithConfig(cfg, opts...)` is also where the store options go.

This extension doesn't use the framework's `LoadConfig`. When `extensions.events` exists in your config, it binds that section over the `Config` you passed, so a key in the file wins over the same field set in code. Keys the file leaves out keep your values.

## Config struct reference

### `Config`

| Field | YAML key | Default | Description |
|---|---|---|---|
| `Bus` | `bus` | see below | Event bus settings |
| `Store` | `store` | see below | Event store settings |
| `Brokers` | `brokers` | one `memory` broker named `memory` | Brokers to connect |
| `Metrics` | `metrics` | see below | Not read today |

### `BusConfig`

| Field | YAML key | Default | Description |
|---|---|---|---|
| `DefaultBroker` | `default_broker` | `"memory"` | Where `Publish` sends. Empty means every broker |
| `BufferSize` | `buffer_size` | `1000` | Size of an internal queue that nothing feeds today. Must not be negative |
| `WorkerCount` | `worker_count` | `10` | Idle workers on that queue. Must not be negative |
| `MaxRetries` | `max_retries` | `3` | Not read |
| `RetryDelay` | `retry_delay` | `5s` | Not read |
| `EnableMetrics` | `enable_metrics` | `true` | Not read. The bus records its metrics either way |
| `EnableTracing` | `enable_tracing` | `false` | Not read |
| `ProcessingTimeout` | `processing_timeout` | `30s` | Not read |

Retries come from a handler's `RetryPolicy` or from Redis Streams redelivery, not from the bus settings.

### `StoreConfig`

| Field | YAML key | Default | Description |
|---|---|---|---|
| `Type` | `type` | `"memory"` | `memory` is built in. Anything else needs `WithEventStore` or `WithEventStoreFactory` |
| `Database` | `database` | `""` | Handed to your store factory |
| `Table` | `table` | `"events"` | Handed to your store factory |

### `BrokerConfig`

| Field | YAML key | Description |
|---|---|---|
| `Name` | `name` | Unique broker name |
| `Type` | `type` | `memory`, `nats` or `redis` |
| `Enabled` | `enabled` | Disabled entries are skipped |
| `Priority` | `priority` | Not read |
| `Config` | `config` | Broker settings, see the table above |

### `MetricsConfig`

`enabled`, `publish_interval`, `enable_per_type` and `enable_per_handler` exist on the struct (defaults `true`, `30s`, `true`, `true`), but nothing reads them.

## Redis delivery modes

Redis Pub/Sub is ephemeral by default. Set `enable_streams: true` for durable
consumer groups on a single Redis server or Sentinel deployment. Streams mode
rejects Redis Cluster and ordering modes other than `topic`. A handler acknowledges a message by returning `nil`; after `stream_max_deliveries` attempts (5 by default) the message moves to the `<topic>:forge:dead-letter` stream.

```yaml
brokers:
  - name: market-events
    type: redis
    enabled: true
    config:
      addresses: ["localhost:6379"]
      enable_streams: true
      consumer_group: tap-events
      stream_ordering: topic
      stream_max_len: 10000
      stream_max_deliveries: 5
      stream_claim_idle: "30s"
      stream_poll_interval: "100ms"
      stream_lease_duration: "10s"
```

Before you wire a critical route, call `core.RequireDurableBroker` on the selected
`core.MessageBroker`. Memory, NATS and Redis Pub/Sub return
`core.ErrDurableDeliveryUnavailable`. Redis Streams implements the optional
`core.DurableMessageBroker` interface and reports topic ordering, one in-flight
handler, acknowledgement after handler success, pending recovery, its consumer
group namespace and replica identity.

```go
func subscribeCommitted(
    ctx context.Context,
    bus core.EventBus,
    handler core.EventHandler,
) error {
    broker, err := bus.GetBroker("market-events")
    if err != nil {
        return err
    }
    durable, err := core.RequireDurableBroker(broker)
    if err != nil {
        return err
    }
    return durable.SubscribeDurable(ctx, "market.price", handler)
}
```

`SubscribeDurable` uses its context for the subscription lifetime. Cancellation
stops delivery, cancels the in-flight handler and leaves uncommitted work pending
for recovery. After the listener exits, you can subscribe the same logical handler
again. If you use `bus.Subscribe`, the bus restores subscriptions across
its own stop and start cycle. Check the selected broker's capability before wiring it.

Pub/Sub `Subscribe` uses its context for setup. Canceling that context after setup
succeeds keeps the listener active until `Unsubscribe` or broker `Close`.

Give every logical handler a stable, non-anonymous `Name()`. The broker creates a
separate group for each name. Replicas of that handler share its name and use
unique `consumer_name` values, generated automatically when omitted. One leased
worker processes a topic for that group at a time. A handler must return success
only after its effects commit. Failed deliveries remain pending for retry; poison
messages move to a bounded dead-letter stream with the original event and error.

`stream_max_len` bounds retained messages. Publication fails when capacity cannot
be reclaimed without losing unread or pending messages. A deleted or truncated
history puts the subscription in `recovery_required`, visible in broker stats and
health checks. Stop affected effects, rebuild from your authoritative source log,
and establish a fresh delivery namespace before resuming. The broker does not
reconstruct source history itself.

Lease tokens fence acknowledgement and dead-letter writes. They cannot undo an
external effect from a handler that ignores cancellation. Use an application inbox
for database effects and stable command IDs plus reconciliation for external calls.

## Store ownership and lifecycle

The service constructs the memory store automatically. For persistent storage,
provide your own `core.EventStore` with `WithEventStore(store)` or an
`EventStoreFactory` with `WithEventStoreFactory(factory)`. An unsupported store
configuration fails startup. `stores.PostgresEventStore` and
`stores.MongoEventStore` don't implement the full interface yet, so they can't
be passed here. The service borrows an injected store and never closes
it. A factory-created store belongs to the service and is recreated on restart.

`Publish` saves before delivery. `PublishTo(ctx, brokerName, event)` only sends to
the named broker, so you can relay an already committed source event without
saving a second copy. A failed destination returns an error, including partial
fanout failures. Retrying can redeliver to destinations that already succeeded.

Startup requires at least one enabled broker and a valid default broker. Register
or remove brokers while the bus is stopped. You can change the default route while
it is running. Shutdown stops admission, cancels active operations, and drains
them before closing brokers. If the caller's deadline expires, cleanup continues,
and a new start is rejected until that cleanup finishes.

## Retrying subscription removal

When a bus unsubscribe succeeds on one broker and fails on another, you receive
the failure and can retry the same event type and handler name. The bus retries
only unfinished destinations. While removals remain pending, `HealthCheck`
returns an error and `GetStats` exposes `pending_subscription_removals`.

Successful broker shutdown completes its outstanding removals. If a broker fails
to close, the removal stays visible and restart skips restoring that handler.
This keeps already removed handlers from returning while you finish cleanup.
