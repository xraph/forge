## Overview

`github.com/xraph/forge/extensions/events` gives your app a publish and subscribe event bus, an append-only event store with snapshots, and pluggable message brokers: in-memory, NATS, Redis Pub/Sub and Redis Streams with consumer groups and a dead-letter stream. You publish domain events such as `user.created` from your handlers, and subscribers in the same process or in other services react to them.

The defaults use an in-memory broker and an in-memory store, so there's nothing else to run.

## What it registers

| Service | DI key | Type | Helper |
|---|---|---|---|
| Event service | `events` | `*events.EventService` | `events.GetEventService(c)` |
| Event bus | `eventBus` | `core.EventBus` | `events.GetEventBus(c)` |
| Event store | `eventStore` | `core.EventStore` | `events.GetEventStore(c)` |
| Handler registry | `eventHandlerRegistry` | `*core.HandlerRegistry` | `events.GetHandlerRegistry(c)` |

All four come from the one `EventService` that Vessel builds. Each helper has a `Must...` twin that panics, and `GetEventServiceFromApp(app)` saves you the `Container()` call. The extension's `Start` opens the store, connects every enabled broker and starts the bus, so if a broker can't be reached, the app doesn't start.

## Quick start

```bash
go get github.com/xraph/forge@latest
go get github.com/xraph/forge/extensions/events@latest
```

This app publishes `user.created` from `POST /users`, and a named handler picks it up:

```go
package main

import (
	"context"
	"log"
	"net/http"

	"github.com/xraph/forge"
	"github.com/xraph/forge/extensions/events"
	"github.com/xraph/forge/extensions/events/core"
)

type signup struct {
	Email string `json:"email"`
}

func main() {
	app := forge.NewApp(forge.AppConfig{
		Name:        "accounts",
		HTTPAddress: ":8080",
		Extensions: []forge.Extension{
			events.NewExtension(), // in-memory broker and store
		},
	})

	// Subscribe once the bus is running.
	err := app.RegisterHookFn(forge.PhaseAfterStart, "welcome-email",
		func(ctx context.Context, a forge.App) error {
			bus, err := events.GetEventBus(a.Container())
			if err != nil {
				return err
			}

			welcome := events.NewTypedEventHandler("welcome-email", []string{"user.created"},
				func(ctx context.Context, e *core.Event) error {
					log.Printf("send welcome email to %v (user %s)", e.Data, e.AggregateID)

					return nil
				})

			return bus.Subscribe("user.created", welcome)
		})
	if err != nil {
		log.Fatal(err)
	}

	err = app.Router().POST("/users", func(ctx forge.Context) error {
		var in signup
		if err := ctx.BindJSON(&in); err != nil {
			return err
		}

		bus, err := events.GetEventBus(app.Container())
		if err != nil {
			return err
		}

		event := core.NewEvent("user.created", "user-1", in).WithSource("accounts-api")
		if err := bus.Publish(ctx.Context(), event); err != nil {
			return err
		}

		return ctx.JSON(http.StatusCreated, map[string]string{"event_id": event.ID})
	})
	if err != nil {
		log.Fatal(err)
	}

	if err := app.Run(); err != nil {
		log.Fatal(err)
	}
}
```

`core.NewEvent` takes the event type, the aggregate ID and the data. `Publish` saves the event to the store and then sends it to the default broker, so `GetEventsByAggregate(ctx, "user-1", 0)` returns it afterwards.

## Reading history back

```go
store, err := events.GetEventStore(app.Container())
if err != nil {
	return err
}

history, err := store.GetEventsByAggregate(ctx, "order-456", 0) // from version 0
if err != nil {
	return err
}

for _, e := range history {
	fmt.Printf("v%d: %s\n", e.Version, e.Type)
}

// Snapshot the current state so you don't replay the full history next time.
err = store.CreateSnapshot(ctx, events.NewSnapshot("order-456", "order", orderState, 10))
```

## Using events in your own services

Take `*events.EventService` (or `core.EventBus`) as a constructor parameter and Vessel resolves it by type:

```go
type OrderService struct {
	bus core.EventBus
}

func NewOrderService(bus core.EventBus) *OrderService {
	return &OrderService{bus: bus}
}

func (s *OrderService) PlaceOrder(ctx context.Context, order Order, requestID string) error {
	event := core.NewEvent("order.placed", order.ID, order).
		WithSource("order-service").
		WithCorrelationID(requestID)

	return s.bus.Publish(ctx, event)
}
```

```go
err := forge.ProvideConstructor(app.Container(), NewOrderService)
```

## Key concepts

- The event bus subscribes a handler on every registered broker and publishes to the default broker, or to all of them when `bus.default_broker` is empty. `PublishTo` targets one broker by name and skips the store.
- The event store is an append-only log with per-aggregate history, time-range queries, soft deletes and snapshots. Only the in-memory store is built in. For a durable log, lend the service your own `core.EventStore`.
- The handler registry holds the bus's handlers by event type. Typed, domain and reflection handlers all take middleware and a retry policy.
- Every event carries `ID`, `Type`, `AggregateID`, `Version`, `Source`, `CorrelationID`, `CausationID` and free-form metadata.

## Runtime notes

- Only the `memory` store type is built in. `store.type` set to anything else fails startup unless you pass `WithEventStore` or `WithEventStoreFactory`.
- The `stores` package also has `PostgresEventStore` and `MongoEventStore`, but neither implements the full `core.EventStore` interface yet, so you can't hand them to the service.
- The extension reads only `extensions.events` from your config file, and that section binds over the `Config` you pass in code. See [Configuration](/docs/extensions/events/configuration).
- On the memory, NATS and Redis Pub/Sub brokers a handler error is logged and the event isn't redelivered. Give the handler a `RetryPolicy`, or use Redis Streams.
