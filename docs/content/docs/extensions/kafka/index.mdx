## Overview

`github.com/xraph/forge/extensions/kafka` puts an Apache Kafka client in your app's container. You get a sync and an async producer, partition consumers, consumer groups, topic administration, and TLS and SASL (PLAIN, SCRAM-SHA-256, SCRAM-SHA-512). It is built on [IBM Sarama](https://github.com/IBM/sarama), and you can reach the raw Sarama client, producers and consumers whenever the wrapper doesn't cover what you need.

```bash
go get github.com/xraph/forge/extensions/kafka@latest
go get github.com/IBM/sarama
```

## Quick Start

This app publishes the body of every `POST /orders` to an `orders` topic and logs each message it reads back:

```go
package main

import (
	"context"
	"io"
	"log"
	"net/http"

	"github.com/IBM/sarama"
	"github.com/xraph/forge"
	"github.com/xraph/forge/extensions/kafka"
)

func main() {
	app := forge.NewApp(forge.AppConfig{
		Name:        "orders",
		HTTPAddress: ":8080",
		Extensions: []forge.Extension{
			kafka.NewExtension(
				kafka.WithBrokers("localhost:9092"),
				kafka.WithClientID("orders"),
			),
		},
	})

	// Start reading the topic once every extension is up.
	err := app.RegisterHookFn(forge.PhaseAfterStart, "consume-orders",
		func(ctx context.Context, a forge.App) error {
			k, err := forge.Inject[*kafka.KafkaService](a.Container())
			if err != nil {
				return err
			}

			return k.Consume(ctx, []string{"orders"}, func(msg *sarama.ConsumerMessage) error {
				log.Printf("partition %d offset %d: %s", msg.Partition, msg.Offset, msg.Value)

				return nil
			})
		})
	if err != nil {
		log.Fatal(err)
	}

	// POST a body and it lands on the "orders" topic.
	err = app.Router().POST("/orders", func(ctx forge.Context) error {
		k, err := forge.Inject[*kafka.KafkaService](app.Container())
		if err != nil {
			return err
		}

		body, err := io.ReadAll(ctx.Request().Body)
		if err != nil {
			return err
		}

		if err := k.SendMessage("orders", nil, body); err != nil {
			return err
		}

		return ctx.JSON(http.StatusAccepted, map[string]string{"status": "queued"})
	})
	if err != nil {
		log.Fatal(err)
	}

	if err := app.Run(); err != nil {
		log.Fatal(err)
	}
}
```

No broker yet? Start a single-node one and create the topic:

```bash
docker run -d --name kafka -p 9092:9092 apache/kafka:latest
docker exec kafka /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 --create --topic orders
```

Then `go run .` and `curl -X POST localhost:8080/orders -d '{"id": 42}'`. The log shows the message coming back from the topic.

## What It Registers

| Service | How you resolve it | Type |
|---|---|---|
| Kafka service | `forge.Inject[*kafka.KafkaService](c)`, or `forge.Resolve[*kafka.KafkaService](c, "kafka")` | `*kafka.KafkaService`, which implements `kafka.Kafka` |

The service is built the first time something resolves it, not when the app starts. That first resolve creates the Sarama client, the producers and consumer you enabled, and pings the brokers, so it's where a connection error shows up. If you resolve it in an after-start hook, as the quick start does, that error stops `app.Run()`. When the app stops, the container closes every producer, consumer and consumer group, then the client.

## Consumer Groups

`Consume` reads partitions directly, with no group and no committed offsets. When several instances should split a topic, or a restart should continue where it stopped, join a group with your own Sarama handler and mark messages yourself:

```go
type orderHandler struct{}

func (orderHandler) Setup(sarama.ConsumerGroupSession) error   { return nil }
func (orderHandler) Cleanup(sarama.ConsumerGroupSession) error { return nil }

func (orderHandler) ConsumeClaim(s sarama.ConsumerGroupSession, c sarama.ConsumerGroupClaim) error {
	for msg := range c.Messages() {
		log.Printf("group message: %s", msg.Value)
		s.MarkMessage(msg, "")
	}

	return nil
}

err := k.JoinConsumerGroup(ctx, "order-workers", []string{"orders"}, orderHandler{})
```

The call returns once the consume loop is running in the background. One client is in one group at a time; call `k.LeaveConsumerGroup(ctx)` before you join another. The [features page](/docs/extensions/kafka/features#consumer-groups) covers what the group does and doesn't pick up from your config, including TLS and SASL.

## Using Kafka in Your Services

Depend on `*kafka.KafkaService` in a constructor and the container hands you the shared client. Store it as the `kafka.Kafka` interface if you want to swap in a fake in tests:

```go
type EventPublisher struct {
	kafka  kafka.Kafka
	logger forge.Logger
}

func NewEventPublisher(k *kafka.KafkaService, logger forge.Logger) *EventPublisher {
	return &EventPublisher{kafka: k, logger: logger}
}

func (p *EventPublisher) PublishUserEvent(userID string, data []byte) error {
	return p.kafka.SendMessage("user-events", []byte(userID), data)
}
```

Register it with the container:

```go
err := forge.ProvideConstructor(app.Container(), NewEventPublisher)
```

## Key Concepts

- Producers: `SendMessage` waits for the broker, `SendMessageAsync` queues and returns, `SendMessages` sends a batch. Compression, flush batching, retries and ack level come from config.
- Consumers: `Consume` reads every partition of a topic from the newest offset, and `ConsumePartition` reads one partition from an offset you pick. Neither commits offsets.
- Consumer groups: `JoinConsumerGroup` with a Sarama `ConsumerGroupHandler`, using the rebalance strategy, session timeout and heartbeat from config.
- Admin: create, delete, list and describe topics, list partitions, and look up offsets.
- Security: TLS with a client certificate and custom CA, and SASL PLAIN or SCRAM.

## Important Runtime Notes

- You can turn the producers and the partition consumer off independently with `WithProducer(false)` and `WithConsumer(false)`.
- Async producer errors are logged and counted in `GetStats().Errors`, never returned to you. Use `SendMessage` when the caller has to know the write landed.
- `WithIdempotent(true)` makes client creation fail today, and `consumer_group_id` is stored but unused.
- With `enable_tracing` on (the default), sends and `Consume` handlers are traced and records carry a `traceparent` header. Pass a context to the `*Context` methods to join your request's trace. See [Tracing](/docs/extensions/kafka/features#tracing).
- The [features page](/docs/extensions/kafka/features) has the details.
