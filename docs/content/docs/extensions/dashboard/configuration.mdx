## YAML Configuration

```yaml title="config.yaml"
extensions:
  dashboard:
    base_path: "/dashboard"

    # Data collection
    refresh_interval: "30s"
    history_duration: "30m"
    max_data_points: 120

    # Tracing
    trace_max_count: 200
    trace_retention: "30m"
    trace_max_spans_per_trace: 200
    trace_idle_ttl: "5m"
    trace_capture_request_body: false

    # Security
    enable_csrf: true
    enable_contract_security: true
    contract_max_body_bytes: 1048576

    # Authentication
    enable_auth: false
    login_path: "/login"
    required_roles: []

    # Export
    enable_export: true
    export_formats:
      - "json"
      - "csv"
      - "prometheus"
```

The extension loads config from `extensions.dashboard` first, falling back to `dashboard`.

## Programmatic Configuration

```go
ext := dashboard.NewExtension(
    dashboard.WithBasePath("/admin/dashboard"),
    dashboard.WithRefreshInterval(30 * time.Second),
    dashboard.WithHistoryDuration(2 * time.Hour),
    dashboard.WithEnableAuth(true),
    dashboard.WithLoginPath("/auth/login"),
    dashboard.WithRequiredRoles([]string{"admin"}),
    dashboard.WithContractMaxBodyBytes(4 << 20),
)
```

If you'd rather tune for the memory you have than set each value, `WithMemoryProfile(dashboard.MemoryProfileLow)` (or `Medium`, `High`) sets the history and trace limits together. Options after it still override it.

## Config Reference

### Server

| Field | Type | Default | Option | Description |
|---|---|---|---|---|
| `BasePath` | `string` | `"/dashboard"` | `WithBasePath()` | Prefix for every route the extension mounts |

### Data Collection

| Field | Type | Default | Option | Description |
|---|---|---|---|---|
| `RefreshInterval` | `time.Duration` | `30s` | `WithRefreshInterval()` | How often metrics and health are collected |
| `HistoryDuration` | `time.Duration` | `30m` | `WithHistoryDuration()` | How long historical data points are kept |
| `MaxDataPoints` | `int` | `120` | `WithMaxDataPoints()` | Most data points kept per series |

### Tracing

| Field | Type | Default | Option | Description |
|---|---|---|---|---|
| `TraceMaxCount` | `int` | `200` | `WithTraceMaxCount()` | Most traces kept in memory |
| `TraceRetention` | `time.Duration` | `30m` | `WithTraceRetention()` | How long a trace is kept |
| `TraceMaxSpansPerTrace` | `int` | `200` | `WithTraceMaxSpansPerTrace()` | Most spans one trace keeps, so a long-lived trace can't grow without bound |
| `TraceIdleTTL` | `time.Duration` | `5m` | `WithTraceIdleTTL()` | How long after the last dashboard request or open stream spans are still recorded. Negative records always |
| `TraceCaptureRequestBody` | `bool` | `false` | `WithTraceCaptureRequestBody()` | Keep a size-limited, redacted JSON request body on each trace |

<Callout type="warn">
Setting `TraceIdleTTL` to zero doesn't reliably turn the gate off. Under a ConfigManager a zero value is treated as unset and the default wins. Use a negative duration.
</Callout>

### Security

| Field | Type | Default | Option | Description |
|---|---|---|---|---|
| `EnableCSRF` | `bool` | `true` | `WithCSRF()` | Create the CSRF manager and serve `/api/dashboard/v1/csrf` |
| `EnableContractSecurity` | `bool` | `true` | `WithContractSecurity()` | Check CSRF tokens on commands, dedupe by idempotency key, and trace dispatches |
| `ContractMaxBodyBytes` | `int64` | `0` (1 MiB) | `WithContractMaxBodyBytes()` | Largest envelope a client may POST. Zero or less means 1 MiB, and there's no way to turn the cap off |

### Authentication

| Field | Type | Default | Option | Description |
|---|---|---|---|---|
| `EnableAuth` | `bool` | `false` | `WithEnableAuth()` | Attach the `AuthChecker` to the contract routes and make `/principal` answer 401 when nobody is signed in |
| `LoginPath` | `string` | `"/login"` | `WithLoginPath()` | Where signed-out users are sent, relative to `BasePath`. Reported by `/principal`; the dashboard serves no login page |
| `RequiredRoles` | `[]string` | none | `WithRequiredRoles()` | When set, `/principal` answers 403 for users without at least one of these roles |

Auth does nothing until something calls `SetAuthChecker`. An auth extension that implements `DashboardAuthAware` does that for you.

### Export

| Field | Type | Default | Option | Description |
|---|---|---|---|---|
| `EnableExport` | `bool` | `true` | `WithExport()` | Serve the `/export/*` routes |
| `ExportFormats` | `[]string` | `["json","csv","prometheus"]` | `WithExportFormats()` | Supported export formats |

### Internal

| Field | Type | Default | Option | Description |
|---|---|---|---|---|
| `RequireConfig` | `bool` | `false` | `WithRequireConfig()` | Fail `Register()` if the ConfigManager has no dashboard config |

## Validation Rules

The config is validated during `Register()`:

| Field | Rule |
|---|---|
| `BasePath` | Must not be empty |
| `RefreshInterval` | At least 1 second |
| `MaxDataPoints` | At least 10 |

<Callout type="warn">
If validation fails, `Register()` returns an error and the dashboard won't start.
</Callout>
