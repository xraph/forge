## Boolean flags

`IsEnabled` returns the flag's answer for the user, or `false` when the flag isn't defined anywhere. `IsEnabledWithDefault` lets you pick that fallback.

```go
svc := features.MustGet(app.Container())
user := features.NewUserContext("user-123")

if svc.IsEnabled(ctx, "new-checkout", user) {
	// show the new checkout
}

if svc.IsEnabledWithDefault(ctx, "beta-features", user, true) {
	// on unless a flag or default says otherwise
}
```

For a boolean flag, the answer comes from `Enabled`, not `Value`. A flag with `Enabled: true, Value: false` is on.

## Typed flag values

String, number and JSON flags carry their answer in `Value`:

```go
theme := svc.GetString(ctx, "theme", user, "light")
maxUpload := svc.GetInt(ctx, "max-upload-size-mb", user, 10)
discount := svc.GetFloat(ctx, "discount-rate", user, 0.0)
layout := svc.GetJSON(ctx, "checkout-config", user, map[string]any{
	"steps":   3,
	"showTax": true,
})
```

Types match exactly. `GetInt` only returns a value stored as a Go `int`, and `GetFloat` only one stored as a `float64`. Store `50` in a flag and read it with `GetFloat` and you get your default back with no warning in the logs. The same goes for the values in `WithDefaultFlags`.

String, number and JSON flags ignore `Enabled`. A flag with `Enabled: false` still returns its `Value`.

## User context

Build a `UserContext` with what you know about the caller:

```go
user := features.NewUserContext("user-123").
	WithEmail("alice@example.com").
	WithName("Alice Smith").
	WithGroups([]string{"beta-testers", "premium"}).
	WithIP("192.168.1.100").
	WithCountry("US").
	WithAttribute("plan", "enterprise")
```

| Attribute | Set with | Rule attribute |
|---|---|---|
| User ID | `NewUserContext(id)` | `user_id` |
| Email | `WithEmail(email)` | `email` |
| Name | `WithName(name)` | `name` |
| Groups | `WithGroups(groups)` | `group` (only with `in`) |
| IP address | `WithIP(ip)` | `ip` |
| Country | `WithCountry(country)` | `country` |
| Custom | `WithAttribute(key, value)` | the key, when the value is a string |

You can also pass `nil` as the user context. Targeting and rollouts are then skipped and you get the flag's base value.

```go
if user.HasGroup("beta-testers") {
	// ...
}

plan, ok := user.GetAttribute("plan")
planStr, err := user.GetAttributeString("plan") // error when missing or not a string
```

## Targeting rules

A rule matches a user attribute against `Values`. When it matches and its `Value` has the type you asked for, that value is the answer.

```go
features.WithLocalFlags(map[string]features.FlagConfig{
	"premium-feature": {
		Key:     "premium-feature",
		Type:    "boolean",
		Enabled: false, // off unless a rule turns it on
		Targeting: []features.TargetingRule{
			{
				Attribute: "plan",
				Operator:  "in",
				Values:    []string{"premium", "enterprise"},
				Value:     true,
			},
			{
				Attribute: "email",
				Operator:  "contains",
				Values:    []string{"@company.com"},
				Value:     true,
			},
		},
	},
})
```

| Operator | True when |
|---|---|
| `equals`, `in` | The attribute equals one of `Values` |
| `not_in` | The attribute equals none of `Values` |
| `contains` | The attribute contains one of `Values` as a substring (case-sensitive) |

For `group`, only `in` works: it's true when the user is in any of the listed groups. Rules run in the order you list them, and the first one that matches with a value of the right type wins.

## Percentage rollouts

A rollout applies to boolean flags (`IsEnabled`, `IsEnabledWithDefault`):

```go
features.WithLocalFlags(map[string]features.FlagConfig{
	"new-search": {
		Key:     "new-search",
		Type:    "boolean",
		Enabled: true,
		Rollout: &features.RolloutConfig{
			Percentage: 25,
			Attribute:  "user_id", // the default when empty
		},
	},
})
```

1. The provider reads the rollout attribute: `user_id` when empty, `email`, or a custom string attribute.
2. It hashes the value with MD5 and takes the first four bytes modulo 100.
3. A user whose bucket is below `Percentage` gets `Enabled`. Everyone else gets the opposite.

A user with an empty value for that attribute is always outside. `Percentage` of `0` or less puts nobody in, and `100` or more puts everybody in. Raising the percentage only adds users, because a bucket never moves.

So `Enabled: true` with `Percentage: 25` is on for about a quarter of your users. Flip it to `Enabled: false` and that quarter gets `false` while everyone else gets `true`, which is rarely what you meant.

## Evaluation order

For a defined flag the local provider stops at the first step that gives an answer:

1. Targeting rules, in order.
2. For boolean flags with a `Rollout`, the user's bucket.
3. The flag's own value: `Enabled` for booleans, `Value` for everything else.

A flag you never defined falls back to `WithDefaultFlags`, then to the default you passed to the getter.

## Local provider

The `local` provider keeps the flags you pass to `WithLocalFlags` in memory. It needs no infrastructure, and it's the only provider that works today.

```go
features.NewExtension(
	features.WithLocalFlags(map[string]features.FlagConfig{
		"feature-a": {Key: "feature-a", Type: "boolean", Enabled: true},
		"max-items": {Key: "max-items", Type: "number", Value: 100},
	}),
)
```

The flag set is fixed once you build the extension. The underlying `providers.LocalProvider` has `UpdateFlag` and `RemoveFlag`, but the service doesn't expose its provider, so you can't reach them from an app. To change a flag, restart with new definitions.

## Providers

| `Provider` | Status |
|---|---|
| `local` | Works |
| `launchdarkly` | `WithLaunchDarkly` exists. Registration fails with "launchdarkly provider not yet available" |
| `unleash` | `WithUnleash` exists. Registration fails the same way |
| `flagsmith` | `WithFlagsmith` exists. Registration fails the same way |
| `posthog` | `WithPostHog` exists. Registration fails the same way |

The `providers` package has client code for the four remote services, but the extension doesn't call it yet. Pick one today and your app won't start.

## Caching

Not implemented. `WithCache(enabled, ttl)` sets `EnableCache` and `CacheTTL`, but nothing reads them, and every call goes straight to the provider. With the in-memory local provider that costs nothing.

## Periodic refresh

The service starts a goroutine that calls the provider's `Refresh` every `RefreshInterval` (30 seconds by default, `0` turns it off) and stops it on `Stop`. The local provider's `Refresh` does nothing, so the loop has no visible effect today. `svc.Refresh(ctx)` calls it once by hand.

## Default values

`WithDefaultFlags` gives values for keys that have no flag definition:

```go
features.WithDefaultFlags(map[string]any{
	"new-dashboard": true,
	"max-items":     100,
	"theme":         "light",
})
```

A defined flag never falls back to these. For an undefined key, the getter checks the default map first and then uses the default you passed, as long as the stored value has the matching Go type.

## Listing every flag

```go
all, err := svc.GetAllFlags(ctx, user)
```

This evaluates every flag you defined for that user. `Type` decides how: `boolean` goes through `IsEnabled`, `string` through `GetString`, `number` through `GetInt`, and anything else returns the raw `Value`. Keys that only exist in `WithDefaultFlags` aren't included.

## Health

The service's `Health(ctx)` delegates to the provider's `Health`. The local provider always reports healthy.
