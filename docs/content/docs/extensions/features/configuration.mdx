## Configure it

You can set the extension up with options on `features.NewExtension`, or under `extensions.features` (falling back to a top-level `features`) in your config file. Options you set in code win over the file and the file wins over `DefaultConfig()`, so you can keep the flag definitions in YAML and still override one setting in code. `WithRequireConfig(true)` makes a missing section an error at startup.

```yaml title="config.yaml"
extensions:
  features:
    provider: local
    refresh_interval: 1m
    default_flags:
      theme: light
    local:
      flags:
        new-dashboard:
          key: new-dashboard
          type: boolean
          enabled: true
        max-items:
          key: max-items
          type: number
          value: 50
```

Every flag type works from the file, `value` included, and so does a targeting rule's `value`. Mind how you write numbers, though. The typed getters match Go types exactly, and YAML picks the type from the literal: `50` decodes as `int`, so `GetInt` finds it and `GetFloat` returns your default, while `50.0` decodes as `float64` and only `GetFloat` finds it.

You can define the same flags in code instead. `WithLocalFlags` replaces the whole flag map, file flags included, so keep every flag in one place:

```go
ext := features.NewExtension(
	features.WithLocalFlags(map[string]features.FlagConfig{
		"new-dashboard": {Key: "new-dashboard", Type: "boolean", Enabled: true},
		"max-items":     {Key: "max-items", Type: "number", Value: 50},
	}),
	features.WithDefaultFlags(map[string]any{
		"theme": "light",
	}),
	features.WithRefreshInterval(time.Minute),
)
```

## Options

| Option | Effect |
|---|---|
| `WithLocalFlags(flags map[string]FlagConfig)` | Sets the flag definitions and selects the `local` provider |
| `WithDefaultFlags(flags map[string]any)` | Fallback values for keys with no flag definition |
| `WithEnabled(enabled bool)` | `false` skips registration entirely, and `features.Get` then returns an error |
| `WithProvider(provider string)` | Picks a provider by name. Only `local` works |
| `WithRefreshInterval(interval time.Duration)` | How often the service calls the provider's `Refresh`. `0` turns the loop off |
| `WithCache(enabled bool, ttl time.Duration)` | Sets `EnableCache` and `CacheTTL`, which nothing reads yet |
| `WithLaunchDarkly(sdkKey string)` | Selects `launchdarkly`. Registration then fails |
| `WithUnleash(url, apiToken, appName string)` | Selects `unleash`. Registration then fails |
| `WithFlagsmith(apiURL, environmentKey string)` | Selects `flagsmith`. Registration then fails |
| `WithPostHog(apiKey, host string)` | Selects `posthog`. Registration then fails |
| `WithRequireConfig(require bool)` | `true` makes `Register` fail when neither `extensions.features` nor `features` is in your config |
| `WithConfig(config Config)` | Replaces the whole config. `NewExtensionWithConfig(cfg)` does the same |

Options apply in order over `DefaultConfig()`, so a later option wins.

## `Config`

| Field | Type | Default | Description |
|---|---|---|---|
| `Enabled` | `bool` | `true` | `false` registers nothing |
| `Provider` | `string` | `"local"` | `local`, `launchdarkly`, `unleash`, `flagsmith` or `posthog`. Anything else fails registration |
| `RefreshInterval` | `time.Duration` | `30s` | Refresh loop interval, `0` for none |
| `EnableCache` | `bool` | `true` | Not read |
| `CacheTTL` | `time.Duration` | `5m` | Not read |
| `DefaultFlags` | `map[string]any` | empty | Fallbacks for undefined keys |
| `Local.Flags` | `map[string]FlagConfig` | empty | Local flag definitions |
| `LaunchDarkly`, `Unleash`, `Flagsmith`, `PostHog` | provider config structs | zero | Not used, since those providers aren't wired up |

## `FlagConfig`

| Field | Type | Description |
|---|---|---|
| `Key` | `string` | The flag key. Use the same string as the map key |
| `Name`, `Description` | `string` | For your own reference |
| `Type` | `string` | `boolean`, `string`, `number` or `json`. Decides how `GetAllFlags` evaluates the flag |
| `Enabled` | `bool` | The base answer for boolean flags. Ignored by the other getters |
| `Value` | `any` | The base answer for string, number and JSON flags |
| `Targeting` | `[]TargetingRule` | Rules checked in order |
| `Rollout` | `*RolloutConfig` | Percentage rollout for boolean flags |

## `TargetingRule`

| Field | Type | Description |
|---|---|---|
| `Attribute` | `string` | `user_id`, `email`, `name`, `ip`, `country`, `group` or a custom attribute key |
| `Operator` | `string` | `equals`, `contains`, `in` or `not_in` |
| `Values` | `[]string` | Values to compare against |
| `Value` | `any` | The answer when the rule matches. Its Go type must match the getter you call |

## `RolloutConfig`

| Field | Type | Description |
|---|---|---|
| `Percentage` | `int` | `0` to `100` |
| `Attribute` | `string` | What to hash: `user_id` when empty, `email`, or a custom string attribute |
