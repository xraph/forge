## Overview

`github.com/xraph/forge/extensions/features` gives you feature flags evaluated in process. You define boolean, string, number and JSON flags in Go, target them at users by ID, email, country, group or any custom attribute, and roll a feature out to a fixed percentage of users with stable hashing, so the same user gets the same answer on every request.

Only the `local` provider works today. LaunchDarkly, Unleash, Flagsmith and PostHog have options and config structs, but picking one makes registration fail. See [Providers](/docs/extensions/features/features#providers).

## What it registers

| Service | DI key | Type |
|---|---|---|
| Feature flags service | `features` (also `features.Service`) | `*features.Service` |

Resolve it with `features.Get(container)`, `features.GetFromApp(app)` or their `Must` versions, or take `*features.Service` as a constructor parameter. With `WithEnabled(false)` nothing is registered, and `features.Get` returns an error.

## Quick start

```bash
go get github.com/xraph/forge@latest
go get github.com/xraph/forge/extensions/features@latest
```

This app defines two flags: a checkout switch that beta users always get and a quarter of everyone else gets, and a theme string that changes for one country.

```go
package main

import (
	"log"
	"net/http"

	"github.com/xraph/forge"
	"github.com/xraph/forge/extensions/features"
)

func main() {
	app := forge.NewApp(forge.AppConfig{
		Name:        "flags-demo",
		HTTPAddress: ":8080",
		Extensions: []forge.Extension{
			features.NewExtension(
				features.WithLocalFlags(map[string]features.FlagConfig{
					"new-checkout": {
						Key:     "new-checkout",
						Type:    "boolean",
						Enabled: true,
						Targeting: []features.TargetingRule{
							{Attribute: "group", Operator: "in", Values: []string{"beta"}, Value: true},
						},
						Rollout: &features.RolloutConfig{Percentage: 25},
					},
					"checkout-theme": {
						Key:   "checkout-theme",
						Type:  "string",
						Value: "classic",
						Targeting: []features.TargetingRule{
							{Attribute: "country", Operator: "equals", Values: []string{"DE"}, Value: "compact"},
						},
					},
				}),
			),
		},
	})

	err := app.Router().GET("/checkout", func(ctx forge.Context) error {
		flags, err := features.Get(app.Container())
		if err != nil {
			return err
		}

		user := features.NewUserContext(ctx.QueryDefault("user", "anonymous")).
			WithCountry(ctx.Query("country"))
		if ctx.Query("beta") == "true" {
			user = user.WithGroups([]string{"beta"})
		}

		return ctx.JSON(http.StatusOK, map[string]any{
			"user":         user.UserID,
			"new_checkout": flags.IsEnabled(ctx.Context(), "new-checkout", user),
			"theme":        flags.GetString(ctx.Context(), "checkout-theme", user, "classic"),
		})
	})
	if err != nil {
		log.Fatal(err)
	}

	if err := app.Run(); err != nil {
		log.Fatal(err)
	}
}
```

```bash
curl "http://localhost:8080/checkout?user=alice"
# {"new_checkout":false,"theme":"classic","user":"alice"}
curl "http://localhost:8080/checkout?user=bob&beta=true&country=DE"
# {"new_checkout":true,"theme":"compact","user":"bob"}
```

Bob is in the `beta` group, so the targeting rule turns the checkout on for him, and his country picks the compact theme. Alice falls through to the 25% rollout, and her user ID hashes outside it. Ask again as Alice and you get the same answer every time.

## Using flags in your own services

```go
type DashboardHandler struct {
	flags *features.Service
}

func NewDashboardHandler(flags *features.Service) *DashboardHandler {
	return &DashboardHandler{flags: flags}
}

func (h *DashboardHandler) GetDashboard(ctx forge.Context) error {
	userID, _ := ctx.Get("user_id").(string) // set by your auth middleware
	user := features.NewUserContext(userID)

	data := map[string]any{"version": "v1"}

	if h.flags.IsEnabled(ctx.Context(), "new-dashboard", user) {
		data["version"] = "v2"
	}

	data["maxItems"] = h.flags.GetInt(ctx.Context(), "max-items", user, 50)
	data["theme"] = h.flags.GetString(ctx.Context(), "theme", user, "light")

	return ctx.JSON(http.StatusOK, data)
}
```

```go
err := forge.Provide(app.Container(), NewDashboardHandler)
```

A value your route middleware stores with `ctx.Set` reaches the handler through `ctx.Get`, so reading the user ID that way works.

## Key concepts

- Every getter takes a `*features.UserContext` and a default. An evaluation error logs a warning and returns the default, never an error.
- Targeting rules match `user_id`, `email`, `name`, `ip`, `country`, `group` or a custom string attribute with `equals`, `contains`, `in` and `not_in`. The first rule that matches and has a value of the right type wins.
- Percentage rollouts apply to boolean flags. They hash the user's ID (or another attribute) with MD5 into 100 buckets.
- For a boolean flag the base value is `Enabled`. For every other type it's `Value`.
- Flags come from `WithLocalFlags` and are fixed for the life of the process. Nothing reads `extensions.features` from your config file.
- The service runs a refresh loop every `RefreshInterval` (30 seconds by default), but the local provider's `Refresh` does nothing, so the loop has no effect today.
