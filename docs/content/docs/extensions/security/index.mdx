## Overview

`github.com/xraph/forge/extensions/security` gives your service security headers, per-IP rate limiting, CORS, CSRF protection, JWT issuing and verification, cookie sessions, API key checks, Argon2id and bcrypt password hashing, and audit logging. Each piece is a manager you can use directly or as middleware. Every feature is enabled by default, and every auto-apply switch is off, so nothing wraps your routes until you ask for it.

```bash
go get github.com/xraph/forge/extensions/security
```

## Quick start

This adds security headers and a five-requests-a-minute rate limit to every route, issues a JWT from `/token`, and protects `/me` with that token and the `admin` role:

```go
package main

import (
	"context"
	"log"
	"net/http"
	"os"
	"time"

	"github.com/xraph/forge"
	"github.com/xraph/forge/extensions/security"
)

func main() {
	sec := security.NewExtension(
		security.WithJWTSigningKey(os.Getenv("JWT_SIGNING_KEY")),
		security.WithAutoApplySecurityHeaders(true),
		security.WithRateLimitPerIP(5, time.Minute),
		security.WithAutoApplyRateLimit(true),
	)

	app := forge.NewApp(forge.AppConfig{
		Name:        "security-demo",
		HTTPAddress: ":8080",
		Extensions:  []forge.Extension{sec},
	})

	// The JWT manager exists once the extension has registered.
	err := app.RegisterHookFn(forge.PhaseAfterRegister, "routes", func(_ context.Context, app forge.App) error {
		jwt := sec.JWTManager()
		router := app.Router()

		err := router.POST("/token", func(ctx forge.Context) error {
			token, err := jwt.GenerateToken(&security.JWTClaims{
				UserID: "user-42",
				Roles:  []string{"admin"},
			})
			if err != nil {
				return err
			}

			return ctx.JSON(http.StatusOK, map[string]string{"token": token})
		})
		if err != nil {
			return err
		}

		return router.GET("/me", func(ctx forge.Context) error {
			claims, ok := security.GetJWTClaims(ctx)
			if !ok {
				return forge.Unauthorized("no token")
			}

			return ctx.JSON(http.StatusOK, map[string]any{
				"user":  claims.UserID,
				"roles": claims.Roles,
			})
		}, forge.WithMiddleware(security.JWTMiddleware(jwt), security.RequireRoles("admin")))
	})
	if err != nil {
		log.Fatal(err)
	}

	if err := app.Run(); err != nil {
		log.Fatal(err)
	}
}
```

Run it with a key, then get a token and use it:

```bash
JWT_SIGNING_KEY=a-long-random-secret-for-local-testing go run .

TOKEN=$(curl -s -X POST http://localhost:8080/token | jq -r .token)
curl -i -H "Authorization: Bearer $TOKEN" http://localhost:8080/me
# HTTP/1.1 200 OK
# X-Content-Type-Options: nosniff
# X-Frame-Options: SAMEORIGIN
# X-Ratelimit-Limit: 5
# {"roles":["admin"],"user":"user-42"}
```

A few more calls and you get `429 Rate limit exceeded` with a `Retry-After` header. The limit counts every request from your IP, including `/token` and Forge's own `/_/health`.

<Callout type="warn">
A bare `security.NewExtension()` fails to start. JWT is enabled by default with `HS256` and no key, so registration fails with "signing key is required for HMAC signing methods". Pass `WithJWTSigningKey(...)`, or `WithJWTEnabled(false)` if you don't need tokens.
</Callout>

`JWTMiddleware` stores the verified claims with `ctx.Set("jwt_claims", ...)`. `RequireRoles` reads them further down the chain and your handler reads them with `security.GetJWTClaims(ctx)`. The same goes for the session (`"session"`) and API key info (`"apikey_info"`): read them through the `forge.Context`, because none of the middleware puts them in `ctx.Context()`.

## What it registers

Each manager goes into the Vessel container under its type, with a string alias. Inject by type:

```go
jwt, err := forge.Inject[*security.JWTManager](app.Container())
```

| Type | Alias constant | Alias value | Registered when |
|---|---|---|---|
| `security.SessionStore` | `SessionStoreKey`, `SessionStoreKeyLegacy` | `security:session`, `security.SessionStore` | `Session.Enabled` |
| `*CookieManager` | `CookieManagerKey`, `CookieManagerKeyLegacy` | `security:cookie`, `security.CookieManager` | `Cookie.Enabled` |
| `*CSRFProtection` | `CSRFProtectionKey` | `security.CSRFProtection` | `CSRF.Enabled` |
| `*MemoryRateLimiter` | `RateLimiterKey` | `security.RateLimiter` | `RateLimit.Enabled` |
| `*SecurityHeadersManager` | `SecurityHeadersKey` | `security.SecurityHeadersManager` | `SecurityHeaders.Enabled` |
| `*PasswordHasher` | `PasswordHasherKey` | `security.PasswordHasher` | always |
| `*JWTManager` | `JWTManagerKey` | `security.JWTManager` | `JWT.Enabled` |
| `*CORSManager` | `CORSManagerKey` | `security.CORSManager` | `CORS.Enabled` |
| `*APIKeyManager` | `APIKeyManagerKey` | `security.APIKeyManager` | `APIKey.Enabled` |
| `*AuditLogger` | `AuditLoggerKey` | `security.AuditLogger` | `Audit.Enabled` |

The extension also has accessors that return the same instances: `sec.SessionStore()`, `sec.CookieManager()`, `sec.CSRFProtection()`, `sec.RateLimiter()`, `sec.SecurityHeadersManager()`, `sec.PasswordHasher()`, `sec.JWTManager()`, `sec.CORSManager()`, `sec.APIKeyManager()` and `sec.AuditLogger()`. They return `nil` until the extension has registered, which is why the quick start defines its routes in a `forge.PhaseAfterRegister` hook.

## Global and route middleware

The extension implements `forge.MiddlewareExtension`. Turn on a feature's auto-apply switch and Forge installs its middleware in front of every route, `/_/health` and `/_/metrics` included.

| Feature | Auto-apply option | Middleware you can use per route |
|---|---|---|
| Sessions | `WithAutoApplyMiddleware(true)` | `SessionMiddleware(opts)`, then `RequireSession(...)` or `RequireSessionSimple()` |
| CSRF | `WithAutoApplyCSRF(true)` | `CSRFMiddleware(csrf, cookieManager)` |
| Rate limiting | `WithAutoApplyRateLimit(true)` | `RateLimitMiddleware(limiter)` |
| Security headers | `WithAutoApplySecurityHeaders(true)` | `SecurityHeadersMiddleware(manager)` |
| JWT | `WithAutoApplyJWT(true)` | `JWTMiddleware(jwtManager)`, then `RequireRoles(...)` |
| CORS | `WithAutoApplyCORS(true)` | `CORSMiddleware(manager)` |
| API keys | `WithAutoApplyAPIKey(true)` | `APIKeyMiddleware(manager)`, then `RequireScopes(...)` |
| Audit | `WithAutoApplyAudit(true)` | `AuditMiddleware(auditLogger)` |

Auto-applied middleware runs in the order of that table. That order matters if you auto-apply both JWT and CORS: JWT runs first, so a browser's preflight `OPTIONS` request, which carries no token, gets a 401 before CORS can answer it. Auto-apply CORS and put `JWTMiddleware` on the routes that need it. Global middleware runs before route middleware, and what it stores with `ctx.Set` is visible to your route middleware and handler, so an auto-applied `JWTMiddleware` and a handler that calls `GetJWTClaims(ctx)` work together.

The rate limiter keys on `X-Real-IP`, then the first `X-Forwarded-For` address, then the connection address. A client can set those headers itself, so put the service behind a proxy that overwrites them before you rely on the limit.

## Not implemented yet

- `WithSessionStore("redis")` passes validation but registration fails with "redis session store not yet implemented". Sessions live in memory, so they don't survive a restart or span replicas.
- `RateLimitConfig.Store` only has the in-memory limiter behind it, and `WithRateLimitPerUser` still limits by client IP.
- The `ErrorHandler` fields on `JWTConfig`, `CSRFConfig` and `APIKeyConfig` are never called. The middleware writes a plain-text 401 or 403 itself.
- `SessionConfig.IdleTimeout`, `TrackIPAddress` and `TrackUserAgent`, and `AuditConfig.LogRequestBody`, `LogResponseBody` and `MaxBodySize` are accepted and ignored.
