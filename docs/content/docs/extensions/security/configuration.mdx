You can configure the extension with options in code, or under `extensions.security` (falling back to a top-level `security`) in your config file. Your options win over the file and the file wins over the defaults, one field at a time. A field you set in code to exactly its default value looks untouched, so the file still wins for that field.

## YAML keys

<Callout type="warn">
Only the `session` and `cookie` sections have snake_case keys. Every other section binds to the Go field names, case and all, so the JWT key is `jwt.SigningKey`. A key the binder doesn't recognise, such as `jwt.signing_key` or `rate_limit.requestsPerWindow`, is silently ignored.
</Callout>

The section names themselves follow the struct tags: `rate_limit`, `security_headers`, `password_hasher` and `api_key` are snake_case.

```yaml title="config.yaml"
extensions:
  security:
    session:
      enabled: true
      store: inmemory            # "redis" fails at registration, see below
      cookie_name: forge_session
      ttl: 24h
      auto_renew: true
      auto_apply_middleware: false
      skip_paths: ["/health", "/metrics"]

    cookie:
      enabled: true
      secure: true               # set false for local development over plain HTTP
      http_only: true
      same_site: lax             # default, lax, strict or none (none needs secure)
      path: /
      domain: ""
      max_age: 0

    jwt:
      Enabled: true
      SigningKey: change-me      # required while JWT is enabled
      SigningMethod: HS256
      TokenLookup: header:Authorization
      TokenPrefix: Bearer
      Issuer: ""
      Audience: ""
      TTL: 1h
      RefreshTTL: 168h
      SkipPaths: []
      AutoApplyMiddleware: false

    csrf:
      Enabled: true
      TokenLength: 32
      TokenLookup: header:X-CSRF-Token
      CookieName: csrf_token
      CookieSecure: true
      CookieSameSite: strict
      TTL: 12h
      SafeMethods: [GET, HEAD, OPTIONS, TRACE]
      SkipPaths: []
      AutoApplyMiddleware: false

    rate_limit:
      Enabled: true
      RequestsPerWindow: 100
      Window: 1m
      SkipPaths: ["/health", "/metrics"]
      AutoApplyMiddleware: false

    security_headers:
      Enabled: true
      XFrameOptions: SAMEORIGIN
      ContentSecurityPolicy: "default-src 'self'"
      AutoApplyMiddleware: false

    cors:
      Enabled: true
      AllowOrigins: ["https://app.example.com"]
      AllowMethods: [GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS]
      AllowHeaders: [Origin, Content-Type, Accept, Authorization]
      ExposeHeaders: []
      AllowCredentials: true
      MaxAge: 3600               # seconds
      AutoApplyMiddleware: false

    api_key:
      Enabled: true
      KeyLookup: header:X-API-Key
      KeyPrefix: ""
      AutoApplyMiddleware: false

    password_hasher:
      Algorithm: argon2id        # or bcrypt
      Argon2Memory: 65536        # KiB
      Argon2Iterations: 3
      Argon2Parallelism: 4
      BcryptCost: 12

    audit:
      Enabled: true
      Level: auth                # auth, data, admin, security or all
      ExcludePaths: ["/health", "/metrics"]
      AutoApplyMiddleware: false
```

Durations take Go duration strings (`30s`, `1h`). The function fields (`ErrorHandler`, `APIKeyConfig.Validator`, `AuditConfig.Handler`) can only be set in code.

The top-level `enabled` key has no effect from the file. The extension checks `Enabled` before it reads the file, so turn the whole extension off with `WithEnabled(false)` in code.

## Options

| Area | Options |
|---|---|
| Whole extension | `WithEnabled`, `WithConfig`, `WithRequireConfig`. `NewExtensionWithConfig(cfg)` is `NewExtension(WithConfig(cfg))` |
| Sessions | `WithSessionEnabled`, `WithSessionStore`, `WithSessionCookieName`, `WithSessionTTL`, `WithSessionIdleTimeout`, `WithSessionAutoRenew`, `WithAutoApplyMiddleware`, `WithSkipPaths`, `WithRedisAddress`, `WithRedisPassword`, `WithRedisDB` |
| Cookies | `WithCookieEnabled`, `WithCookieSecure`, `WithCookieHttpOnly`, `WithCookieSameSite`, `WithCookiePath`, `WithCookieDomain` |
| Headers | `WithSecurityHeadersEnabled`, `WithSecurityHeadersConfig`, `WithSecureHeaders`, `WithAutoApplySecurityHeaders` |
| Rate limiting | `WithRateLimitEnabled`, `WithRateLimitConfig`, `WithRateLimitPerIP`, `WithRateLimitPerUser`, `WithAutoApplyRateLimit` |
| CORS | `WithCORSEnabled`, `WithCORSConfig`, `WithCORSOrigins`, `WithCORSMethods`, `WithCORSHeaders`, `WithCORSExposeHeaders`, `WithCORSAllowCredentials`, `WithCORSMaxAge`, `WithCORSMaxAgeDuration`, `WithCORSAllowPrivateNetwork`, `WithCORSSkipPaths`, `WithAutoApplyCORS` |
| CSRF | `WithCSRFEnabled`, `WithCSRFConfig`, `WithAutoApplyCSRF` |
| JWT | `WithJWTEnabled`, `WithJWTConfig`, `WithJWTSigningKey`, `WithAutoApplyJWT` |
| API keys | `WithAPIKeyEnabled`, `WithAPIKeyConfig`, `WithAutoApplyAPIKey` |
| Passwords | `WithPasswordHasherConfig`, `WithSecurePasswordHasher` |
| Audit | `WithAuditEnabled`, `WithAuditConfig`, `WithAuditLevel`, `WithAutoApplyAudit` |

Options apply in order. The `...Config` options and the `WithSecureHeaders` and `WithSecurePasswordHasher` presets replace their whole section, auto-apply switch included, so put them before the finer options for the same section. `WithRequireConfig(true)` makes registration fail when neither `extensions.security` nor `security` is in the config file.

```go
ext := security.NewExtension(
	security.WithJWTSigningKey(os.Getenv("JWT_SIGNING_KEY")),
	security.WithAutoApplyJWT(true),
	security.WithSecureHeaders(),
	security.WithAutoApplySecurityHeaders(true),
	security.WithRateLimitPerIP(200, time.Minute),
	security.WithAutoApplyRateLimit(true),
	security.WithCORSOrigins([]string{"https://app.example.com"}),
	security.WithCORSAllowCredentials(true),
	security.WithAutoApplyCORS(true),
)
```

## Defaults

| Section | Default |
|---|---|
| Features | every one enabled, every auto-apply switch off |
| Session | `inmemory`, cookie `forge_session`, 24-hour TTL, auto-renew on, skip `/health` and `/metrics` |
| Cookie | `Secure`, `HttpOnly`, `SameSite=Lax`, path `/` |
| JWT | `HS256`, no signing key, `header:Authorization` with prefix `Bearer`, 1-hour tokens, 7-day refresh tokens |
| CSRF | 32-byte tokens kept 12 hours, `header:X-CSRF-Token`, cookie `csrf_token` (`Secure`, `SameSite=Strict`) |
| Rate limit | 100 requests a minute per client IP, skip `/health` and `/metrics` |
| Headers | `X-Frame-Options: SAMEORIGIN`, `nosniff`, `X-XSS-Protection: 1; mode=block`, HSTS for a year with subdomains (TLS only), `strict-origin-when-cross-origin`, `Server` and `X-Powered-By` removed |
| CORS | every origin, no credentials, common methods and headers, preflight cached for 3600 seconds |
| API keys | `header:X-API-Key` |
| Passwords | Argon2id, 64 MiB, 3 iterations, 4 lanes. bcrypt cost 12 |
| Audit | level `auth`, exclude `/health` and `/metrics` |

## Accepted but not used

These fields exist and pass validation, but nothing reads them yet:

- `session.store: redis` and the `session.redis` block (`address`, `password`, `db`, `pool_size`). Registration fails with "redis session store not yet implemented".
- `session.idle_timeout`, `session.track_ip_address` and `session.track_user_agent`.
- `rate_limit.Store`. Only the in-memory limiter exists.
- `ErrorHandler` on JWT, CSRF and API keys. The middleware writes its own plain-text 401 or 403.
- `audit.LogRequestBody`, `audit.LogResponseBody` and `audit.MaxBodySize`. The audit middleware never captures bodies.
