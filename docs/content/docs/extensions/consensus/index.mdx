## Overview

`github.com/xraph/forge/extensions/consensus` holds a Raft implementation in Go with leader election, pre-vote, log replication and snapshots, plus the pieces a node is built from: log storage on BadgerDB, BoltDB or memory, gRPC, TCP, HTTP and in-process transports, peer discovery through static lists, DNS, Consul, etcd or Kubernetes, and in-memory and persistent state machines.

A Forge extension sits on top of those packages, but it doesn't use them yet. Read the status below before you pick it for a distributed system.

<Callout type="warn">
The extension's `Start` only logs each component it would initialise. Storage, transport, discovery, the cluster manager, the state machine and the Raft node are never created, so nothing listens on the bind port and the node stays a follower forever. `Apply` always returns a not-leader error, `Read` and `Snapshot` panic on the nil state machine, and the auto-snapshot loop (on by default) panics the same way after `raft.snapshot_interval`, which takes your process down. The admin API, `TransferLeadership` and `StepDown` aren't implemented. If you need Raft today, build nodes from the packages yourself, as the quick start does.
</Callout>

## Status

| Piece | State |
|---|---|
| Leader election and log replication in `raft` | Works on the in-process transport. Three nodes elect a leader, and a proposed entry commits on a majority |
| Applying entries on followers | Followers advance their commit index but don't apply committed entries to their state machine, so reads from a follower stay empty. Read from the leader |
| `consensus.NewExtension` | Validates config and registers services, but builds none of the components. See [the Forge extension](#the-forge-extension) |
| Network transports, BadgerDB and BoltDB storage, discovery backends | The code is there and compiles, but nothing in the repository runs a networked cluster on them yet. The BadgerDB and BoltDB stores and the Consul, etcd and Kubernetes discovery don't implement the module's own interfaces, so `raft.NewNode` won't take the stores without an adapter |
| Cluster tests | `testing/` runs in-process clusters. `TestLogReplication` is skipped under `-short`, which is how CI runs it |

## Quick start

You need Go 1.26 or later. Add Forge and the module:

```bash
go get github.com/xraph/forge@latest
go get github.com/xraph/forge/extensions/consensus@latest
```

This program builds a three-node Raft cluster in one process, on the in-process transport the module's own cluster tests use. It waits for a leader, writes a key through it, and checks that every node has committed the entry:

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"log"
	"time"

	"github.com/xraph/forge"
	"github.com/xraph/forge/extensions/consensus"
	"github.com/xraph/forge/extensions/consensus/raft"
	"github.com/xraph/forge/extensions/consensus/statemachine"
	"github.com/xraph/forge/extensions/consensus/storage"
	"github.com/xraph/forge/extensions/consensus/transport"
)

func main() {
	ctx := context.Background()
	logger := forge.NewNoopLogger()
	ids := []string{"node-1", "node-2", "node-3"}

	transports := map[string]*transport.LocalTransport{}
	nodes := map[string]*raft.Node{}
	machines := map[string]*statemachine.MemoryStateMachine{}

	// Build three nodes, each with its own log storage and state machine.
	for _, id := range ids {
		tr := transport.NewLocalTransport(transport.LocalTransportConfig{NodeID: id}, logger)
		st := storage.NewMemoryStorage(storage.MemoryStorageConfig{}, logger)
		sm := statemachine.NewMemoryStateMachine(statemachine.MemoryStateMachineConfig{}, logger)

		node, err := raft.NewNode(raft.Config{
			NodeID:             id,
			HeartbeatInterval:  100 * time.Millisecond,
			ElectionTimeoutMin: 300 * time.Millisecond,
			ElectionTimeoutMax: 600 * time.Millisecond,
		}, logger, sm, tr, st)
		if err != nil {
			log.Fatal(err)
		}

		if err := st.Start(ctx); err != nil {
			log.Fatal(err)
		}

		transports[id], nodes[id], machines[id] = tr, node, sm
	}

	// Connect every node to every other node, then start them.
	for _, id := range ids {
		for _, peer := range ids {
			if peer != id {
				transports[id].Connect(transports[peer])
				nodes[id].AddPeer(peer)
			}
		}
	}

	for _, id := range ids {
		if err := transports[id].Start(ctx); err != nil {
			log.Fatal(err)
		}

		if err := nodes[id].Start(ctx); err != nil {
			log.Fatal(err)
		}
	}

	// Wait for an election.
	leader := ""
	for leader == "" {
		time.Sleep(100 * time.Millisecond)

		for id, node := range nodes {
			if node.IsLeader() {
				leader = id
			}
		}
	}

	fmt.Println("leader:", leader)

	// Writes go to the leader and return once a majority has the entry.
	cmd, err := json.Marshal(consensus.Command{
		Type:    "set",
		Payload: map[string]any{"key": "greeting", "value": "hello"},
	})
	if err != nil {
		log.Fatal(err)
	}

	if err := nodes[leader].Propose(ctx, cmd); err != nil {
		log.Fatal(err)
	}

	value, err := machines[leader].Query(map[string]any{"type": "get", "key": "greeting"})
	fmt.Println("greeting:", value, err)

	// Followers learn the new commit index on the next heartbeat.
	time.Sleep(300 * time.Millisecond)

	for _, id := range ids {
		fmt.Println(id, "commit index:", nodes[id].GetCommitIndex())
	}
}
```

Run it with `go mod tidy && go run .`:

```text
leader: node-2
greeting: hello <nil>
node-1 commit index: 2
node-2 commit index: 2
node-3 commit index: 2
```

The leader varies from run to run. Entry 1 is the no-op every new leader writes, and entry 2 is your `set`. Calling `Propose` on a follower returns a not-leader error that names the current leader, which you can check with `consensus.IsNotLeaderError`.

## The Forge extension

```go
app := forge.NewApp(forge.AppConfig{
	Name: "orders",
	Extensions: []forge.Extension{
		consensus.NewExtension(
			consensus.WithNodeID("node-1"),
			consensus.WithClusterID("orders"),
			consensus.WithBindAddress("0.0.0.0", 7000),
			consensus.WithPeers([]consensus.PeerConfig{
				{ID: "node-2", Address: "10.0.0.2", Port: 7000},
				{ID: "node-3", Address: "10.0.0.3", Port: 7000},
			}),
		),
	},
})
```

That compiles and starts. If you add it anyway, turn the auto-snapshot loop off in your config file so it can't crash the process:

```yaml
extensions:
  consensus:
    advanced:
      enable_auto_snapshot: false
```

Put that in the file rather than in code. A `false` you set in code is a zero value, so it doesn't override the file or the default of `true` whenever a `consensus` section exists.

Here's what each call does on a started extension today:

| Call | Result |
|---|---|
| `Apply` | Always a not-leader error (`IsNotLeaderError` is true) |
| `Read`, `Snapshot` | Panic, because the state machine is nil |
| `HealthCheck` and the extension's `Health` | `storage not initialized`. The health loop logs that warning every `health.check_interval` |
| `IsLeader`, `GetLeader`, `GetRole` | `false`, `""`, `follower` |
| `AddNode`, `RemoveNode`, `TransferLeadership`, `StepDown` | A not-leader error, because the node is never leader. `TransferLeadership` and `StepDown` aren't implemented past that check |
| `GetRaftNode`, `GetStateMachine`, `GetStorage`, `GetTransport`, `GetDiscovery`, `GetClusterManager` | `nil` |
| `GetStats`, `GetClusterInfo` | Zero counts and `HasQuorum: false` |

## What it registers

| Service | Container name | Type |
|---|---|---|
| Consensus service | `consensus`, `consensus:service` | `*Service` |
| Cluster manager | `consensus:cluster` | `ClusterManager` |
| Raft node | `consensus:raft` | `RaftNode` |
| State machine | `consensus:statemachine` | `StateMachine` |
| Leadership checker | `consensus:leadership` | `*LeadershipChecker` |

The cluster manager, Raft node and state machine entries hold `nil` interfaces, so resolving them returns an error.

<Callout type="warn">
The first time anything resolves `*consensus.Service` from the container after the app has started, including through `*LeadershipChecker`, it fails with `consensus service already started`. The container tries to start the service again and `Start` isn't idempotent. Take the service from the extension instead.
</Callout>

```go
ext, err := app.GetExtension("consensus")
if err != nil {
	return err
}

svc := ext.(*consensus.Extension).Service()
fmt.Println(svc.GetRole()) // follower
```

## Dependencies

With `events.enabled` on (the default), the extension adds `events` to its dependencies, though an app without the events extension still starts. It tries to publish `consensus.node.started` on start, `consensus.node.stopped` on stop and `consensus.config.reloaded` after a hot reload. It looks the bus up by an anonymous `Publish(ctx, topic string, event any) error` interface type, and the container matches types exactly, so nothing is published unless a service is registered under that exact type. No other events are emitted.
