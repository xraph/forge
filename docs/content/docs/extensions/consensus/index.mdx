## Overview

`github.com/xraph/forge/extensions/consensus` holds a Raft implementation in Go with leader election, log replication, snapshots, membership changes and leadership transfer, plus the pieces a node is built from: log storage on BadgerDB, BoltDB or memory (optionally encrypted at rest), TCP, HTTP, gRPC and in-process transports, peer discovery through static lists, DNS, Consul, etcd or Kubernetes, and in-memory and persistent state machines.

A Forge extension sits on top. It builds storage, a transport, a state machine and a Raft node from your config, so each app you start with it is one node of the cluster. You can also assemble nodes from the packages yourself, as the quick start does.

<Callout type="warn">
The module hasn't run a production cluster yet. Reads come from the local state machine and aren't linearizable, the extension only takes its first members from the static `peers` list (DNS, Consul, etcd and Kubernetes discovery aren't wired into it), and there's no pre-vote round. Read the status below before you pick it for a distributed system.
</Callout>

## Status

| Piece | State |
|---|---|
| Leader election, log replication and applying entries in `raft` | Three node clusters elect a leader and replicate commands to every state machine over the in-process, TCP, HTTP and gRPC transports |
| Durability | The log, term and vote are reloaded from storage on restart. A node only acknowledges entries and votes it has persisted |
| Snapshots | Nodes compact their log into snapshots, and a follower that falls behind the snapshot catches up through `InstallSnapshot`, sent in chunks |
| `consensus.NewExtension` | Builds storage, transport, state machine and Raft node from config and replicates over TCP, HTTP or gRPC, with TLS and mTLS. See [the Forge extension](#the-forge-extension) |
| Membership and leadership transfer | Servers are added (as a learner first, then promoted) and removed one at a time through the log, the leader included. `TransferLeadership` hands over to a chosen voter and gives up after an election timeout. Membership survives restarts and snapshots |
| Encryption at rest | With `security.enable_encryption`, every value a node stores is sealed with AES-256-GCM. See [encryption at rest](/docs/extensions/consensus/features#encryption-at-rest) |
| Not implemented | Linearizable reads, a pre-vote round, and dynamic discovery in the extension |
| Cluster tests | `testing/` runs in-process clusters, and the `raft` and root packages run TCP, HTTP and gRPC clusters. `TestLogReplication` is skipped under `-short`, which is how CI runs it |

## Quick start

You need Go 1.26 or later. Add Forge and the module:

```bash
go get github.com/xraph/forge@latest
go get github.com/xraph/forge/extensions/consensus@latest
```

This program builds a three-node Raft cluster in one process, on the in-process transport the module's own cluster tests use. It waits for a leader, writes a key through it, and checks that every node has committed the entry:

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"log"
	"time"

	"github.com/xraph/forge"
	"github.com/xraph/forge/extensions/consensus"
	"github.com/xraph/forge/extensions/consensus/raft"
	"github.com/xraph/forge/extensions/consensus/statemachine"
	"github.com/xraph/forge/extensions/consensus/storage"
	"github.com/xraph/forge/extensions/consensus/transport"
)

func main() {
	ctx := context.Background()
	logger := forge.NewNoopLogger()
	ids := []string{"node-1", "node-2", "node-3"}

	transports := map[string]*transport.LocalTransport{}
	nodes := map[string]*raft.Node{}
	machines := map[string]*statemachine.MemoryStateMachine{}

	// Build three nodes, each with its own log storage and state machine.
	for _, id := range ids {
		tr := transport.NewLocalTransport(transport.LocalTransportConfig{NodeID: id}, logger)
		st := storage.NewMemoryStorage(storage.MemoryStorageConfig{}, logger)
		sm := statemachine.NewMemoryStateMachine(statemachine.MemoryStateMachineConfig{}, logger)

		node, err := raft.NewNode(raft.Config{
			NodeID:             id,
			HeartbeatInterval:  100 * time.Millisecond,
			ElectionTimeoutMin: 300 * time.Millisecond,
			ElectionTimeoutMax: 600 * time.Millisecond,
		}, logger, sm, tr, st)
		if err != nil {
			log.Fatal(err)
		}

		if err := st.Start(ctx); err != nil {
			log.Fatal(err)
		}

		transports[id], nodes[id], machines[id] = tr, node, sm
	}

	// Connect every node to every other node, then start them.
	for _, id := range ids {
		for _, peer := range ids {
			if peer != id {
				transports[id].Connect(transports[peer])
				nodes[id].AddPeer(peer)
			}
		}
	}

	for _, id := range ids {
		if err := transports[id].Start(ctx); err != nil {
			log.Fatal(err)
		}

		if err := nodes[id].Start(ctx); err != nil {
			log.Fatal(err)
		}
	}

	// Wait for an election.
	leader := ""
	for leader == "" {
		time.Sleep(100 * time.Millisecond)

		for id, node := range nodes {
			if node.IsLeader() {
				leader = id
			}
		}
	}

	fmt.Println("leader:", leader)

	// Writes go to the leader and return once a majority has the entry.
	cmd, err := json.Marshal(consensus.Command{
		Type:    "set",
		Payload: map[string]any{"key": "greeting", "value": "hello"},
	})
	if err != nil {
		log.Fatal(err)
	}

	if err := nodes[leader].Propose(ctx, cmd); err != nil {
		log.Fatal(err)
	}

	value, err := machines[leader].Query(map[string]any{"type": "get", "key": "greeting"})
	fmt.Println("greeting:", value, err)

	// Followers learn the new commit index on the next heartbeat.
	time.Sleep(300 * time.Millisecond)

	for _, id := range ids {
		fmt.Println(id, "commit index:", nodes[id].GetCommitIndex())
	}
}
```

Run it with `go mod tidy && go run .`:

```text
leader: node-2
greeting: hello <nil>
node-1 commit index: 2
node-2 commit index: 2
node-3 commit index: 2
```

The leader varies from run to run. Entry 1 is the no-op every new leader writes, and entry 2 is your `set`. Calling `Propose` on a follower returns a not-leader error that names the current leader, which you can check with `consensus.IsNotLeaderError`. If the leader loses its term before your entry commits, you get `raft.ErrProposalDropped` instead, and you can retry on the new leader.

To run the same thing across machines, swap the in-process transport for `transport.NewTCPTransport`, `NewHTTPTransport` or `NewGRPCTransport`, use `storage.NewBadgerStorage` or `NewBoltDBStorage` for an on-disk log, and register the other members with `AddPeerAddress(id, address, port)`. Or let the extension do that wiring for you.

## The Forge extension

```go
app := forge.NewApp(forge.AppConfig{
	Name: "orders",
	Extensions: []forge.Extension{
		consensus.NewExtension(
			consensus.WithNodeID("node-1"),
			consensus.WithClusterID("orders"),
			consensus.WithBindAddress("10.0.0.1", 7000),
			consensus.WithPeers([]consensus.PeerConfig{
				{ID: "node-2", Address: "10.0.0.2", Port: 7000},
				{ID: "node-3", Address: "10.0.0.3", Port: 7000},
			}),
		),
	},
})
```

Start that app on every server, each with its own `node_id`, and they elect a leader between them. `Start` builds:

- storage under `storage.path`: `badger` by default, or `boltdb` or `memory`, encrypted when `security.enable_encryption` is on
- the transport on `bind_addr:bind_port`: `tcp` by default, or `http` or `grpc`, with TLS when `security.enable_tls` is on, and client certificates checked against node IDs when `enable_mtls` is on
- a memory state machine
- a Raft node whose first members are the `peers` list

`bind_addr` defaults to `127.0.0.1`, so set it to an address the other servers can reach. It's also the address other members record for this node.

Settings it can't honour stop the service when it's created, with an error that wraps `ErrInvalidConfig`: storage `pebble` or `postgres`, and any discovery type other than `static`.

Here's what each call does on a started extension:

| Call | Result |
|---|---|
| `Apply` | On the leader, appends the command and returns once it is committed and applied. Elsewhere a not-leader error naming the leader. `raft.ErrProposalDropped` when a leadership change dropped the entry, and `raft.ErrLeadershipTransferInProgress` while leadership is being handed over |
| `Read` | Queries this node's state machine. On a follower it can lag the leader |
| `Snapshot` | Snapshots the state machine and compacts the log |
| `IsLeader`, `GetLeader`, `GetRole`, `GetTerm` | The Raft node's current state |
| `AddNode` | On the leader, adds a running server that was started with `join: true`. It joins as a learner and becomes a voter once it has caught up. Only one change runs at a time (`raft.ErrConfigChangeInProgress`) |
| `RemoveNode` | On the leader, removes a server. Removing the leader is allowed: it steps down once the change commits |
| `TransferLeadership` | On the leader, hands leadership to a voter. Writes are refused while it runs, and it fails with `raft.ErrLeadershipTransferFailed` if the target hasn't taken over within an election timeout |
| `StepDown` | The leader returns to follower and an election picks the next one |
| `HealthCheck` and the extension's `Health` | `nil` while the node has storage, a transport and quorum. `no quorum` otherwise |
| `GetStats`, `GetClusterInfo` | Live numbers from the Raft node, and the members of the current configuration |
| `ReencryptStorage` | Rewrites stored values under the active encryption key after a key rotation |

The admin routes are off by default. With `admin_api.enabled` they're registered on your app's router under `admin_api.path_prefix`, and since they can write to the replicated log, set `admin_api.enable_auth` and `api_key` whenever anyone else can reach that router.

## What it registers

| Service | Container name | Type |
|---|---|---|
| Consensus service | `consensus`, `consensus:service` | `*Service` |
| Cluster manager | `consensus:cluster` | `ClusterManager` |
| Raft node | `consensus:raft` | `RaftNode` |
| State machine | `consensus:statemachine` | `StateMachine` |
| Leadership checker | `consensus:leadership` | `*LeadershipChecker` |

The Raft node and state machine are created by `Start`. The cluster manager is backed by the Raft configuration: its `GetNodes` lists the current members, learners included, and its `AddNode` and `RemoveNode` go through the log like the service's. All four entries resolve through `*Service`, so they hit the problem below; take them from the service with `GetRaftNode()`, `GetStateMachine()` and `GetClusterManager()`.

<Callout type="warn">
The first time anything resolves `*consensus.Service` from the container after the app has started, including through `*LeadershipChecker`, it fails with `consensus service already started`. The container tries to start the service again and `Start` isn't idempotent. Take the service from the extension instead.
</Callout>

```go
ext, err := app.GetExtension("consensus")
if err != nil {
	return err
}

svc := ext.(*consensus.Extension).Service()
fmt.Println(svc.GetRole(), svc.GetLeader())
```

## Dependencies

With `events.enabled` on (the default), the extension adds `events` to its dependencies, though an app without the events extension still starts. It tries to publish `consensus.node.started` on start, `consensus.node.stopped` on stop and `consensus.config.reloaded` after a hot reload. It looks the bus up by an anonymous `Publish(ctx, topic string, event any) error` interface type, and the container matches types exactly, so nothing is published unless a service is registered under that exact type. No other events are emitted.
