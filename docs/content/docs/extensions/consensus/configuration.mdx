## Where config comes from

The extension reads `extensions.consensus` from your config, falling back to `consensus`. It starts from `DefaultConfig()`, applies the file, then applies the options you pass to `NewExtension`. An option counts as set when it differs from the default, so a `false` you set in code beats both the file and a default of `true`. An option you set to exactly its default looks the same as no option, and the file wins for that field.

`WithRequireConfig(true)` makes a missing section an error at startup. `WithConfig(cfg)` replaces the whole programmatic config, and `NewExtensionWithConfig(cfg)` is shorthand for it.

<Callout type="warn">
Some keys are validated and stored but have no effect yet. [Keys the extension acts on](#keys-the-extension-acts-on) lists the ones that do something, and the tables under [all keys](#all-keys) mark the rest.
</Callout>

## YAML example

```yaml title="config.yaml"
extensions:
  consensus:
    node_id: node-1
    cluster_id: orders
    bind_addr: 10.0.0.1
    bind_port: 7000
    peers:
      - {id: node-2, address: 10.0.0.2, port: 7000}
      - {id: node-3, address: 10.0.0.3, port: 7000}
    raft:
      heartbeat_interval: 1s
      election_timeout_min: 5s
      election_timeout_max: 10s
      snapshot_interval: 30m
    transport:
      type: tcp           # tcp, http or grpc
    storage:
      type: badger        # badger, boltdb or memory
      path: ./data/consensus
    discovery:
      type: static        # only static is wired into the extension
    security:
      enable_mtls: true
      enable_tls: true
      cert_file: /etc/consensus/node-1.pem
      key_file: /etc/consensus/node-1-key.pem
      ca_file: /etc/consensus/ca.pem
      enable_encryption: true
      encryption_key_file: /etc/consensus/raft.key
    health:
      check_interval: 10s
    admin_api:
      enabled: false
```

`bind_addr` is both the address the node listens on and the address other members record for it, so use one the other servers can reach. A server joining an existing cluster also sets `join: true`; see [membership changes](/docs/extensions/consensus/features#membership-changes).

## Programmatic configuration

```go
ext := consensus.NewExtension(
	consensus.WithNodeID("node-1"),
	consensus.WithClusterID("orders"),
	consensus.WithBindAddress("10.0.0.1", 7000),
	consensus.WithPeers([]consensus.PeerConfig{
		{ID: "node-2", Address: "10.0.0.2", Port: 7000},
		{ID: "node-3", Address: "10.0.0.3", Port: 7000},
	}),
	consensus.WithTransportType("tcp"),
	consensus.WithStorageType("badger"),
	consensus.WithStoragePath("./data/consensus"),
)
```

| Option | Sets |
|---|---|
| `WithNodeID(id string)` | `node_id` |
| `WithClusterID(id string)` | `cluster_id` |
| `WithBindAddress(addr string, port int)` | `bind_addr` and `bind_port` |
| `WithPeers(peers []PeerConfig)` | `peers` |
| `WithJoin(join bool)` | `join` |
| `WithTransportType(transportType string)` | `transport.type` |
| `WithDiscoveryType(discoveryType string)` | `discovery.type` |
| `WithStorageType(storageType string)` | `storage.type` |
| `WithStoragePath(path string)` | `storage.path` |
| `WithTLS(certFile, keyFile string)` | `security.enable_tls`, `cert_file`, `key_file` |
| `WithMTLS(caFile string)` | `security.enable_mtls`, `ca_file`. Also needs `WithTLS` |
| `WithConfig(cfg Config)` | the whole config |
| `WithRequireConfig(require bool)` | fail when the config section is missing |

There are no options for the Raft timings, snapshots, health, observability, the admin API, events or the advanced section. Set those in the file.

## Validation

`Register` validates the merged config, and your app won't start if any of these fail. Each error wraps `ErrInvalidConfig`.

| Rule | Default |
|---|---|
| `node_id` is set | empty, so you must set it |
| `cluster_id` is set | `default` |
| `bind_port` is between 1 and 65535 | `7000` |
| `raft.heartbeat_interval` > 0 | `1s` |
| `raft.election_timeout_min` > `raft.heartbeat_interval` | `5s` |
| `raft.election_timeout_max` > `raft.election_timeout_min` | `10s` |
| `transport.type` is `tcp`, `http` or `grpc` | `tcp` |
| `transport.max_message_size` > 0 | `4194304` (4MB) |
| `discovery.type` is `static`, `dns`, `consul`, `etcd` or `kubernetes` | `static` |
| `storage.type` is `badger`, `boltdb`, `memory`, `pebble` or `postgres` | `badger` |
| `storage.path` is set | `./data/consensus` |
| `security.cert_file` and `key_file` are set when `enable_tls` is on | TLS off |
| `enable_tls` is on and `ca_file` is set when `enable_mtls` is on | mTLS off |
| With `security.enable_encryption`, exactly one key source is set (`encryption_key_file`, `encryption_key_env`, or `encryption_keys` with unique IDs from 1), inline keys (`encryption_key`, or `value` in a list entry) only with `allow_inline_encryption_key`, and `encryption_active_key_id` is a listed ID | encryption off |
| `admin_api.api_key` is set when `admin_api.enable_auth` is on | auth off |

Two more checks run when the service is created, after validation: `storage.type` must be `badger`, `boltdb` or `memory` (there's no implementation of `pebble` or `postgres`), and `discovery.type` must be `static`.

## Keys the extension acts on

| Key | Default | What it does |
|---|---|---|
| `node_id`, `cluster_id` | none, `default` | Identify the node in the cluster, logs, stats and events |
| `bind_addr`, `bind_port` | `127.0.0.1`, `7000` | Where the transport listens, and the address recorded for this node in membership changes |
| `peers` | `[]` | The first members of a new cluster, and the routes to them. Once the log or a snapshot holds a membership, the log wins and changing `peers` does nothing |
| `join` | `false` | Start as a server waiting to be added with `AddNode`. It never starts an election on its own |
| `raft.heartbeat_interval`, `election_timeout_min`, `election_timeout_max` | `1s`, `5s`, `10s` | Raft timings |
| `raft.max_append_entries` | `64` | Most entries in one AppendEntries message |
| `raft.snapshot_interval`, `snapshot_threshold`, `advanced.enable_auto_snapshot` | `30m`, `10000`, `true` | With auto-snapshots on, the node checks every interval and snapshots when its log holds more than the threshold |
| `transport.*` | see below | `type`, `max_message_size`, `timeout`, `connection_timeout`, `idle_timeout`, `max_connections`, `keep_alive_interval` (TCP and gRPC) and `keep_alive_timeout` (gRPC) |
| `storage.type`, `storage.path` | `badger`, `./data/consensus` | The log storage backend and its directory |
| `storage.bolt_options.timeout`, `no_sync`, `no_grow_sync` | `1s`, `false`, `false` | Passed to BoltDB. Leave `no_sync` off: with it on a crash can lose writes the node already acknowledged |
| `security.*` | off | TLS and mTLS between nodes, and encryption at rest |
| `admin_api.*` | off | Registers the admin routes and protects them with an API key |
| `health.enabled`, `health.check_interval` | `true`, `10s` | Run a loop that calls `HealthCheck` and logs a warning when it fails |
| `observability.metrics.enabled`, `collection_interval` | `true`, `15s` | Run a metrics loop. The extension creates the service without a metrics sink, so it records nothing |
| `events.enabled` | `true` | Adds `events` to the dependencies and tries to publish start, stop and reload events |

The tables below mark the keys that are stored and validated where a rule exists, but otherwise ignored.

## All keys

### Node

| Key | Type | Default |
|---|---|---|
| `node_id` | `string` | `""` |
| `cluster_id` | `string` | `default` |
| `bind_addr` | `string` | `127.0.0.1` |
| `bind_port` | `int` | `7000` |
| `peers` | list of `{id, address, port}` | `[]` |
| `join` | `bool` | `false` |

### `raft`

| Key | Type | Default |
|---|---|---|
| `heartbeat_interval` | duration | `1s` |
| `election_timeout_min` | duration | `5s` |
| `election_timeout_max` | duration | `10s` |
| `snapshot_interval` | duration | `30m` |
| `snapshot_threshold` | `uint64` | `10000` |
| `log_cache_size` | `int` | `1024` |
| `max_append_entries` | `int` | `64` |
| `trailing_logs` | `uint64` | `10000` |
| `replication_batch_size` | `int` | `100` |
| `leader_lease_timeout` | duration | `500ms` |
| `pre_vote` | `bool` | `true` |
| `check_quorum` | `bool` | `true` |
| `disable_pipeline` | `bool` | `false` |

`log_cache_size`, `trailing_logs`, `replication_batch_size`, `leader_lease_timeout`, `pre_vote`, `check_quorum` and `disable_pipeline` have no effect. The log keeps every entry after the last snapshot in memory, so there's no cache to size, and there's no pre-vote round or leader lease.

### `transport`

| Key | Type | Default |
|---|---|---|
| `type` | `string` | `tcp` |
| `max_message_size` | `int` | `4194304` |
| `timeout` | duration | `10s` |
| `keep_alive` | `bool` | `true` |
| `keep_alive_interval` | duration | `30s` |
| `keep_alive_timeout` | duration | `10s` |
| `max_connections` | `int` | `100` |
| `connection_timeout` | duration | `5s` |
| `idle_timeout` | duration | `5m` |
| `enable_compression` | `bool` | `true` |
| `compression_level` | `int` | `6` |
| `enable_multiplexing` | `bool` | `true` |

`keep_alive`, `enable_compression`, `compression_level` and `enable_multiplexing` have no effect. TCP and gRPC connections always send keep-alive probes every `keep_alive_interval`, and messages are never compressed.

|---|---|---|

Only `type: static` is accepted by the service, and the other keys here have no effect.

|---|---|---|

| `path` | `string` | `./data/consensus` |
| `sync_writes` | `bool` | `true` |
| `max_batch_size` | `int` | `1000` |
| `max_batch_delay` | duration | `10ms` |
| `compact_on_start` | `bool` | `false` |
| `badger_options.value_log_max_entries` | `uint32` | `1000000` |

| `badger_options.num_mem_tables` | `int` | `5` |

### `election`

| Key | Type | Default |
|---|---|---|
| `enabled` | `bool` | `true` |
| `randomized_timeout` | `bool` | `true` |
| `pre_vote` | `bool` | `true` |

| `step_down_on_remove` | `bool` | `true` |

### `security`

| Key | Type | Default |
|---|---|---|
| `enable_tls` | `bool` | `false` |
| `enable_mtls` | `bool` | `false` |
| `cert_file`, `key_file`, `ca_file` | `string` | `""` |
| `skip_verify` | `bool` | `false` |
| `enable_encryption` | `bool` | `false` |
| `encryption_key_file` | `string` | `""` |
| `encryption_key_env` | `string` | `""` |
| `encryption_keys` | list of `{id, file, env, value}` | `[]` |
| `encryption_active_key_id` | `uint32` | `0` (the highest listed ID) |
| `allow_inline_encryption_key` | `bool` | `false` |
| `encryption_key` | `string` | `""` |
| `encryption_migrate_plaintext` | `bool` | `false` |

With `enable_mtls`, each node's certificate must name its node ID as a DNS subject alternative name, and messages whose sender doesn't match the certificate are refused. `skip_verify` can't be combined with mTLS.

For encryption at rest, give the node a 32 byte key in a file (`encryption_key_file`) or an environment variable (`encryption_key_env`), as raw bytes (files only), 64 hex characters or base64. `encryption_key` holds the key inline in the config and is refused unless you set `allow_inline_encryption_key: true`, because keys written into config files end up in version control. List several keys under `encryption_keys` to rotate. `encryption_migrate_plaintext` lets a node with existing unencrypted data encrypt it in place on start. The [features page](/docs/extensions/consensus/features#encryption-at-rest) covers the format, rotation and migration.

## Hot reload

The extension implements `Reload(ctx)`. It reloads and validates the config, then copies the `observability`, `health` and `admin_api` sections into the running service. The loops that already started keep their old intervals. The admin routes are registered once, when the extension registers, so changing `admin_api` takes a restart.
