## Where config comes from

The extension reads `extensions.consensus` from your config, falling back to `consensus`. It starts from `DefaultConfig()`, applies the file, then applies the options you pass to `NewExtension`. An option only counts as set when its value isn't the zero value and differs from the default, so a `false` you set in code doesn't override the file or a default of `true` while a `consensus` section exists. Put `false` values in the file.

`WithRequireConfig(true)` makes a missing section an error at startup. `WithConfig(cfg)` replaces the whole programmatic config, and `NewExtensionWithConfig(cfg)` is shorthand for it.

<Callout type="warn">
The extension validates and stores most of this config but doesn't act on it, because it never builds storage, a transport, discovery or a Raft node. The keys it does read are listed under [keys the extension acts on](#keys-the-extension-acts-on).
</Callout>

## YAML example

```yaml title="config.yaml"
extensions:
  consensus:
    node_id: node-1
    cluster_id: orders
    bind_addr: 0.0.0.0
    bind_port: 7000
    peers:
      - {id: node-2, address: 10.0.0.2, port: 7000}
      - {id: node-3, address: 10.0.0.3, port: 7000}
    raft:
      heartbeat_interval: 1s
      election_timeout_min: 5s
      election_timeout_max: 10s
      snapshot_interval: 30m
    transport:
      type: grpc          # grpc or tcp
    storage:
      type: badger        # badger, boltdb, pebble or postgres
      path: ./data/consensus
    discovery:
      type: static        # static, dns, consul, etcd or kubernetes
    health:
      check_interval: 10s
    admin_api:
      enabled: false
    advanced:
      enable_auto_snapshot: false
```

Keep `advanced.enable_auto_snapshot: false`. With the default of `true`, the extension's snapshot loop panics on its nil state machine after `raft.snapshot_interval`.

## Programmatic configuration

```go
ext := consensus.NewExtension(
	consensus.WithNodeID("node-1"),
	consensus.WithClusterID("orders"),
	consensus.WithBindAddress("0.0.0.0", 7000),
	consensus.WithPeers([]consensus.PeerConfig{
		{ID: "node-2", Address: "10.0.0.2", Port: 7000},
		{ID: "node-3", Address: "10.0.0.3", Port: 7000},
	}),
	consensus.WithTransportType("grpc"),
	consensus.WithStorageType("badger"),
	consensus.WithStoragePath("./data/consensus"),
)
```

| Option | Sets |
|---|---|
| `WithNodeID(id string)` | `node_id` |
| `WithClusterID(id string)` | `cluster_id` |
| `WithBindAddress(addr string, port int)` | `bind_addr` and `bind_port` |
| `WithPeers(peers []PeerConfig)` | `peers` |
| `WithTransportType(transportType string)` | `transport.type` |
| `WithDiscoveryType(discoveryType string)` | `discovery.type` |
| `WithStorageType(storageType string)` | `storage.type` |
| `WithStoragePath(path string)` | `storage.path` |
| `WithTLS(certFile, keyFile string)` | `security.enable_tls`, `cert_file`, `key_file` |
| `WithMTLS(caFile string)` | `security.enable_mtls`, `ca_file`. Also needs `WithTLS` |
| `WithConfig(cfg Config)` | the whole config |
| `WithRequireConfig(require bool)` | fail when the config section is missing |

There are no options for the Raft timings, snapshots, health, observability, the admin API, events or the advanced section. Set those in the file.

## Validation

`Register` validates the merged config, and your app won't start if any of these fail. Each error wraps `ErrInvalidConfig`.

| Rule | Default |
|---|---|
| `node_id` is set | empty, so you must set it |
| `cluster_id` is set | `default` |
| `bind_port` is between 1 and 65535 | `7000` |
| `raft.heartbeat_interval` > 0 | `1s` |
| `raft.election_timeout_min` > `raft.heartbeat_interval` | `5s` |
| `raft.election_timeout_max` > `raft.election_timeout_min` | `10s` |
| `transport.type` is `grpc` or `tcp` | `grpc` |
| `transport.max_message_size` > 0 | `4194304` (4MB) |
| `discovery.type` is `static`, `dns`, `consul`, `etcd` or `kubernetes` | `static` |
| `storage.type` is `badger`, `boltdb`, `pebble` or `postgres` | `badger` |
| `storage.path` is set | `./data/consensus` |
| `security.cert_file` and `key_file` are set when `enable_tls` is on | TLS off |
| `enable_tls` is on and `ca_file` is set when `enable_mtls` is on | mTLS off |

## Keys the extension acts on

| Key | Default | What it does |
|---|---|---|
| `node_id`, `cluster_id` | none, `default` | Show up in logs, stats and events |
| `health.enabled`, `health.check_interval` | `true`, `10s` | Run a loop that calls `HealthCheck` and logs a warning when it fails, which today is every time (`storage not initialized`) |
| `observability.metrics.enabled`, `collection_interval` | `true`, `15s` | Run a metrics loop. The service has no metrics sink, so it records nothing |
| `advanced.enable_auto_snapshot`, `raft.snapshot_interval` | `true`, `30m` | Run the snapshot loop, which panics. Turn it off |
| `admin_api.enabled` | `true` | Logs "admin API enabled but not yet implemented" and nothing else |
| `events.enabled` | `true` | Adds `events` to the dependencies and tries to publish start, stop and reload events |

Everything else below is stored and validated where a rule exists, and otherwise ignored.

## Hot reload

The extension implements `Reload(ctx)`. It reloads and validates the config, then copies the `observability`, `health` and `admin_api` sections into the running service. The loops that already started keep their old intervals.
