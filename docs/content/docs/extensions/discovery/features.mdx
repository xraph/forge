## Backends

Every backend implements `discovery.Backend` (an alias for `backends.Backend`), so you switch providers without changing the code that looks services up:

```go
type Backend interface {
	Name() string
	Initialize(ctx context.Context) error
	Register(ctx context.Context, instance *ServiceInstance) error
	Deregister(ctx context.Context, serviceID string) error
	Discover(ctx context.Context, serviceName string) ([]*ServiceInstance, error)
	DiscoverWithTags(ctx context.Context, serviceName string, tags []string) ([]*ServiceInstance, error)
	Watch(ctx context.Context, serviceName string, onChange func([]*ServiceInstance)) error
	ListServices(ctx context.Context) ([]string, error)
	Health(ctx context.Context) error
	Close() error
}
```

| `backend` | Option | Registers this app | Notes |
|---|---|---|---|
| `memory` | `WithBackend("memory")` | yes, in process | Default. One process only |
| `consul` | `WithConsul(address, token)` | yes | ACL token, datacenter, namespace and TLS from `consul.*`. Attaches a 30-second TTL check and tells Consul to drop the instance after a minute in a critical state |
| `etcd` | `WithEtcd(endpoints)` | yes | Keys under `etcd.key_prefix` (default `/services`). The `tls_*` keys aren't applied yet |
| `kubernetes` | `WithKubernetes(namespace, inCluster)` | no, Kubernetes owns that | `Discover` returns one instance per matching Kubernetes Service |
| `mdns` | `WithMDNS(domain)` | yes | Bonjour on macOS, Avahi on Linux, DNS-SD on Windows. No server needed |
| `http` | `WithHTTPSeeds(urls...)` | only in this process | Polls each seed's `/_farp/discovery` endpoint |
| `eureka` | `WithEureka(urls)` | | Not implemented. Startup fails with "eureka backend not yet implemented" |

Every backend supports `Watch`.

## Self-registration

On `Start` the extension builds a `ServiceInstance` from your config and the app (see [where the address comes from](/docs/extensions/discovery/configuration#where-the-address-comes-from)) and registers it. On `Stop` it deregisters, unless you turned `service.enable_auto_deregister` off. With FARP on, the FARP service node handles deregistration instead.

You can also register other instances yourself:

```go
svc, err := forge.Inject[*discovery.Service](app.Container())
if err != nil {
	return err
}

err = svc.Register(ctx, &discovery.ServiceInstance{
	ID:       "worker-1",
	Name:     "worker",
	Version:  "1.0.0",
	Address:  "10.0.0.5",
	Port:     8080,
	Tags:     []string{"http", "v1"},
	Metadata: map[string]string{"region": "us-east-1"},
	Status:   discovery.HealthStatusPassing,
})
```

Set `Status` yourself. An instance without `passing` never shows up in `DiscoverHealthy`, `SelectInstance` or `GetServiceURL`.

`ServiceInstance` has a few helpers:

```go
instance.URL("http")                         // "http://10.0.0.5:8080"
instance.HasTag("http")                      // true
instance.HasAllTags([]string{"http", "v1"})  // true
instance.IsHealthy()                         // Status == HealthStatusPassing
instance.GetMetadata("region")               // "us-east-1", true
```

## Looking up services

```go
instances, err := svc.Discover(ctx, "user-service")
tagged, err := svc.DiscoverWithTags(ctx, "user-service", []string{"http", "v2"}) // must have all tags
healthy, err := svc.DiscoverHealthy(ctx, "user-service")
names, err := svc.ListServices(ctx)
```

## Instance selection

`SelectInstance` picks one healthy instance, and `GetServiceURL` turns it into `scheme://address:port`:

```go
instance, err := svc.SelectInstance(ctx, "user-service", discovery.LoadBalanceRoundRobin)

url, err := svc.GetServiceURL(ctx, "user-service", "http", discovery.LoadBalanceRandom)
```

Two strategies work: `LoadBalanceRoundRobin` and `LoadBalanceRandom`. `LoadBalanceLeastConnections` and `LoadBalanceWeightedRoundRobin` exist as constants, but they fall back to round-robin, since the service doesn't count connections or read weights. When no instance is healthy, both calls return an error.

## Watching

Your callback gets the full instance list each time it changes:

```go
err := svc.Watch(ctx, "payment-service", func(instances []*discovery.ServiceInstance) {
	log.Printf("payment-service now has %d instances", len(instances))
})
```

To watch from start, pass `WithWatch([]string{"payment-service"}, onChange)` when you build the extension, or list the services under `watch.services` with `watch.enabled: true`. A callback can only come from code. Services you list in the file without one get an info log line on each change and nothing else.

## Health

Without FARP, the extension runs a loop every `health_check.interval` (10 seconds by default). It runs your app's health checks with `health_check.timeout`, and re-registers the instance with `passing` when the overall result is healthy and `critical` when it isn't. With FARP on, the FARP service node runs its own health loop instead, and the extension's loop only starts if the node fails to start.

The loop always uses your app's health checks. `health_check.http`, `tcp`, `grpc` and `deregister_critical_service_after` are read into the config but have no effect, and `WithHTTPHealthCheck` only sets the interval and turns the loop on.

Statuses are `HealthStatusPassing`, `HealthStatusWarning`, `HealthStatusCritical` and `HealthStatusUnknown`. Only `passing` counts as healthy.

## FARP

FARP is the Forge API gateway registration protocol, implemented in [xraph/farp](https://github.com/xraph/farp). With `farp.enabled`, the extension adds four routes:

| Route | What it returns |
|---|---|
| `GET /_farp/manifest` | The service manifest: routes, endpoints, capabilities and schema references |
| `GET /_farp/health` | FARP health for this instance |
| `GET /_farp/schemas/:type` | The OpenAPI or AsyncAPI schema |
| `GET /_farp/discovery` | Instance ID, name, version, address, port, tags and metadata |

The routes exist from `Register` on. The manifest itself is built in a `PhaseAfterStart` hook, after every extension has started, so it sees routes that other extensions add during their own start. Until then the first three answer 503, and `/_farp/discovery` answers 503 until the extension's own `Start` has run.

```go
discovery.NewExtension(
	discovery.WithBackend("mdns"),
	discovery.WithServiceName("users"),
	discovery.WithServiceID("users-1"),
	discovery.WithFARPEnabled(true),
	discovery.WithFARPGatewayURL("http://localhost:7903"),
	discovery.WithFARPPathRules(
		farp.PathRule{Pattern: "/internal/**", Action: farp.PathRuleExclude},
	),
)
```

### Metadata in the registry

With FARP on, the instance you register carries these keys, so a gateway browsing the registry can find your manifest:

| Key | Value |
|---|---|
| `farp.enabled` | `true` |
| `farp.manifest` | `http://host:port/_farp/manifest` |
| `farp.health` | `farp.endpoints.health`, or `/_/health` when empty |
| `farp.openapi`, `farp.openapi.path` | The OpenAPI URL and path, when `farp.endpoints.openapi` is set |
| `farp.asyncapi`, `farp.asyncapi.path` | Same for AsyncAPI |
| `farp.graphql`, `farp.graphql.path` | Same for GraphQL |
| `farp.grpc.reflection` | `true` when `farp.endpoints.grpc_reflection` is on |
| `farp.collapse_service_tags` | `true` when you turned tag collapsing on |
| `farp.include_internal_paths` | `true` when you turned internal path exclusion off |

The URL keys need an address and a port. Set `scheme` in `service.metadata` to advertise something other than `http`. On mDNS these end up in the TXT records:

```
farp.enabled=true
farp.manifest=http://192.168.1.10:8080/_farp/manifest
farp.health=/health
```

### Schemas

When `farp.schemas` is empty and `farp.auto_register` is on (the default), the extension publishes whichever of the OpenAPI and AsyncAPI specs your app has turned on. If you list schemas, only their `type` is read, and only `openapi` and `asyncapi` produce anything. `spec_version`, `location` and `content_type` are ignored, and the extension generates the spec from your routes.

```go
discovery.WithFARPSchemas(
	discovery.FARPSchemaConfig{Type: "openapi"},
	discovery.FARPSchemaConfig{Type: "asyncapi"},
)
```

Internal paths (`/_/*`, `/_farp/*` and similar) are left out of the published schemas unless you call `WithFARPExcludeInternalPaths(false)`. `WithFARPPathRules` adds your own rules, checked in order, and the first match wins.

### Gateway push

With `gateway_url` set, the extension posts its registration to `<gateway_url>/_farp/v1/register` once the HTTP server is listening, retries with backoff until that works, and calls `<gateway_url>/_farp/v1/deregister/<name>` on shutdown.

### Not implemented

`farp.strategy` (`push`, `pull`, `hybrid`), `farp.capabilities` and `farp.endpoints.metrics` are stored in the config but the extension doesn't use them. The manifest's capabilities come from the FARP service node, not from your list. `SchemaPublisher` reads them, but the extension doesn't use `SchemaPublisher`.

## mDNS

mDNS needs no server, which makes it the easy choice on one machine or a local network:

```go
discovery.NewExtension(
	discovery.WithMDNS(""), // "local." by default
	discovery.WithServiceName("my-service"),
	discovery.WithServiceID("my-service-1"),
)
```

The service type defaults to `_<name>._tcp`. You can set it, and browse more than one type:

```go
discovery.NewExtension(
	discovery.WithMDNS(""),
	discovery.WithServiceName("user-service"),
	discovery.WithMDNSServiceType("_myapp._tcp"),
	discovery.WithMDNSServiceTypes("_myapp._tcp", "_api._tcp"),
)
```

| Option | Description |
|---|---|
| `WithMDNSServiceType(t)` | Service type to register |
| `WithMDNSServiceTypes(t...)` | Service types to browse |
| `WithMDNSBrowseTimeout(d)` | Browse timeout (default 3s) |
| `WithMDNSTTL(ttl)` | Record TTL in seconds (default 120) |
| `WithMDNSWatchInterval(d)` | Watch polling interval |
| `WithMDNSInterface(iface)` | Network interface to use |
| `WithMDNSIPv6(enabled)` | Use IPv6 too |
