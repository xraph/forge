## Overview

`github.com/xraph/forge/extensions/search` gives your app one `Search` interface for index
management, document indexing, full-text search with filters and field boosts, suggestions and
autocomplete. The in-memory backend is the one that works today.

<Callout type="warn">
The config also accepts `elasticsearch`, `meilisearch` and `typesense`, but those drivers are
placeholders that never contact a server. They pass validation, log that they connected, drop every
write and return no hits. Don't point production traffic at them. See
[Backends](/docs/extensions/search/features#backends).
</Callout>

## What It Registers

| Service | How to resolve it | Type |
|---|---|---|
| Search service | by type, or the alias `search` | `*search.SearchService` |
| Search interface | by type | `search.Search`, backed by the same `*SearchService` |

Get it with `search.GetSearch(c)`, `search.MustGetSearch(c)`, `search.GetSearchFromApp(app)`,
`search.MustGetSearchFromApp(app)` or `forge.Inject[*search.SearchService](c)`. The extension's
`Start` connects the backend and its `Stop` disconnects it, logging a disconnect error without
failing shutdown.

## Quick Start

This app creates a `products` index when it starts, adds three documents, and serves a search
endpoint:

```go
package main

import (
	"context"
	"log"
	"net/http"

	"github.com/xraph/forge"
	"github.com/xraph/forge/extensions/search"
)

func main() {
	app := forge.NewApp(forge.AppConfig{
		Name:        "search-demo",
		HTTPAddress: ":8080",
		Extensions: []forge.Extension{
			search.NewExtension(search.WithDriver("inmemory")),
		},
	})

	// The search service connects when the extension starts, so seed the
	// index once the app is up.
	err := forge.OnStarted(app, "seed-products", func(ctx context.Context, a forge.App) error {
		s := search.MustGetSearchFromApp(a)

		if err := s.CreateIndex(ctx, "products", search.IndexSchema{
			Fields: []search.FieldSchema{
				{Name: "title", Type: "text", Searchable: true},
				{Name: "category", Type: "keyword", Filterable: true},
			},
		}); err != nil {
			return err
		}

		return s.BulkIndex(ctx, "products", []search.Document{
			{ID: "1", Fields: map[string]any{"title": "Mechanical keyboard", "category": "input"}},
			{ID: "2", Fields: map[string]any{"title": "Wireless mouse", "category": "input"}},
			{ID: "3", Fields: map[string]any{"title": "USB-C keyboard dock", "category": "hubs"}},
		})
	})
	if err != nil {
		log.Fatal(err)
	}

	err = app.Router().GET("/search", func(ctx forge.Context) error {
		s, err := search.GetSearchFromApp(app)
		if err != nil {
			return err
		}

		results, err := s.Search(ctx.Context(), search.SearchQuery{
			Index: "products",
			Query: ctx.Query("q"),
			Limit: 10,
		})
		if err != nil {
			return err
		}

		return ctx.JSON(http.StatusOK, results)
	})
	if err != nil {
		log.Fatal(err)
	}

	if err := app.Run(); err != nil {
		log.Fatal(err)
	}
}
```

Run it and try `curl 'http://localhost:8080/search?q=keyboard'`. You get the keyboard and the dock
back, each with a score, plus `total`, `offset` and `limit`. Hits with equal scores can come back
in either order. The index lives in process memory, so every restart starts empty and the start
hook seeds it again.

## Using Search in Your Services

Take `search.Search` in your constructor and Vessel fills it in:

```go
type ProductSearch struct {
	search search.Search
	logger forge.Logger
}

func NewProductSearch(s search.Search, logger forge.Logger) *ProductSearch {
	return &ProductSearch{search: s, logger: logger}
}

func (ps *ProductSearch) Find(ctx context.Context, query, category string) ([]search.Hit, error) {
	results, err := ps.search.Search(ctx, search.SearchQuery{
		Index:   "products",
		Query:   query,
		Filters: []search.Filter{{Field: "category", Operator: "=", Value: category}},
		Limit:   20,
	})
	if err != nil {
		return nil, err
	}

	return results.Hits, nil
}
```

Register it with Vessel:

```go
forge.ProvideConstructor(app.Container(), NewProductSearch)
```

## Key Concepts

- Drivers: `inmemory` works. `elasticsearch`, `meilisearch` and `typesense` are placeholders that accept config and do nothing.
- Index management: create, delete, list and inspect indexes. The in-memory backend stores the `IndexSchema` you pass and hands it back from `GetIndexInfo`, but doesn't use it to index or rank.
- Document operations: index one document or many, get by ID, update an existing one, and delete.
- Search: case-insensitive substring matching across every field, with per-field boosts, a minimum score, simple filters (`=`, `!=`, `EXISTS`, `NOT EXISTS`), an offset and a capped limit.
- Suggest and autocomplete: substring and prefix matches on one field, for search-as-you-type.

## Important Runtime Notes

- `Sort`, `Facets`, `Highlight`, `HighlightFields`, `Fields` and `FuzzyLevel` on `SearchQuery` are accepted and ignored. Setting `Sort` also turns off the score ordering, so hits come back in no particular order.
- `ProcessingTime` is a `time.Duration`, so the JSON key `processing_time_ms` carries nanoseconds.
- Disconnecting the in-memory backend drops every index.
- `Health` on the extension reports whether it started. `SearchService.Health` pings the backend.
