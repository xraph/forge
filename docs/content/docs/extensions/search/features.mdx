## Unified Search Interface

Every backend implements the same `Search` interface:

```go
type Search interface {
    Connect(ctx context.Context) error
    Disconnect(ctx context.Context) error
    Ping(ctx context.Context) error
    CreateIndex(ctx context.Context, name string, schema IndexSchema) error
    DeleteIndex(ctx context.Context, name string) error
    ListIndexes(ctx context.Context) ([]string, error)
    GetIndexInfo(ctx context.Context, name string) (*IndexInfo, error)
    Index(ctx context.Context, index string, doc Document) error
    BulkIndex(ctx context.Context, index string, docs []Document) error
    Get(ctx context.Context, index string, id string) (*Document, error)
    Delete(ctx context.Context, index string, id string) error
    Update(ctx context.Context, index string, id string, doc Document) error
    Search(ctx context.Context, query SearchQuery) (*SearchResults, error)
    Suggest(ctx context.Context, query SuggestQuery) (*SuggestResults, error)
    Autocomplete(ctx context.Context, query AutocompleteQuery) (*AutocompleteResults, error)
    Stats(ctx context.Context) (*SearchStats, error)
}
```

The extension calls `Connect` in its `Start` and `Disconnect` in its `Stop`, so you don't call them
yourself.

## Backends

| Driver | Status | Needs |
|---|---|---|
| `inmemory` | Works. Indexes live in process memory and are lost on restart | Nothing |
| `elasticsearch` | Placeholder | `url` or `hosts` to pass validation |
| `meilisearch` | Placeholder | `url` |
| `typesense` | Placeholder | `url` or `hosts`, and `api_key` |

<Callout type="warn">
The three network drivers never contact a server. `Connect` succeeds without dialling, writes return
`nil` and store nothing, `Get` returns `ErrDocumentNotFound`, and `Search`, `Suggest` and
`Autocomplete` return empty results. An app you configure for Elasticsearch starts fine, logs that
it connected, and silently indexes nothing. Use `inmemory`, or wrap your own client behind the
`search.Search` interface.
</Callout>

The in-memory backend keeps a map of indexes, each with a map of documents, behind
`sync.RWMutex` locks, so concurrent handlers can index and search at the same time.

## Index Management

```go
err := s.CreateIndex(ctx, "articles", search.IndexSchema{
    Fields: []search.FieldSchema{
        {Name: "title", Type: "text", Searchable: true},
        {Name: "body", Type: "text", Searchable: true},
        {Name: "author", Type: "keyword", Filterable: true},
    },
})

names, err := s.ListIndexes(ctx)
info, err := s.GetIndexInfo(ctx, "articles") // DocumentCount, CreatedAt, UpdatedAt, Schema
err = s.DeleteIndex(ctx, "articles")
```

`CreateIndex` on a name you already used returns `ErrIndexAlreadyExists`, which you can check with
`errors.Is` if your startup code might run twice. The other calls return `ErrIndexNotFound` for an
index that doesn't exist.

`IndexSchema` has room for field types (`text`, `keyword`, `integer`, `float`, `boolean`, `date`,
`geo_point`), searchable, filterable, sortable and faceted flags, analyzers, synonyms, stop words,
ranking rules and highlighting tags. The in-memory backend stores the schema and returns it from
`GetIndexInfo`, but doesn't read any of it: every field is searched and filterable whatever the
schema says. `IndexInfo.IndexSize` is an estimate of 1 KB per document.

## Document Operations

A document is an `ID` plus `Fields map[string]any`:

```go
// Write or replace one document
err := s.Index(ctx, "articles", search.Document{
    ID:     "article-1",
    Fields: map[string]any{"title": "Getting Started", "body": "...", "author": "Alice"},
})

// Write or replace several
err = s.BulkIndex(ctx, "articles", []search.Document{doc1, doc2, doc3})

// Read by ID
doc, err := s.Get(ctx, "articles", "article-1")

// Replace an existing document
err = s.Update(ctx, "articles", "article-1", search.Document{
    Fields: map[string]any{"title": "Updated Title", "body": "...", "author": "Alice"},
})

// Delete
err = s.Delete(ctx, "articles", "article-1")
```

`Index` and `BulkIndex` write or replace the document with that ID, and you have to create the index
first. `Update` replaces the whole document (it doesn't merge fields), sets its ID to the one you
pass, and returns `ErrDocumentNotFound` if there's nothing to replace. `Get` and `Delete` return
`ErrDocumentNotFound` for an unknown ID. `BulkIndex` writes everything in one call; `bulk_size` in
the config isn't used to split it.

## Full-Text Search

```go
results, err := s.Search(ctx, search.SearchQuery{
    Index:       "articles",
    Query:       "distributed",
    Filters:     []search.Filter{{Field: "author", Operator: "=", Value: "Alice"}},
    BoostFields: map[string]float64{"title": 3},
    MinScore:    1,
    Offset:      0,
    Limit:       20,
})
```

This is what the in-memory backend does with each field of a `SearchQuery`:

| Field | Behaviour |
|---|---|
| `Query` | Lowercased substring match against the string form (`fmt.Sprintf("%v")`) of every field. An empty query matches every document |
| Scoring | Each matching field adds 1, multiplied by its `BoostFields` entry, and doubled when the whole field equals the query. Hits come back highest score first |
| `MinScore` | Drops hits that score below it. An empty query scores 0 |
| `Filters` | All filters must match. See the operator table below |
| `Offset` | Skips that many hits |
| `Limit` | `0` uses `default_limit` (20). Anything above `max_limit` (100) is capped |
| `Sort` | Ignored, and setting it turns off the score ordering, so hits come back in no particular order |
| `Facets`, `Highlight`, `HighlightFields`, `Fields`, `FuzzyLevel`, `Options` | Accepted, not applied. `Facets` and `Highlights` stay empty and every hit carries the whole document |

Filters compare the string form of the value:

| Operator | Matches |
|---|---|
| `=` or `==` | The field exists and equals the value |
| `!=` | The field exists and doesn't equal the value. Documents without the field are dropped |
| `EXISTS` | The field is present |
| `NOT EXISTS` | The field is absent |

Any other operator (`>`, `<`, `IN`, `BETWEEN` and so on) matches nothing, so the search returns no
hits. The comment on `Filter.Operator` lists more operators than the backend supports.

## Search Results

```go
fmt.Printf("found %d results\n", results.Total)
for _, hit := range results.Hits {
    fmt.Printf("  %s (score %.2f) %v\n", hit.ID, hit.Score, hit.Document)
}
```

`SearchResults` has `Hits`, `Total` (matches before paging), `Offset`, `Limit` (the limit actually
applied), `Query`, `ProcessingTime`, `Facets` and `Exhaustive`. The in-memory backend always sets
`Exhaustive` to `true` and leaves `Facets` empty.

<Callout type="warn">
`ProcessingTime` is a Go `time.Duration`, so when you return results as JSON you get a nanosecond
count under the key `processing_time_ms`. The same goes for `SuggestResults`,
`AutocompleteResults` and `SearchStats.AvgLatency` (`avg_latency_ms`).
</Callout>

## Suggestions and Autocomplete

Both look at one field:

```go
// Substring matches anywhere in the field
suggestions, err := s.Suggest(ctx, search.SuggestQuery{
    Index: "articles",
    Field: "title",
    Query: "system",
    Limit: 5,
})

// Prefix matches
completions, err := s.Autocomplete(ctx, search.AutocompleteQuery{
    Index: "articles",
    Field: "title",
    Query: "dist",
    Limit: 10,
})
```

Matching is case-insensitive, duplicates are dropped, and every result has a score of 1. Both
default to 10 results and stop as soon as they have enough, so which matches you get from a larger
set isn't defined. `SuggestQuery.Fuzzy` is accepted and ignored.

## Stats

`Stats` returns `IndexCount`, `DocumentCount`, `TotalSize` (1 KB per document), `Queries` (calls to
`Search`), `Uptime` and `Version`. On the in-memory backend `AvgLatency` is a fixed 5ms, not a
measurement.

## Not Implemented Yet

The config carries connection pooling, retries, timeouts, bulk batching, compression, TLS,
highlighting and facet switches, and metrics and tracing flags. Nothing reads them yet, because the
only working backend runs in process. See [Configuration](/docs/extensions/search/configuration)
for which keys do something today.

## Sentinel Errors

These are the errors the backends return today:

| Error | Returned when |
|---|---|
| `ErrNotConnected` | You call a method before `Connect` or after `Disconnect` |
| `ErrIndexNotFound` | The named index doesn't exist (in-memory) |
| `ErrIndexAlreadyExists` | `CreateIndex` on a name that exists (in-memory) |
| `ErrDocumentNotFound` | `Get`, `Update` or `Delete` on an unknown ID |

`ErrAlreadyConnected`, `ErrInvalidQuery`, `ErrInvalidSchema`, `ErrConnectionFailed`, `ErrTimeout`,
`ErrInvalidConfig`, `ErrUnsupportedDriver` and `ErrOperationFailed` are declared in `errors.go`, but
nothing returns them yet.
