## What works

| You need | What you get |
|---|---|
| A GraphQL endpoint on your router | `GET` and `POST` routes at `endpoint`, registered when the extension starts |
| A browser IDE while you develop | GraphQL Playground at `playground_endpoint`, switched off with `WithPlayground(false)` |
| Protection from expensive queries | gqlgen's fixed complexity limit, from `max_complexity` |
| Smaller requests from repeat clients | Automatic persisted queries, always on |
| File uploads | gqlgen's multipart transport, capped at gqlgen's default of 32MB |
| Federation | Apollo Federation v2 code generated in, including `{ _service { sdl } }` |
| Visibility | Two metrics, debug logs per operation, error logs, and a warning for slow queries |
| N+1 batching in your own resolvers | The `dataloader` package |

## The schema is fixed

The server runs the schema compiled into the module and nothing else. `Query` has `hello(name: String!)` and `version`, `Mutation` has `echo(message: String!)`, and that's it. There's no schema file loading and no schema generation from Go types.

<Callout type="warn">
The `GraphQL` interface has registration methods, but they're placeholders. `RegisterType`, `RegisterQuery`, `RegisterMutation` and `RegisterSubscription` log a debug line and return `nil`, so nothing you register is ever served. `Use(middleware)` does nothing. `ExecuteQuery` returns a `*Response` whose only error says direct execution isn't implemented. `EnableIntrospection` changes a field the running server never reads again.
</Callout>

If you need your own schema now, generate it with gqlgen in your own module and register its handler on a Forge route:

```go
srv := handler.NewDefaultServer(generated.NewExecutableSchema(generated.Config{Resolvers: &Resolver{}}))

err := app.Router().POST("/graphql", func(c forge.Context) error {
	srv.ServeHTTP(c.Response(), c.Request())

	return nil
})
```

Here `generated` and `Resolver` are your own gqlgen output, not this module's.

## Reading the schema

`GenerateSchema()` returns a short SDL listing of the `Query` and `Mutation` fields, and `GetSchema()` returns a `*GraphQLSchema` with `Types`, `Queries`, `Mutations`, `Subscriptions` and `Directives`. Only `Queries`, `Mutations` and `Subscriptions` get filled in, and the query map includes gqlgen's own `_service`, `__schema` and `__type` fields. Both describe the built-in schema.

```go
gql, err := forge.Inject[graphql.GraphQL](app.Container())
if err != nil {
	return err
}

for name, field := range gql.GetSchema().Queries {
	fmt.Println(name, field.Type)
}
```

## Playground

The playground is served with `GET` at `playground_endpoint` (default `/playground`) when `enable_playground` is on. It points at `endpoint`. There's no option for the playground path, so set `playground_endpoint` in your config file if you want a different one.

## Complexity limit

`max_complexity` (default `1000`, option `WithMaxComplexity`) adds gqlgen's `FixedComplexityLimit`. Every field costs one unless gqlgen's generated complexity functions say otherwise. Set it to `0` to turn the limit off.

`max_depth` (`WithMaxDepth`) and `query_timeout` (`WithTimeout`) aren't enforced. They're validated (`max_depth` has to be at least 1, `query_timeout` positive) and then ignored.

## Persisted queries

gqlgen's default server, which the extension starts from, already turns on automatic persisted queries with a 100-entry LRU cache and keeps a 1000-entry cache of parsed queries. That's why APQ works even with `enable_query_cache: false`.

With `enable_query_cache` on (the default), the extension adds a second APQ cache of `max_cache_size` entries. A lookup by hash goes to the first cache, so the 100-entry one decides whether a hash is found. `query_cache_ttl` isn't read.

## File uploads

gqlgen's multipart transport handles `multipart/form-data` requests. The default server registers one with gqlgen's 32MB limit before the extension adds its own with `max_upload_size`, and the first one wins, so `max_upload_size` doesn't change the limit today.

## Observability

With `enable_metrics` on and a metrics sink in the container, every operation records:

| Metric | Type | Labels |
|---|---|---|
| `graphql_operation_duration_seconds` | histogram | `operation`, `type` |
| `graphql_operation_total` | counter | `operation`, `type` |

With `enable_logging` on, each operation gets a debug line when it starts and when it finishes, and every GraphQL error in a response is logged at error level with the operation name and path.

With `log_slow_queries` on, an operation slower than `slow_query_threshold` (default `1s`) logs a warning with its duration and raw query. The slow query check is installed with the metrics and logging hooks, so it only runs when `enable_metrics` or `enable_logging` is on.

`enable_tracing` (`WithTracing`) isn't read. There's no tracing.

## Federation

The module's `gqlgen.yml` generates Apollo Federation v2 support, so `{ _service { sdl } }` returns the built-in schema's SDL. The schema has no `@key` types, so there are no entity resolvers. `FederationConfig` and `DefaultFederationConfig()` exist but nothing reads them, and there's no option that turns federation on or off.

## The @auth directive

The schema declares `@auth(requires: String)`, and the `directives` package has an `Auth` function that checks `ctx.Value("user")` and a `[]string` of roles under `ctx.Value("roles")`. Nothing wires it into the server and no field uses it, so it has no effect today.

## CORS

`enable_cors` and `allowed_origins` (`WithCORS`) aren't read. If browsers on other origins call your endpoint, handle CORS in front of it, for example with `middleware.CORS` from `github.com/xraph/forge/middleware`.

## Batch lookups with DataLoader

The `dataloader` package works on its own, whether or not you use the extension. A `Loader` collects the keys concurrent callers ask for during a short wait window, calls your batch function once with all of them, and caches the results:

```go
users := dataloader.NewLoader(dataloader.DefaultLoaderConfig(),
	func(ctx context.Context, keys []any) ([]any, []error) {
		// One query for every key collected in this window.
		values := make([]any, len(keys))
		for i, k := range keys {
			values[i] = fmt.Sprintf("user-%v", k)
		}

		return values, make([]error, len(keys))
	})

user, err := users.Load(ctx, 42)
```

Your batch function has to return a value slice and an error slice that line up with `keys`, one entry per key, or the wrong caller gets the wrong value. `DefaultLoaderConfig()` waits 10ms (`Wait`) and sets `MaxBatch` to 100. `Prime(key, value)`, `Clear(key)` and `ClearAll()` manage the cache.

`LoadMany` calls `Load` for one key after another, so it waits a full window per key and doesn't batch. Call `Load` from concurrent resolvers if you want the batching. Create one `Loader` per request, because the cache never expires.

The `enable_dataloader`, `dataloader_batch_size` and `dataloader_wait` config keys aren't connected to this package. Pass a `LoaderConfig` yourself.

## Sentinel errors

The package exports these, but the server doesn't return any of them today:

| Error | Message |
|---|---|
| `ErrNotInitialized` | `graphql: not initialized` |
| `ErrInvalidQuery` | `graphql: invalid query` |
| `ErrInvalidSchema` | `graphql: invalid schema` |
| `ErrTypeNotFound` | `graphql: type not found` |
| `ErrResolverNotFound` | `graphql: resolver not found` |
| `ErrExecutionFailed` | `graphql: execution failed` |
| `ErrComplexityExceeded` | `graphql: query complexity exceeded` |
| `ErrDepthExceeded` | `graphql: query depth exceeded` |
| `ErrTimeout` | `graphql: query timeout` |
| `ErrInvalidConfig` | `graphql: invalid configuration` |

Config validation returns plain errors such as `max_depth must be at least 1`, and registration wraps them as `graphql config validation failed: ...`. A query over the complexity limit comes back as a normal GraphQL error from gqlgen.
