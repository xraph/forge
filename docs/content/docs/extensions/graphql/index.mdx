## Overview

`github.com/xraph/forge/extensions/graphql` runs a [gqlgen](https://gqlgen.com/) server inside your app and mounts it on the Forge router. You get a GraphQL endpoint, a GraphQL Playground, a query complexity limit, automatic persisted queries, Apollo Federation's `_service` query, two Forge metrics and slow query logging. The module also ships a small `dataloader` package for batching N+1 lookups in your own resolvers.

<Callout type="warn">
The server only runs the schema compiled into the module (`hello`, `version` and `echo`). You can't hand it your own schema or resolvers yet: `RegisterQuery`, `RegisterMutation`, `RegisterType` and `RegisterSubscription` only write a debug log line, `Use` does nothing, and `ExecuteQuery` returns an error response. If you need your own schema today, run gqlgen in your own module and mount its `handler.Server` on a Forge route, the same way the extension does.
</Callout>

## Quick start

You need Go 1.26 or later. Add Forge and the extension:

```bash
go get github.com/xraph/forge@latest
go get github.com/xraph/forge/extensions/graphql@latest
```

Save this as `main.go`:

```go
package main

import (
	"log"

	"github.com/xraph/forge"
	"github.com/xraph/forge/extensions/graphql"
)

func main() {
	app := forge.NewApp(forge.AppConfig{
		Name:        "graphql-demo",
		HTTPAddress: ":8080",
		Extensions: []forge.Extension{
			graphql.NewExtension(
				graphql.WithEndpoint("/graphql"),
				graphql.WithPlayground(true),
			),
		},
	})

	if err := app.Run(); err != nil {
		log.Fatal(err)
	}
}
```

Run it with `go mod tidy && go run .`, then send a query:

```bash
curl -X POST http://localhost:8080/graphql \
  -H 'Content-Type: application/json' \
  -d '{"query":"{ hello(name: \"Forge\") version }"}'
# {"data":{"hello":"Hello, Forge!","version":"2.0.0"}}
```

Open `http://localhost:8080/playground` in a browser for the playground. The endpoint answers `GET` too, so `curl -G localhost:8080/graphql --data-urlencode 'query={ version }'` works.

## The built-in schema

This is everything the server answers today, from `schema/schema.graphql` in the module:

```graphql
directive @auth(requires: String) on FIELD_DEFINITION

type Query {
  hello(name: String!): String!
  version: String!
}

type Mutation {
  echo(message: String!): String!
}
```

Federation v2 code is generated in, so `{ _service { sdl } }` returns that SDL. There are no entities and no subscriptions.

## What it registers

| Service | How you resolve it | Type |
|---|---|---|
| GraphQL service | `forge.Inject[*graphql.GraphQLService](c)`, or the name `graphql` | `*GraphQLService` |
| GraphQL interface | `forge.Inject[graphql.GraphQL](c)` | `GraphQL`, backed by the same instance |

When the extension starts, it adds these routes to the Forge router:

- `POST` and `GET` on `endpoint` (default `/graphql`)
- `GET` on `playground_endpoint` (default `/playground`), only when `enable_playground` is on

Behind the endpoint, gqlgen's WebSocket, `GET`, `POST`, `OPTIONS` and multipart transports are registered. The schema has no subscriptions, so the WebSocket transport has nothing to stream.

## Runtime notes

- Routes are registered in `Start()`, not in `Register()`.
- Introspection is always on. `WithIntrospection(false)` and `enable_introspection: false` don't change that.
- The complexity limit (`max_complexity`, default `1000`) is enforced. Depth limits and the query timeout aren't: `max_depth` and `query_timeout` are validated and then ignored.
- Slow query logging warns about operations slower than `slow_query_threshold` (default `1s`), as long as metrics or logging is on.
- `GenerateSchema()` and `GetSchema()` work. They describe the built-in schema.
