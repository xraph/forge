# Forge Telemetry - Internal Implementation

## Purpose

OpenTelemetry tracing for Forge apps. It resolves the tracing config, builds the shared resource, the sampler and the tracer provider, and provides the HTTP server middleware that gives every request a span. `forge.New` builds one `Provider` per app (`buildTracing` in `app_impl.go`) and the public wrappers live in the root `tracing.go`.

## Key Components

- **config.go**: `Resolve(Inputs) Settings`, the precedence chain and the `OTEL_*` parsing.
- **resource.go**: `BuildResource`, the one resource every signal shares.
- **sampler.go**: `BuildSampler`, maps a sampler name to an SDK sampler.
- **provider.go**: `NewProvider`, `Provider.RegisterSpanProcessor`, `Provider.Shutdown`.
- **server.go**: `ServerMiddleware`, `PropagationMiddleware`, `RouteMatchMiddleware`, `NormalizeMethod`, `Excluded` (the path-prefix check, shared with the HTTP server metrics middleware).
- **client.go**: `InstrumentTransport`, `HTTPClient`.
- **recorder.go**: `StatusRecorder` (`NewStatusRecorder`), captures the status and body bytes (`Status`, `BytesWritten`) and keeps Flusher, Hijacker and Unwrap working. The HTTP server metrics middleware in `internal/metrics/collectors` uses it too. A 1xx other than 101 is forwarded but not recorded, so 103 Early Hints never becomes the final status. Flush and Hijack go through `http.ResponseController`, so a wrapper below that only has `Unwrap` still works; a failed hijack returns the controller's error (wrapping `http.ErrNotSupported`) and records nothing, a successful one records 101.
- **errorhandler.go**: the OTel error handler, rate limited to one warn per minute through `logger.RateLimited` (`internal/logger/ratelimit.go`, shared with the profiler's upload errors).
- **labels.go**: `serveLabelled` and `spanName`, the pprof span labels for profiling.
- **metrics_config.go**: `ResolveMetrics(MetricsInputs) MetricsSettings`, the precedence chain for metrics push.
- **metrics.go**: `NewMetricsPusher`, `MetricsPusher`, the OTLP/HTTP metrics push.

## Precedence

For every setting the first source that has a value wins:

1. Code: `forge.WithAppTracingConfig` (`Inputs.Code`)
2. Forge config, the `tracing` key bound with `ConfigManager.Bind` (`Inputs.File`)
3. `OTEL_*` environment variables, read through `Inputs.Getenv`
4. Defaults

`Enabled` and `SampleRatio` are pointers in `shared.TracingConfig` so that `false` and `0` count as set. `ResponseHeader` is a pointer so `""` can turn the header off.

## Settings

| Field | Source and default |
|---|---|
| `Enabled` | code, file, `OTEL_SDK_DISABLED=true` (false), default true |
| `Endpoint` | code, file, `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` (as is), `OTEL_EXPORTER_OTLP_ENDPOINT` + `/v1/traces`; empty means no export |
| `Headers` | code, file, `OTEL_EXPORTER_OTLP_TRACES_HEADERS`, `OTEL_EXPORTER_OTLP_HEADERS` (comma separated `k=v`, values percent-decoded) |
| `SamplerName` | `OTEL_TRACES_SAMPLER` if supported, else `parentbased_traceidratio` |
| `SampleRatio` | code, file, `OTEL_TRACES_SAMPLER_ARG` (only for `*traceidratio` samplers, default 1.0), else 1.0 for environment "", development, dev, local, test and 0.1 otherwise |
| `Propagators` | code, file, `OTEL_PROPAGATORS`, default `tracecontext`, `baggage` |
| `ExcludePaths` | code, file, default `"/_/"` |
| `ResponseHeader` | code, file, default `traceparent`; empty string disables it |
| `Resource` | code, file; merged over the detected resource |
| `SpanLabels` | never set by `Resolve`; `forge.New` copies it from `profiling.Settings.SpanLabels` |
| `Warnings` | messages for the caller to log (unsupported sampler, an `OTEL_TRACES_SAMPLER_ARG` that is not a number, NaN or out of range ratio) |

A code or file `SampleRatio` always pairs with `parentbased_traceidratio` and ignores `OTEL_TRACES_SAMPLER`. A ratio outside [0, 1] is clamped with a warning; NaN falls back to the environment default.

Resource order, later wins: `service.name` (app name), `deployment.environment.name`, `service.version`, host and process detectors, telemetry SDK, `OTEL_SERVICE_NAME` and `OTEL_RESOURCE_ATTRIBUTES` (`WithFromEnv`), then `Settings.Resource`. A partial detector failure is a warning, not an error.

## Server middleware

`ServerMiddleware(tp, settings)` goes in the router's outer slot (`internalrouter.UseOuterMiddleware`), so it runs ahead of every `UseGlobal` middleware with no forge Context of its own, and only when `Settings.Enabled` is true. When tracing is off, `PropagationMiddleware()` goes in its place. It extracts the incoming context with the global propagator and does nothing else: no span, no `RouteMatch`, no response header. That's what lets an incoming `traceparent` reach `HTTPClient` calls in an app with tracing disabled. If metrics are on and `features.http_metrics` is off as well, nothing else would install a `RouteMatch`, so `forge.New` adds `RouteMatchMiddleware(settings.ExcludePaths)` after it. That one only calls `shared.NewRouteMatch`, which is all the router's stream observer needs to name a stream. It skips excluded paths the same way the other two do, so a stream under `/_/` isn't recorded in any configuration.

Per request the middleware keeps its state in one `serverSpan` struct: the status recorder and the span start options, with `finish` and `recoverPanic` as methods, so nothing gets a closure of its own. The request attributes (`http.request.method`, `url.scheme`, `url.path`, `network.protocol.version`, `http.request.method_original`, `server.address`, `user_agent.original`, and `pyroscope.profile.id` on a labelled request) are captured as strings at start and set when the span ends, in that order and before the route and status attributes, so an unsampled request never builds or copies them. `recoverPanic` sets them too. The exported span is the same as when they were set at start, but a sampler or a span processor's `OnStart` doesn't see them; none of forge's samplers read attributes. `traceparentIDs` formats the response `traceparent` once and slices the trace and span IDs out of it. Span names come from `spanNames`, a copy-on-write cache keyed by method and route (1024 entries, then built per request), which `spanName` in labels.go shares so the profiler's `span_name` label always matches. `headerCarrier` stands in for `propagation.HeaderCarrier` on extract: it maps `traceparent`, `tracestate` and `baggage` to their canonical keys, because `http.Header.Get` allocates a canonicalized copy of a lowercase key on every lookup. `TestServerMiddlewareAllocations` holds a sampled request to 13 allocations; 2 of those are the go-utils log context node that carries the trace and span IDs.

For each request, `ServerMiddleware` does this:

1. A path starting with any `ExcludePaths` prefix skips tracing entirely.
2. It extracts the incoming context with the global propagator, then calls `shared.NewRouteMatch(ctx)`. The router fills the `shared.RouteMatch` holder with the matched pattern, so the middleware can read it after `next` returns even though the match happens inside the router. `NewRouteMatch` always installs a fresh holder. A handler that dispatches a second request through the router with its own context (the orpc extension does this) would otherwise share the outer holder, and the inner route would rename the outer span. Inner middleware that wants the pattern calls `shared.EnsureRouteMatch` to share the holder the outermost one made.
3. It starts a span named after the method (`_OTHER` methods are named `HTTP`) with `SpanKindServer`. After the handler returns, the span is renamed `METHOD pattern` and `http.route` is set, but only if a pattern matched.
4. It puts `trace_id` and `span_id` on the context through `logger.WithTraceID` and `logger.WithSpanID`, so a request-scoped logger writes them on every line.
5. It writes `ResponseHeader` (default `traceparent`) before calling the handler. The value is built straight from the span context by `traceparent()`, the same bytes `propagation.TraceContext` would inject, without the carrier map. `TestServerResponseHeaderMatchesTraceContext` holds the two together.
6. 5xx sets status Error and `error.type`. A panic that escapes records the error with a stack trace, ends the span, and re-panics.
7. On a stream route (WebSocket, SSE, WebTransport) the span ends at the handshake, not when the handler returns. The middleware registers its finish function with `match.OnEstablished` before calling `next`. The router stamps `RouteMatch.Kind` and calls `RouteMatch.Establish(status)` after the WebSocket upgrade (101), once an `EventStream` is writable (200), right before an `SSE()` handler (200) and after the WebTransport upgrade (200). `finish` then names the span, sets the attributes plus `forge.stream.kind` (`Kind.String()`: `sse`, `websocket`, `webtransport`) and ends it. After `next` returns, `match.Established()` is true and the middleware does nothing more; a panic after that re-panics without touching the ended span. Spans started from the request context afterwards are children of the ended span. A rejected upgrade (a 403 for a bad Origin) never calls `Establish`, so it ends like any other request. The router has already stamped `Kind` by then, so `finish` adds `forge.stream.kind` only when `match.Established()` is true; a rejected upgrade's span carries no stream kind. Forge can't currently complete a WebTransport upgrade (a known issue, being fixed separately), so WebTransport stream spans won't appear until it can. `Establish` runs its callbacks once, on the request goroutine, so the holder needs no locking.

The router records errors on the span itself: `internal/router/span_error.go` wraps the error handler (`wrapSpanErrors`) and records any error that maps to a 5xx, and the recovery wrapper in `router_impl.go` records recovered panics with `recordSpanPanic`, which adds a stack trace. The 5xx error path records no stack. 4xx errors are not recorded.

### Span attribute keys

Set at start: `http.request.method`, `url.scheme`, `url.path`, `network.protocol.version`, `server.address`, `user_agent.original`, and `http.request.method_original` when the method is outside the standard nine (the method attribute is then `_OTHER`).

Set at end, in one `SetAttributes` call: `http.route` (when matched), `forge.stream.kind` (stream routes that established only), `http.response.status_code`, and `error.type` (the status code as a string) for 5xx. An unsampled span isn't recording, so the middleware skips the rename, the attributes and the status and just ends it.

### Span labels

With `Settings.SpanLabels` on and a sampled span, the middleware sets `pyroscope.profile.id` (the span ID) on the span and serves the request through `serveLabelled`. The names match `grafana/otel-profiling-go`, so Grafana's Tempo "Profiles for this span" works without that module. Labels off or an unsampled span cost the bool and `IsSampled` checks and nothing else; excluded paths get no span and no labels.

`serveLabelled` runs `next` inside `pprof.Do(ctx, pprof.Labels("span_id", id), ...)` and hands the labelled context to the request. Two callbacks on the `RouteMatch`:

- `OnMatched` relabels the goroutine with `span_name` added, built by `spanName(method, pattern)` from the same cache the span rename uses, so the label equals the span's final name. `_OTHER` methods give `HTTP`. The router calls `Match` before the route's middleware, so route middleware runs labelled.
- `OnEstablished` relabels a stream route's goroutine to `span_name` only (no labels at all when no pattern matched). The span ends at the handshake while the handler can run for hours, and that CPU must not land on the span.

When `next` returns, panics included, `pprof.Do` sets the goroutine's labels to the ones on `ctx`. That isn't always what the goroutine had before (a label set on the goroutine and never put on `ctx` is gone), but it means nothing leaks into the next request `net/http` serves on that goroutine.

`span_name` lives only on the goroutine, not on the request context. A handler or middleware that adds its own labels with `pprof.Do(r.Context(), ...)` loses `span_name` inside that `Do` and for the rest of the request after it returns, because `Do` restores the context's labels and the context only has `span_id`. `span_id`, the trace link, survives. Labels reach CPU and goroutine profiles only, and goroutines a handler starts inherit them while an existing worker pool does not.

Tests read labels from `pprof.Lookup("goroutine").WriteTo(buf, 1)`, the handler's own `# labels:` line, since CPU sampling is too flaky to assert on.

## Provider lifecycle

- `NewProvider` installs the propagator and the tracer provider as the OTel globals and sets the rate limited error handler. With no endpoint it still records spans, so processors added later see them.
- A disabled config gives a `noop` provider, still installed as the global along with the propagator, and `RegisterSpanProcessor` returns `ErrTracingDisabled`.
- The endpoint must be an `http` or `https` URL with a host, or `NewProvider` returns an error wrapping `ErrInvalidEndpoint`. `buildTracing` logs one error, clears the endpoint and builds again without an exporter, so a bad endpoint never stops the app booting.
- Export is OTLP over HTTP/protobuf (`otlptracehttp`) only, through a batching span processor.
- Shutdown happens in `app.Stop` (`app_impl.go`), as the last step after extensions and the container have stopped, so their final spans are flushed. `Provider.Shutdown` waits at most five seconds.
- The provider is in DI as `trace.TracerProvider`.

## Process globals

`forge.New` takes over the OpenTelemetry globals: tracer provider, propagator and error handler. Consumers feel this in two ways.

- An app that set up its own tracer provider in code before `forge.New` loses it. Forge replaces it, and spans from `otel.Tracer(...)` go to Forge's provider, which exports only when an endpoint is configured. With tracing disabled, `NewProvider` still installs a `noop` provider and the propagator as globals, so an app that wants to keep its own provider sets it up after `forge.New`.
- An app that already runs its own `otelhttp` server middleware gets two server spans per request. It should remove its own, or turn forge's off with `tracing.enabled: false`.

With more than one forge app in a process, the last one built wins the tracer provider, the `propagators` setting and the error handler. The error handler is set when tracing is on, and also when a metrics pusher is built. `forge.StartSpan` reads the globals on every call, so it follows the last app. Each app's own request spans still go to that app's provider because `ServerMiddleware` is handed it directly.

`InstrumentTransport` and `HTTPClient` capture the provider and propagator that are current when you call them. A client built before any `forge.New` still traces: OTel's global delegate forwards to the first provider set. In a process with several apps a client stays with whichever provider was current when it was built.

## Metrics push

`ResolveMetrics` in metrics_config.go works the way `Resolve` does: code (`forge.WithAppMetricsExportConfig`), then the forge config `metrics_export` key, then `OTEL_*` env, then defaults. `MetricsPusher` in metrics.go does the pushing.

| Field | Source and default |
|---|---|
| `Endpoint` | code, file, `OTEL_EXPORTER_OTLP_METRICS_ENDPOINT` (as is), `OTEL_EXPORTER_OTLP_ENDPOINT` + `/v1/metrics`; empty means no push |
| `Headers` | code, file, `OTEL_EXPORTER_OTLP_METRICS_HEADERS`, `OTEL_EXPORTER_OTLP_HEADERS` |
| `Interval` | code, file, `OTEL_METRIC_EXPORT_INTERVAL` (milliseconds), default 60s; a bad env value is a warning |
| `Temporality` | code, file, `OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE`; `cumulative` (default) or `delta` (`lowmemory` counts as delta) |
| `Enabled` | an explicit false in code or file wins; otherwise `OTEL_SDK_DISABLED=true` or `OTEL_METRICS_EXPORTER=none` turn it off; otherwise it needs an endpoint. An explicit true with no endpoint is a warning |

`NewMetricsPusher(ctx, settings, res, producer, log)` checks the endpoint with `validateEndpoint` (an `http` or `https` URL with a host, or an error wrapping `ErrInvalidEndpoint`), builds an `otlpmetrichttp` exporter and wraps it in a periodic reader that pulls from `producer`. The pusher doesn't read `Settings.Temporality`: delta versus cumulative is decided by the producer (the `OTLPConfig` handed to the metrics collector), so pass that same value there. Pass the shared resource from `BuildResource` so metrics and traces carry the same `service.name`. A `nil` resource uses the SDK default. The exporter still reads its own `OTEL_EXPORTER_OTLP_METRICS_*` variables for what the settings don't cover: timeout, compression, TLS certificates.

The `MeterProvider` inside the pusher is private. Nothing calls `otel.SetMeterProvider`, so `otel.Meter(...)` in your own code never reaches it, and only what the producer returns is pushed. That's what keeps a push identical to a scrape. Don't install it as the global.

`Shutdown` runs one last collect and export, capped at `shutdownCap` (five seconds) or the caller's context, whichever ends first. A nil pusher returns nil, so the app can call it without checking whether push was on.

Constructing a pusher also installs the rate limited OTel error handler (`otel.SetErrorHandler`), so a collector that is down logs one warn a minute even with tracing off. Like the tracer provider, the last one set wins.

Tests: run the pusher against an `httptest` server that decodes the body into `metricspb.MetricsData`. That has the wire shape of an export request, so the collector package and its gRPC dependency stay out of the build. Set `Interval` to an hour and let `Shutdown` do the export.

## Public API (root `tracing.go`)

```go
type TracingConfig = shared.TracingConfig
var ErrTracingDisabled = telemetry.ErrTracingDisabled

func StartSpan(ctx context.Context, name string, opts ...trace.SpanStartOption) (context.Context, trace.Span)
func SpanFromContext(ctx context.Context) trace.Span

func InstrumentTransport(rt http.RoundTripper) http.RoundTripper // nil means http.DefaultTransport
func RegisterSpanProcessor(a App, sp sdktrace.SpanProcessor) error // needs an App from forge.New

func WithAppTracingConfig(config TracingConfig) AppOption // app.go
```

## Testing

- Use `sdktrace` with a `tracetest.SpanRecorder` and pass the tracer provider straight to `ServerMiddleware`; no global state is needed.
- `Resolve` takes `Getenv`, so tests never touch the real environment.
- Tests that call `NewProvider` or `forge.New` change the OTel globals; restore them in `t.Cleanup`.
