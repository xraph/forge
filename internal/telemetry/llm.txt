# Forge Telemetry - Internal Implementation

## Purpose

OpenTelemetry tracing for Forge apps. It resolves the tracing config, builds the shared resource, the sampler and the tracer provider, and provides the HTTP server middleware that gives every request a span. `forge.New` builds one `Provider` per app (`buildTracing` in `app_impl.go`) and the public wrappers live in the root `tracing.go`.

## Key Components

- **config.go**: `Resolve(Inputs) Settings`, the precedence chain and the `OTEL_*` parsing.
- **resource.go**: `BuildResource`, the one resource every signal shares.
- **sampler.go**: `BuildSampler`, maps a sampler name to an SDK sampler.
- **provider.go**: `NewProvider`, `Provider.RegisterSpanProcessor`, `Provider.Shutdown`.
- **server.go**: `ServerMiddleware`, `PropagationMiddleware`, `RouteMatchMiddleware`, `NormalizeMethod`, `Excluded` (the path-prefix check, shared with the HTTP server metrics middleware).
- **client.go**: `InstrumentTransport`, `HTTPClient`.
- **recorder.go**: `StatusRecorder` (`NewStatusRecorder`), captures the status and body bytes (`Status`, `BytesWritten`) and keeps Flusher, Hijacker and Unwrap working. The HTTP server metrics middleware in `internal/metrics/collectors` uses it too. A 1xx other than 101 is forwarded but not recorded, so 103 Early Hints never becomes the final status. Flush and Hijack go through `http.ResponseController`, so a wrapper below that only has `Unwrap` still works; a failed hijack returns the controller's error (wrapping `http.ErrNotSupported`) and records nothing, a successful one records 101.
- **errorhandler.go**: the OTel error handler, rate limited to one warn per minute.

## Precedence

For every setting the first source that has a value wins:

1. Code: `forge.WithAppTracingConfig` (`Inputs.Code`)
2. Forge config, the `tracing` key bound with `ConfigManager.Bind` (`Inputs.File`)
3. `OTEL_*` environment variables, read through `Inputs.Getenv`
4. Defaults

`Enabled` and `SampleRatio` are pointers in `shared.TracingConfig` so that `false` and `0` count as set. `ResponseHeader` is a pointer so `""` can turn the header off.

## Settings

| Field | Source and default |
|---|---|
| `Enabled` | code, file, `OTEL_SDK_DISABLED=true` (false), default true |
| `Endpoint` | code, file, `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` (as is), `OTEL_EXPORTER_OTLP_ENDPOINT` + `/v1/traces`; empty means no export |
| `Headers` | code, file, `OTEL_EXPORTER_OTLP_TRACES_HEADERS`, `OTEL_EXPORTER_OTLP_HEADERS` (comma separated `k=v`, values percent-decoded) |
| `SamplerName` | `OTEL_TRACES_SAMPLER` if supported, else `parentbased_traceidratio` |
| `SampleRatio` | code, file, `OTEL_TRACES_SAMPLER_ARG` (only for `*traceidratio` samplers, default 1.0), else 1.0 for environment "", development, dev, local, test and 0.1 otherwise |
| `Propagators` | code, file, `OTEL_PROPAGATORS`, default `tracecontext`, `baggage` |
| `ExcludePaths` | code, file, default `"/_/"` |
| `ResponseHeader` | code, file, default `traceparent`; empty string disables it |
| `Resource` | code, file; merged over the detected resource |
| `Warnings` | messages for the caller to log (unsupported sampler, an `OTEL_TRACES_SAMPLER_ARG` that is not a number, NaN or out of range ratio) |

A code or file `SampleRatio` always pairs with `parentbased_traceidratio` and ignores `OTEL_TRACES_SAMPLER`. A ratio outside [0, 1] is clamped with a warning; NaN falls back to the environment default.

Resource order, later wins: `service.name` (app name), `deployment.environment.name`, `service.version`, host and process detectors, telemetry SDK, `OTEL_SERVICE_NAME` and `OTEL_RESOURCE_ATTRIBUTES` (`WithFromEnv`), then `Settings.Resource`. A partial detector failure is a warning, not an error.

## Server middleware

`ServerMiddleware(tp, settings)` is registered with `router.UseGlobal` so it is the outermost global middleware, and only when `Settings.Enabled` is true. When tracing is off, `PropagationMiddleware()` goes in its place. It extracts the incoming context with the global propagator and does nothing else: no span, no `RouteMatch`, no response header. That's what lets an incoming `traceparent` reach `HTTPClient` calls in an app with tracing disabled. If metrics are on and `features.http_metrics` is off as well, nothing else would install a `RouteMatch`, so `forge.New` adds `RouteMatchMiddleware()` after it. That one only calls `shared.NewRouteMatch`, which is all the router's stream observer needs to name a stream.

For each request, `ServerMiddleware` does this:

1. A path starting with any `ExcludePaths` prefix skips tracing entirely.
2. It extracts the incoming context with the global propagator, then calls `shared.NewRouteMatch(ctx)`. The router fills the `shared.RouteMatch` holder with the matched pattern, so the middleware can read it after `next` returns even though the match happens inside the router. `NewRouteMatch` always installs a fresh holder. A handler that dispatches a second request through the router with its own context (the orpc extension does this) would otherwise share the outer holder, and the inner route would rename the outer span. Inner middleware that wants the pattern calls `shared.EnsureRouteMatch` to share the holder the outermost one made.
3. It starts a span named after the method (`_OTHER` methods are named `HTTP`) with `SpanKindServer`. After the handler returns, the span is renamed `METHOD pattern` and `http.route` is set, but only if a pattern matched.
4. It puts `trace_id` and `span_id` on the context through `logger.WithTraceID` and `logger.WithSpanID`, so a request-scoped logger writes them on every line.
5. It writes `ResponseHeader` (default `traceparent`) before calling the handler. The value is built straight from the span context by `traceparent()`, the same bytes `propagation.TraceContext` would inject, without the carrier map. `TestServerResponseHeaderMatchesTraceContext` holds the two together.
6. 5xx sets status Error and `error.type`. A panic that escapes records the error with a stack trace, ends the span, and re-panics.

The router records errors on the span itself: `internal/router/span_error.go` wraps the error handler (`wrapSpanErrors`) and records any error that maps to a 5xx, and the recovery wrapper in `router_impl.go` records recovered panics with `recordSpanPanic`, which adds a stack trace. The 5xx error path records no stack. 4xx errors are not recorded.

### Span attribute keys

Set at start: `http.request.method`, `url.scheme`, `url.path`, `network.protocol.version`, `server.address`, `user_agent.original`, and `http.request.method_original` when the method is outside the standard nine (the method attribute is then `_OTHER`).

Set at end, in one `SetAttributes` call: `http.route` (when matched), `http.response.status_code`, and `error.type` (the status code as a string) for 5xx. An unsampled span isn't recording, so the middleware skips the rename, the attributes and the status and just ends it.

## Provider lifecycle

- `NewProvider` installs the propagator and the tracer provider as the OTel globals and sets the rate limited error handler. With no endpoint it still records spans, so processors added later see them.
- A disabled config gives a `noop` provider, still installed as the global along with the propagator, and `RegisterSpanProcessor` returns `ErrTracingDisabled`.
- The endpoint must be an `http` or `https` URL with a host, or `NewProvider` returns an error wrapping `ErrInvalidEndpoint`. `buildTracing` logs one error, clears the endpoint and builds again without an exporter, so a bad endpoint never stops the app booting.
- Export is OTLP over HTTP/protobuf (`otlptracehttp`) only, through a batching span processor.
- Shutdown happens in `app.Stop` (`app_impl.go`), as the last step after extensions and the container have stopped, so their final spans are flushed. `Provider.Shutdown` waits at most five seconds.
- The provider is in DI as `trace.TracerProvider`.

## Process globals

`forge.New` takes over the OpenTelemetry globals: tracer provider, propagator and error handler. Consumers feel this in two ways.

- An app that set up its own tracer provider in code before `forge.New` loses it. Forge replaces it, and spans from `otel.Tracer(...)` go to Forge's provider, which exports only when an endpoint is configured. With tracing disabled, `NewProvider` still installs a `noop` provider and the propagator as globals, so an app that wants to keep its own provider sets it up after `forge.New`.
- An app that already runs its own `otelhttp` server middleware gets two server spans per request. It should remove its own, or turn forge's off with `tracing.enabled: false`.

With more than one forge app in a process, the last one built wins the tracer provider, the `propagators` setting and the error handler. The error handler is only set when tracing is on. `forge.StartSpan` reads the globals on every call, so it follows the last app. Each app's own request spans still go to that app's provider because `ServerMiddleware` is handed it directly.

`InstrumentTransport` and `HTTPClient` capture the provider and propagator that are current when you call them. A client built before any `forge.New` still traces: OTel's global delegate forwards to the first provider set. In a process with several apps a client stays with whichever provider was current when it was built.

## Public API (root `tracing.go`)

```go
type TracingConfig = shared.TracingConfig
var ErrTracingDisabled = telemetry.ErrTracingDisabled

func StartSpan(ctx context.Context, name string, opts ...trace.SpanStartOption) (context.Context, trace.Span)
func SpanFromContext(ctx context.Context) trace.Span
func HTTPClient() *http.Client
func InstrumentTransport(rt http.RoundTripper) http.RoundTripper // nil means http.DefaultTransport
func RegisterSpanProcessor(a App, sp sdktrace.SpanProcessor) error // needs an App from forge.New

func WithAppTracingConfig(config TracingConfig) AppOption // app.go
```

## Testing

- Use `sdktrace` with a `tracetest.SpanRecorder` and pass the tracer provider straight to `ServerMiddleware`; no global state is needed.
- `Resolve` takes `Getenv`, so tests never touch the real environment.
- Tests that call `NewProvider` or `forge.New` change the OTel globals; restore them in `t.Cleanup`.
