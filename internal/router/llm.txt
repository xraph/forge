# Forge Router - Internal Implementation

## Purpose

High-performance HTTP router implementation for Forge providing fast route matching, automatic OpenAPI/AsyncAPI generation, streaming support (WebSocket, SSE, WebTransport), middleware composition, and controller-based organization. Built on top of uptrace/bunrouter with extensive enhancements for production use.

## Key Components

- **Route Registration**: HTTP methods (GET, POST, PUT, DELETE, etc.) with path parameters
- **Route Matching**: Trie-based fast path matching with wildcard and parameter support
- **OpenAPI Generation**: Automatic OpenAPI 3.x spec generation from route metadata
- **AsyncAPI Generation**: AsyncAPI 2.x/3.x spec for streaming and event endpoints
- **Streaming**: WebSocket, Server-Sent Events (SSE), and WebTransport support
- **Middleware Chain**: Composable middleware with proper execution order
- **Controller System**: Organize related routes into controllers
- **Route Groups**: Nested route grouping with inherited middleware
- **Route Metadata**: Tags, descriptions, security, parameters for documentation

## Public API

### Core Types

```go
type Router interface {
    // HTTP Methods
    GET(path string, handler any, opts ...RouteOption) error
    POST(path string, handler any, opts ...RouteOption) error
    PUT(path string, handler any, opts ...RouteOption) error
    DELETE(path string, handler any, opts ...RouteOption) error
    PATCH(path string, handler any, opts ...RouteOption) error
    
    // Route Groups
    Group(prefix string, opts ...GroupOption) Router
    
    // Middleware
    Use(middleware ...Middleware)
    
    // Controllers
    RegisterController(controller Controller) error
    
    // Streaming
    WebSocket(path string, handler WebSocketHandler, opts ...RouteOption) error
    EventStream(path string, handler SSEHandler, opts ...RouteOption) error
    WebTransport(path string, handler WebTransportHandler, opts ...RouteOption) error
    
    // Inspection
    Routes() []RouteInfo
    RouteByName(name string) (RouteInfo, bool)
    
    // Spec Generation
    OpenAPISpec() *OpenAPISpec
    AsyncAPISpec() *AsyncAPISpec
    
    // HTTP Server
    ServeHTTP(w http.ResponseWriter, r *http.Request)
    Handler() http.Handler
}

type RouteOption interface {
    Apply(*RouteConfig)
}

type RouteConfig struct {
    Name         string
    Description  string
    Summary      string
    Tags         []string
    Security     []SecurityRequirement
    Deprecated   bool
    Metadata     map[string]interface{}
}
```

## Usage Examples

### Basic Route Registration

```go
import "github.com/xraph/forge/internal/router"

func main() {
    r := router.NewRouter()
    
    // Simple routes
    r.GET("/", homeHandler)
    r.GET("/users/:id", getUserHandler)
    r.POST("/users", createUserHandler)
    r.PUT("/users/:id", updateUserHandler)
    r.DELETE("/users/:id", deleteUserHandler)
    
    // Path parameters
    r.GET("/posts/:id/comments/:commentId", getCommentHandler)
    
    // Wildcard routes
    r.GET("/static/*filepath", serveStaticHandler)
}

func getUserHandler(ctx router.Context) error {
    userID := ctx.Param("id")
    return ctx.JSON(200, map[string]string{"id": userID})
}
```

### WebSocket Streaming

```go
// WebSocket route
r.WebSocket("/ws/chat", func(ws *router.WebSocket) error {
    for {
        // Read message
        msgType, data, err := ws.ReadMessage()
        if err != nil {
            return err
        }
        
        // Process message
        response := processMessage(data)
        
        // Write response
        if err := ws.WriteMessage(msgType, response); err != nil {
            return err
        }
    }
},
    router.WithName("chatWebSocket"),
    router.WithDescription("Real-time chat over WebSocket"),
    router.WithTags("chat", "websocket"),
)
```

### Server-Sent Events (SSE)

```go
// SSE route
r.EventStream("/events", func(stream *router.SSEStream) error {
    ticker := time.NewTicker(1 * time.Second)
    defer ticker.Stop()
    
    for {
        select {
        case <-ticker.C:
            event := router.SSEEvent{
                Event: "update",
                Data:  []byte(`{"timestamp":"` + time.Now().String() + `"}`),
            }
            if err := stream.Send(event); err != nil {
                return err
            }
        case <-stream.Context().Done():
            return nil
        }
    }
},
    router.WithName("eventsStream"),
    router.WithDescription("Server-sent events stream"),
    router.WithTags("events", "sse"),
)
```

### WebTransport Support

```go
// Enable WebTransport
r.EnableWebTransport(router.WebTransportConfig{
    AllowedOrigins: []string{"https://example.com"},
})

// WebTransport route
r.WebTransport("/wt/data", func(ctx router.Context, session router.WebTransportSession) error {
    // Echo datagrams until the client goes away
    for {
        data, err := session.ReceiveDatagram(session.Context())
        if err != nil {
            return err
        }

        if err := session.SendDatagram(data); err != nil {
            return err
        }
    }
})

// Start HTTP/3 server for WebTransport
if err := r.StartHTTP3(":4433", tlsConfig); err != nil {
    return err
}
defer r.StopHTTP3()
```

`StartHTTP3` binds the UDP socket before it returns, so a busy address is its error, and serves in the background. It builds one `webtransport.Server` around an `http3.Server` whose handler is the router. That server accepts the QUIC connections itself and calls `webtransport.ConfigureHTTP3Server`, which is what lets `Upgrade` find the connection behind a CONNECT. The route accepts both Extended CONNECT protocols, `webtransport-h3` (draft 15, what webtransport-go clients send) and the older `webtransport`. The writer reaching the route is always wrapped (the router's before-write writer, then the tracing and metrics status recorders), so the router walks `Unwrap()` down to the HTTP/3 writer for `http3.Settingser` and `http3.HTTPStreamer` and sends the 200 through the outermost writer, where the recorders see it. `StopHTTP3` closes every session and QUIC connection, then the socket.

The stream limits in `WebTransportConfig` go on the QUIC config, and a server lets each connection carry one session, so they cap the session too. `MaxBidiStreams` caps bidirectional streams and `MaxUniStreams` unidirectional ones. `quicStreamLimit` adds what HTTP/3 needs on top: one bidirectional stream for the CONNECT request, and three unidirectional ones for the control stream and the QPACK encoder and decoder streams. Zero means 100 and a negative value allows none. `webtransport.Server.Config` stays unset, because its per-session limits only hold when the client sends WebTransport flow control settings too, and setting it lets one connection carry several sessions.

`WebTransportSession` never holds its lock across a blocking call, so `Close` from one goroutine unblocks a `ReceiveDatagram` or `Accept*` parked in another. Stream wrappers lock only the send side (quic-go forbids `Close` alongside `Write`), so a blocked `Read` doesn't hold up `Close`.

`WebTransportConfig.MaxDatagramFrameSize` is enforced in the session wrapper, because quic-go hardcodes the datagram size it advertises. Over the limit, `SendDatagram` returns a wrapped `*quic.DatagramTooLargeError` and `ReceiveDatagram` drops the datagram uncounted and keeps waiting. Zero or less means no limit beyond QUIC's (about 1200 bytes of payload at first, since a datagram fits in one packet).

`WriteJSON` on a stream writes the value and a `\n` in one `Write` (`writeJSONLine`), so streams carry newline-delimited JSON; the generated TypeScript client's `receiveIterator` splits on newlines. `ReadJSON` goes through a `streamReader` that keeps one `json.Decoder` per stream, so values that arrive in one frame aren't lost, and a `Read` after `ReadJSON` gets the decoder's read-ahead first. One reader per stream at a time.

### Controller Pattern

```go
type UserController struct {
    userService *UserService
}

func (c *UserController) Routes() []router.Route {
    return []router.Route{
        {
            Method:  "GET",
            Path:    "/users",
            Handler: c.ListUsers,
            Options: []router.RouteOption{
                router.WithName("listUsers"),
                router.WithTags("users"),
            },
        },
        {
            Method:  "POST",
            Path:    "/users",
            Handler: c.CreateUser,
            Options: []router.RouteOption{
                router.WithName("createUser"),
                router.WithTags("users"),
            },
        },
    }
}

func (c *UserController) ListUsers(ctx router.Context) error {
    users, err := c.userService.List()
    if err != nil {
        return err
    }
    return ctx.JSON(200, users)
}

// Register controller
userController := &UserController{userService: userService}
r.RegisterController(userController)
```

### Outer middleware

`UseOuterMiddleware(r, mw...)` takes plain `func(http.Handler) http.Handler` middleware and runs it ahead of every `UseGlobal` middleware, whichever you registered first. It also runs before route matching, so it sees 404s and 405s. `forge.New` puts tracing, trace propagation, HTTP metrics and the bare route-match holder here. They have to see a request before an extension can reject it.

It's cheaper too. The outer slot lives inside the same single adapter wrapper as the `UseGlobal` chain, and it calls the `http.Handler` middleware directly. Wrapping one in `PureMiddleware(mw).ToMiddleware()` builds a second forge Context on every request. When nothing is registered through `UseGlobal`, the wrapper builds no Context at all before routing. A `Router` forge didn't build falls back to `UseGlobal` through `PureMiddleware`, in registration order.

An error a `UseGlobal` middleware returns goes through the router's error handler, and the outer middleware sees the status that produces.

### Stream observer and establishment

A stream route (`WebSocket`, `EventStream`, `SSE`, `WebTransport`) is observed from the handshake on. When the router matches a route it stamps `shared.RouteMatch.Pattern` and `RouteMatch.Kind` (`KindHTTP` unless the route is a stream kind). The stream handlers then call `shared.RouteMatchFromContext(ctx).Establish(status)` at the point the stream is up: 101 after the WebSocket upgrade, 200 once an `EventStream` is writable, 200 right before an `SSE()` handler runs, 200 after the WebTransport upgrade. `Establish` runs the callbacks middleware registered with `RouteMatch.OnEstablished` (once, on the request goroutine). That is how the tracing middleware ends its span and the HTTP metrics middleware records the duration at the handshake instead of at disconnect. `Established()` tells middleware that already happened. A rejected upgrade (a bad Origin, 403) never establishes. The holder has no locking, because it assumes every middleware calls `next` on the request goroutine. Middleware that runs `next` on another goroutine breaks that: `middleware.Timeout` does, so `Establish` races with the outer middleware reading `Established()`, and on a timeout the outer middleware finishes the request while the stream is still opening. Stream routes must not sit behind it.

`WithStreamObserver(o)` sets a `shared.StreamObserver`. The router calls `o.Opened(kind, route)` right after `Establish` and uses the returned `shared.StreamHandle` for that connection: `Sent()` per outbound message, `Received()` per inbound one, and `Closed(err)` once, after the router has closed the connection. `Sent` and `Received` never follow `Closed`, and they may run on several goroutines. With no observer, or when the request has no route pattern (no `RouteMatch` holder on the context), the router uses `shared.NoopStreamHandle`. What counts as a message: `EventStream` events sent through `Send`/`SendJSON`/`SendWithID`/`SendJSONWithID` (including the `forge.resumed` and `forge.gap` markers, not comments; `SSE()` handlers write with `ctx.WriteSSE` and count none), WebSocket data frames in both directions (not ping, pong or close), WebTransport datagrams only. The `err` given to `Closed` is the handler's error, with a WebSocket close frame (`wsutil.ClosedError`) already turned into `io.EOF`. A handler panic closes the handle with the panic as its error, wrapped with `%w` when the value is an error, so `errors.Is` matches `http.ErrAbortHandler`; the panic then carries on to recovery. `collectors.StreamMetrics` labels that `error_type` empty for errors that only mean the client left (`io.EOF`, `io.ErrUnexpectedEOF`, `context.Canceled`, `net.ErrClosed`, `syscall.EPIPE`, `syscall.ECONNRESET`, `os.ErrDeadlineExceeded` for a client too slow to take a write, `http.ErrAbortHandler`) and `handler_error` for anything else, any other panic included. `collectors.StreamMetrics` in `internal/metrics/collectors` is the one observer forge installs. A WebTransport route only establishes behind the router's own HTTP/3 server (`StartHTTP3`), because the upgrade needs the `webtransport.Server` that accepted the QUIC connection. A CONNECT that reaches the route any other way gets a 500 and never establishes.

### Performance Characteristics
- Route matching: <1μs for typical paths
- OpenAPI generation: ~10ms (cached after first generation)
- WebSocket: <100μs per message
- SSE: <50μs per event
- Memory efficient with zero allocation for cached routes

### Security Considerations
- Validate all path parameters
- Use CORS middleware for cross-origin requests
- Implement rate limiting per route/group
- Use HTTPS for WebSocket (wss://)
- Validate WebSocket origins
- Use authentication middleware

### Best Practices
1. Group related routes together
2. Apply middleware at appropriate level (global/group/route)
3. Add OpenAPI metadata for documentation
4. Use controllers for complex route groups
5. Validate inputs in handlers
6. Return structured errors with status codes
7. Use streaming for real-time data
8. Implement health check routes
